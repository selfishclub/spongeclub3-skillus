# 비트싱크 (beat-sync-skill)

> 클로드코드로 자동 편집하다 보면 전사(whisper) 타임스탬프로 잘라서 **말끝이 이상하게 끊기는** 문제 — 그걸 WAV 파형의 무음 구간 검출로 해결하는 Claude Code 스킬. (+ 실험적으로 음악 비트 분석도)

## ★ 본업: 음성 컷 (신뢰도 높음)

```bash
python scripts/beat_sync.py cuts "나레이션영상.mp4"
# → 무음(-50dB↓) 구간 목록 + "컷 추천: X.XX초" (무음 가운데 = 앞말 여운·뒷말 첫음 둘 다 보호)
```

whisper는 뜸(pause)을 다음 단어 길이로 잘못 잡아서 그 시간으로 자르면 단어가 잘립니다. 파형에는 진짜 무음이 보이므로 거기서 자르면 깔끔합니다.

## 보조 (실험적): 음악 비트 분석

솔직히 **음악에는 쓰시기에 부족합니다** — 곡 구조가 곡마다 달라서 드랍·BPM은 추정이고, 후보+확신도로만 냅니다. 그래도 곡을 파형으로 분석해서:

- **BPM·비트 간격** (컷 길이를 몇 초 배수로 자를지)
- **인트로/빌드업/드랍 구간** (에너지 곡선)
- **드랍 후보 시점** (±0.05초 정밀, 강도순 2~3개 + 확신도 등급)
- **편집 처방** — "하이라이트 컷을 X초에 스냅, 사진 버스트는 장당 Y초"

를 출력합니다 (후보 근처를 직접 들어보고 확정하는 용도). 편집이 끝나면 **편집본(mp4)을 재스캔해 드랍 싱크가 맞았는지 검증**까지 합니다.

## ⚠️ 솔직한 한계 (이 스킬의 철학)

이 파형 기법의 뿌리는 **음성 분석**입니다 — 무음·발화 경계 검출은 신뢰도가 높습니다. 반면 **음악 구조 해석은 사실상 어렵습니다**. 멀티히트 곡은 "주 드랍"이 분석 방법에 따라 갈리고, BPM은 반배/두배 모호성이 있습니다. 그래서 이 스킬은 드랍을 단정하지 않고 **후보 + 확신도**로 내며, "후보 근처를 직접 들어보고 확정하라"고 말합니다. **숫자는 좌표를 좁혀주는 도구지, 귀의 대체재가 아닙니다.**

## 설치

```bash
# Claude Code 전역 스킬 폴더에 클론
git clone https://github.com/jinyangse/beat-sync-skill "~/.claude/skills/비트싱크"
# Windows라면:
git clone https://github.com/jinyangse/beat-sync-skill "%USERPROFILE%\.claude\skills\비트싱크"
```

요구사항: **ffmpeg** (PATH에 있어야 함) + Python 3. 그 외 의존성 없음 (numpy 불필요 — 표준 라이브러리만).

## 사용법

Claude Code에서 그냥 자연어로:
- "이 곡(mp3 경로) 드랍이 어디야? 쇼츠 하이라이트 맞추고 싶어"
- "편집본(mp4 경로)이 10.25초 매치컷에 맞게 떨어졌는지 확인해줘"

스크립트 직접 실행도 가능:
```bash
python scripts/beat_sync.py analyze "곡.mp3"        # 전체 분석 + 편집 처방
python scripts/beat_sync.py fine "곡.mp3" 8 13      # 특정 구간 0.05초 정밀 스캔
python scripts/beat_sync.py verify "편집본.mp4" 10.25  # 드랍 싱크 검증
```

## 출력 예시

```
비트 간격 ≈ 0.94초  (BPM ≈ 64 — 반배/두배 모호성 있음)
  반박자 = 0.47초

드랍 후보 (강도순 · 확신도 보통 · 단차비율 0.62):
  후보1: 10.25초  ← 가장 유력
  ⚠️ 어디까지나 파형 추정 — 후보 근처를 직접 들어보고 확정할 것

===== 편집 처방 =====
· 하이라이트 컷(매치컷/반전)을 영상 10.25초 드랍에 스냅
· 컷 경계는 비트 간격의 배수로: 0.94s / 1.88s / 2.82s
· 사진 버스트(촤라락): 장당 0.47초 (반박자)
```

## 실전 검증

오프라인 모임 스케치 쇼츠(캡컷 편집)에서 풀 사이클 검증:
곡 드랍 10.25초 검출 → 매치컷 스냅 → 편집본 재검증 **오차 0.05초**.

스킬 유/무 벤치마크(3케이스): 정확도 9/9 vs 8/9, **속도 2배**(평균 136초 vs 277초), 스킬 없는 Claude는 librosa 설치·numpy 다운그레이드 등 환경을 건드리지만 이 스킬은 표준 라이브러리만 씁니다.
