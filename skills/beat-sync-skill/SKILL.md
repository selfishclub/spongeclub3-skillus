# 비트싱크 — BGM 파형 분석으로 컷 편집 처방

Claude는 음악을 듣지 못하지만, **파형에는 편집에 필요한 숫자가 있다**: 어디서 터지는지(드랍), 얼마나 빠른지(BPM), 어디가 조용한지(인트로). 이 스킬은 그 숫자를 뽑아 "편집 처방"으로 바꾼다. 실전 검증: 오프모임 스케치 쇼츠에서 드랍 10.25초 검출 → 매치컷 스냅 → 편집본 재검증(오차 0.05초)까지 한 사이클을 돌렸다.

## ⚠️ 솔직한 한계부터 (사용자에게도 이대로 말할 것)

이 파형 기법의 뿌리는 **음성 분석**이다 — 무음·발화 경계 검출(대사 컷, 편집본의 드랍 "유무" 확인)은 신뢰도가 높다. 반면 **음악 구조 해석은 사실상 어렵다**:
- "드랍이 어디냐"는 곡마다 정의가 다르다 — 인트로→드랍이 뚜렷한 곡은 잘 맞지만, 여러 번 치는 곡(멀티 히트)·서서히 커지는 곡·처음부터 풀 에너지인 곡에선 **후보가 갈린다** (실측: 같은 곡에서 분석 방법에 따라 29초 vs 38초로 갈린 사례 있음).
- BPM은 반배/두배 모호성이 있다 (64로 검출된 곡이 체감 128일 수 있음).

그래서 이 스킬은 드랍을 **단정하지 않고 후보 2~3개(강도순) + 확신도 등급**으로 낸다 (`analyze`가 "확신도 낮음/보통/높음 · 단차비율"을 함께 출력 — 실측 캘리브레이션: 드랍 있는 곡 0.44~1.06, 없는 곡 0.37). 사용자에게 전달할 때도 "여기가 드랍이다"가 아니라 **"파형상 유력 후보는 X초고, 후보 근처를 직접 들어보고 확정하라"**고 말한다. 숫자는 좌표를 좁혀주는 도구지 귀의 대체재가 아니다.

## 언제 쓰나
- **대사·나레이션 컷이 잘릴 때 (본업)** → `cuts`로 무음 구간 목록 + 안전 컷 지점(무음 가운데) 추천. whisper 시간으로 자르면 잘리는 문제의 해답
- 사용자가 **곡을 골라왔을 때** → `analyze`로 BPM·드랍·처방을 뽑아준다
- 편집 중 **"몇 초에 맞춰야 해?"** → 드랍 시점 + 컷 길이(비트 배수) 답변
- **편집본이 나왔을 때** → `verify`로 드랍 싱크가 맞았는지 검증
- 경계가 애매하거나 드랍이 여러 개 의심될 때 → `fine`으로 구간 정밀 스캔

## 사용법 (번들 스크립트)

```bash
# ★본업 — 음성 컷 지점 추천: 무음(-50dB↓) 구간을 찾아 "여기서 자르면 안전" 목록
python "<이 스킬 폴더>/scripts/beat_sync.py" cuts "나레이션영상.mp4"

# (실험적) 음악 전체 분석: 길이·에너지 곡선·BPM·드랍 후보 + 편집 처방
python "<이 스킬 폴더>/scripts/beat_sync.py" analyze "곡.mp3"

# 특정 구간 0.05초 정밀 스캔 (드랍 후보 눈으로 확인·무음 찾기)
python "<이 스킬 폴더>/scripts/beat_sync.py" fine "곡.mp3" 8.0 13.0

# 편집본 검증: 드랍이 기대 시점에 있는지 (오차 0.15초 이내 = OK)
python "<이 스킬 폴더>/scripts/beat_sync.py" verify "편집본.mp4" 10.25
```

- 입력은 ffmpeg이 읽는 건 뭐든 됨 (mp3/wav/m4a/mp4/mov — 영상이면 오디오 트랙을 자동 추출)
- 의존성: ffmpeg(PATH) + 파이썬 표준 라이브러리뿐 (numpy 불필요)
- Windows에서 한글 출력이 깨지면 `PYTHONUTF8=1 python …`으로 실행

## 결과를 편집 언어로 통역하는 법

스크립트가 처방을 출력하지만, 사용자에게 전달할 때 아래 원칙으로 살을 붙인다:

1. **드랍 = 하이라이트 컷의 좌표.** 영상의 한 방(매치컷·반전·공개 순간)을 드랍 시점에 스냅하라고 안내한다.
   - 하이라이트가 드랍보다 **늦으면**: 영상을 줄이는 것보다 **곡 시작을 미는 게** 보통 쉽다 (곡을 타임라인 `하이라이트시점 − 드랍시점`초 위치에서 시작 + 페이드인 1~1.5초).
2. **드랍 전 구간 = 조용한 도입.** 외관·설정·빌드업 컷을 배치. 글자 읽힐 여유가 있는 구간이기도 하다.
3. **컷 경계는 비트 간격의 배수로.** 편집 앱(캡컷 등)의 "비트 맞추기" 마커와 간격이 일치하는지 알려주면 사용자가 마커에 스냅만 하면 된다.
4. **사진 버스트(촤라락) = 반박자/장.** 한 박자/장은 버스트라기엔 느긋하다.
5. **BPM의 반배/두배 모호성**: 자기상관은 반템포를 잡을 수 있다(예: 쿰비아 곡을 64로 검출 — 체감은 128의 반박). 값 자체보다 "간격의 배수로 자른다"는 처방이 중요하므로 편집엔 지장 없지만, 사용자에게 BPM을 단정하지 말고 "비트 간격"으로 말한다.
6. **"뚜렷한 드랍 없음"이 나오면**: 처음부터 에너지가 일정한 곡이다(인트로 없이 바로 시작). 이런 곡은 드랍 스냅 대신 ①0초부터 깔고 ②하이라이트엔 효과음/자막 펀치로 강조하라고 안내한다.

## 검출 원리 (경계 케이스 이해용)

- **에너지 곡선**: 1초 창 RMS — 인트로/빌드업/드랍의 큰 그림.
- **드랍 정밀 검출**: 0.05초 창에서 "뒤 1초 평균 − 앞 1초 평균"(계단 단차)이 큰 후보들을 모은 뒤, **이후 도달 음량(fwd)이 가장 큰 지점**을 드랍으로 고른다. 빌드업 시작도 단차가 크게 나오지만(실측 0.111 vs 0.105로 박빙) 빌드업은 중간 음량에 머물고 드랍은 곡의 최대 에너지로 진입한다는 차이로 구분한다.
- **BPM**: 온셋 엔벨로프(0.02초)의 자기상관, 0.3~1.2초 랙 범위.
- 한계: 페이드로 서서히 커지기만 하는 곡(단차 없음), 비트가 약한 앰비언트 곡에서는 드랍/BPM이 안 잡힐 수 있다 — 그럴 땐 `fine`으로 사람이 보게 하고, 위 6번 처방으로 우회한다.

## 예시 (실전 케이스)

**Input**: "Crab Cay - Cumbia Deli.mp3 골랐어" (오프모임 스케치 쇼츠 편집 중)
**Output 요지**:
- 0~9초 잔잔한 인트로 → 10.25초 드랍 → 이후 하이 에너지 / 비트 간격 0.94초(반박 0.47초)
- 처방: 매치컷을 10.25초에 스냅, 드랍 전엔 외관·빈 공간 컷, 사진 버스트 0.47초/장
- 편집본이 나오면: `verify 편집본.mp4 10.25` → "오차 +0.05초 ✅ 싱크 OK"
