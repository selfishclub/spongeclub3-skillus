# SEO 노션 블로그 작성 스킬

## 목적

현재 페이지와 대화에서 사용자가 제공한 내용을 바탕으로, 검색 의도에 맞고 초보자도 이해하기 쉬운 노션 블로그 글을 작성한다. SEO와 검색 상위 노출 가능성을 높이는 구조를 적용하되 순위를 보장한다고 표현하지 않는다.

## 필수 입력

- 글의 주제 또는 핵심 메시지
- 현재 페이지와 대화에 포함된 사실, 경험, 의견
- 명시된 경우 타깃 독자, 핵심 키워드, 글 길이, 게시 채널

정보가 충분하면 추가 질문 없이 작성한다. 핵심 주제나 독자가 불명확해 결과가 크게 달라질 때만 질문 1개로 확인한다.

## 작성 절차

1. 현재 페이지와 대화의 내용을 가장 우선적인 원문으로 삼는다.
2. 독자의 검색 의도를 정보 탐색, 문제 해결, 비교, 구매·신청 중 가장 가까운 유형으로 판단한다.
3. 핵심 키워드 1개와 연관 키워드 3~5개를 정한다. 사용자가 키워드를 지정하면 그대로 우선한다.
4. 제목에 핵심 키워드와 구체적인 효익을 자연스럽게 넣는다.
5. 도입부에서 독자의 문제, 글에서 얻을 결과, 읽어야 할 이유를 짧게 제시한다.
6. 본문을 명확한 H2·H3 구조로 작성한다. 한 문단에는 하나의 메시지만 담는다.
7. 노션 기능을 설명할 때 기능의 의미, 필요한 상황, 실행 순서, 실제 사용 예시를 함께 제공한다.
8. 사용법은 메뉴 경로와 클릭 순서를 번호 목록으로 작성한다. 화면이나 버전에 따라 달라질 수 있는 명칭은 단정하지 않는다.
9. 추상적인 설명마다 예시, 적용 사례, 전후 비교 중 하나를 추가한다. 실제 사례가 없으면 ‘가상 예시’로 명확히 표시한다.
10. 결론에서 핵심 내용을 요약하고 독자가 바로 실행할 다음 행동을 제안한다.
11. 키워드 과다 반복, 장황한 문장, 근거 없는 수치·성과, 중복 설명을 제거한다.

## SEO 원칙

- 제목 앞부분에 핵심 키워드를 자연스럽게 배치한다.
- 첫 100~150자 안에 핵심 키워드와 글의 효익을 포함한다.
- 검색 질문에 대한 직접 답변을 각 섹션 초반에 배치한다.
- 연관 키워드를 억지로 반복하지 않는다.
- 짧은 문단, 목록, 단계, 표를 활용한다.
- 과장형·낚시형 표현을 피한다.
- 필요하면 FAQ 3~5개를 추가한다.
- 최신 정보가 필요한 내용은 출처를 확인하고, 확인하지 못한 사실은 단정하지 않는다.

## 초보자 친화 원칙

- 전문 용어를 처음 사용할 때 한 문장으로 뜻을 설명한다.
- ‘왜 필요한가 → 무엇인가 → 어떻게 하는가 → 예시 → 주의점’ 순서로 설명한다.
- 한 단계에 한 행동만 안내한다.
- 자주 막히는 지점과 실수 방지 팁을 포함한다.
- 설명 없이 ‘간단히’, ‘당연히’, ‘설정하면 된다’라고 쓰지 않는다.

## 노션 설명 규칙

노션 기능이나 방법을 다루는 각 핵심 섹션에 가능한 범위에서 다음 요소를 넣는다.

- **기능:** 무엇을 하는 기능인지
- **활용 상황:** 언제 쓰면 좋은지
- **사용 방법:** 순서대로 따라 할 수 있는 단계
- **예시:** 구체적인 입력과 결과
- **사례:** 실제 경험 또는 ‘가상 사례’로 표시한 적용 장면
- **주의점:** 권한, 요금제, 데이터 구조, 모바일·PC 차이 등 필요한 제약
- **용어:** 검색어와 실제 화면 표기가 다르면 둘 다 알려준다

검색어와 화면 용어가 다른 경우가 흔하다. 독자는 검색어로 들어와서 화면에서 그 단어를 못 찾고 헤맨다. 제목과 키워드는 검색어를 쓰되, 본문에 "화면에서는 OOO이라고 표기된다"를 한 줄 넣는다.

## 사실 확인

제품의 기능·메뉴명·모델명·수치는 **공식 릴리스 노트와 도움말, 그리고 사용자의 실제 화면**만 근거로 삼는다.

- **서드파티 요약 블로그를 근거로 쓰지 않는다.** 제품 정보를 정리해둔 블로그는 시점이 지났거나 틀린 경우가 많다. 방향을 잡는 데만 쓰고, 본문에 들어가는 이름·숫자는 공식 문서나 사용자 화면으로 다시 확인한다.
- **캡처에서 읽히지 않는 값은 추정해서 채우지 않는다.** 막대 칸 수, 작은 숫자, 흐릿한 라벨이 여기 해당한다. 읽은 것과 추정한 것을 구분해 밝히고 확인을 요청한다. 추정치를 넣어야 한다면 그 사실을 사용자에게 먼저 말한다.
- **사용자 캡처에 제품이 직접 쓴 문구가 있으면 본문에 인용한다.** 글쓴이의 설명보다 제품 화면의 문구가 훨씬 강한 근거가 된다.
- 시점에 따라 달라지는 내용에는 본문에 "YYYY년 M월 기준"을 박고, 갱신될 수 있다는 주의점을 단다.

## 캡처 자리 지정

글에 필요한 이미지는 사용자가 찍어야 한다. **어디에 무엇을 넣을지 본문에 직접 표시**하고, 무엇을 담아야 하는지 알려준다.

- 본문에 마커를 박는다. 마크다운은 `【캡처 N — 설명】`, HTML은 `<p class="cap">[캡처 N] 설명</p>`. 사용자가 그 줄만 이미지로 바꾸면 되게 한다.
- 본문과 별개로 **캡처 목록을 표로 낸다.** 번호 / 위치 / 무엇이 보여야 하는지 / 우선순위.
- **우선순위를 매기고, 없어도 발행 가능한 것을 구분해 말한다.** 전부 찍어야 한다고 하면 글이 멈춘다.
- 찍는 방법이 자명하지 않으면(두 계정 비교, 마우스 올려야 뜨는 화면 등) 방법을 함께 적는다.
- 이메일·실명·비공개 항목이 들어갈 수 있는 화면은 가림 처리를 안내한다.
- 캡처를 받은 뒤 번호가 바뀌면 **본문 전체의 번호를 다시 매긴다.** 중간에 끼워넣고 뒤를 그대로 두지 않는다.

표나 도표를 이미지로 만들어 달라고 하면, 데이터와 렌더링을 분리한 생성 스크립트로 만든다. 숫자만 고쳐 다시 뽑을 수 있어야 수정 요청에 대응할 수 있다.

## 기본 출력 형식

1. **SEO 제목 후보 3개**
2. **추천 제목 1개**
3. **메타 설명**: 120~160자 내외
4. **핵심 키워드·연관 키워드**
5. **블로그 본문**
    - 도입
    - H2·H3 본문
    - 노션 기능 및 단계별 사용법
    - 예시와 사례
    - 실수 방지 팁
    - 결론과 실행 제안
6. **FAQ**: 필요한 경우 3~5개
7. **썸네일 문구 후보 3개**

사용자가 ‘본문만’, 특정 분량, 특정 플랫폼 형식을 요청하면 해당 형식을 우선한다.

## 발행 채널별 출력

게시 채널을 확인하고 그에 맞는 파일을 낸다. 채널이 불명확하면 노션 기준으로 내고 다른 채널이 필요한지 한 번 묻는다.

### 노션

마크다운 `.md` 파일로 낸다. 노션은 붙여넣을 때 마크다운을 서식으로 변환한다.

### 네이버 블로그, 티스토리, 브런치

**마크다운을 그대로 주지 않는다.** 이 편집기들은 마크다운을 렌더링하지 않아서 `##`, `**`, `|---|`가 화면에 글자 그대로 노출된다. 사용자가 수십 곳을 손으로 고쳐야 한다.

대신 **브라우저에서 열어 복사할 HTML 파일**을 낸다.

- 파일 맨 위에 사용법 안내 상자를 넣는다. (브라우저에서 열기 → 안내 상자 아래만 선택 → 복사 → 편집기에 붙여넣기)
- 서식은 `<h1>` `<h2>` `<h3>` `<p>` `<strong>` `<ul>` `<ol>` `<blockquote>`만 쓴다. 이 태그들은 리치 텍스트로 복사할 때 서식이 유지된다.
- **표(`<table>`)는 쓰지 않는다.** 붙여넣을 때 깨지거나 이미지로 변환된다. 표로 쓸 내용은 `<strong>제목</strong><br>내용` 형태의 문단으로 편다.
- 스타일은 `<style>` 블록에 두고 클래스로 지정한다. 편집기가 클래스를 버려도 태그 자체의 서식은 남는다.
- 이미지 자리는 회색 배경 문단에 `[캡처 N] 설명` 형태로 표시한다. 사용자가 그 줄만 이미지로 교체하면 되게 한다.
- 이모지와 특수 기호(❌, ✅)는 쓰지 않는다. 굵은 글씨와 문단 구분으로 대신한다.

노션과 네이버 양쪽에 올리는 경우 `.md`와 `.html` 두 파일을 모두 낸다.

## 문체

- 친절하고 신뢰감 있게 작성한다.
- 초보자에게 말하듯 쉬운 한국어를 사용한다.
- 짧은 문장과 능동태를 우선한다.
- 사용자의 경험과 말투가 드러나는 표현은 보존하되 반복과 구어체는 읽기 좋게 정리한다.
- 성과를 과장하거나 검색 상위 노출을 보장하지 않는다.

## 품질 점검

- 현재 페이지와 대화의 핵심 내용이 반영되었는지 확인한다.
- 독자의 검색 질문에 초반부터 답했는지 확인한다.
- 노션 사용법이 실제로 따라 할 수 있을 만큼 구체적인지 확인한다.
- 초보자가 모를 용어를 설명했는지 확인한다.
- 실제 사례와 가상 예시를 구분했는지 확인한다.
- 키워드가 자연스러운지 확인한다.
- 근거 없는 수치, 출처, 기능을 만들지 않았는지 확인한다.
- 제품 이름·메뉴명·수치를 공식 문서나 사용자 화면으로 확인했는지, 서드파티 요약만 믿지 않았는지 확인한다.
- 캡처 자리를 본문에 표시하고 우선순위를 알려줬는지 확인한다.
- 게시 채널에 맞는 형식으로 냈는지 확인한다. 네이버·티스토리·브런치에 마크다운을 주지 않았는지 본다.
- 중복과 불필요한 문장을 제거한다.

## 발행 뒤

네이버 등 일부 채널은 이쪽에서 열어 확인할 수 없다. 발행 결과를 봤다고 말하지 않는다. 대신 **사용자가 눈으로 30초 안에 확인할 점검 항목 서너 개**를 준다. 마크다운 기호 잔존, 인용구·목록 서식 유지, 안내용 문구가 딸려 들어갔는지 정도면 충분하다.
