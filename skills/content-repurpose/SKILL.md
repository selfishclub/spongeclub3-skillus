# 한 편을 여러 곳에

**문구를 새로 쓰지 않는다. 쪼개고, 맡기고, 순서를 짜고, 닿게 만든다.**

```
모드 A · 새 글       원본 1편   →  원자 3~7개  →  카톡 채널 · 오픈 채팅방 · 인스타 · 스레드
모드 B · 월간 정리    원본 3~5편  →  뉴스레터 한 통  →  다시 원본으로
```

**B의 재료가 A의 발행 로그다.** 그래서 한 스킬에 둔다 —
따로 두면 B가 「지난 달에 뭘 올렸는지」를 모르는 채 시작한다.

---

## 시작하기 전에 읽는다

```
references/account.md          이 계정의 주소 · 꼬리표 · 쓰는 채널 · 부를 스킬     ← 값
references/voice.md            어떻게 말하는가                                   ← 말투 (있으면)
references/tone.md             카톡 · 오카방 · 인스타 캡션 · 뉴스레터에서의 톤          ← (있으면)
references/brand.md            무엇을 하는 사람으로 보이나                         ← (있으면)
references/clinical-facts.md   무엇이 사실인가                                   ← (있으면)
references/channels.md         채널 제약                                        ← 항상
```

**`account.md` 가 없으면** `account.example.md` 의 칸대로 **한 번에 묻는다** —
쓰는 채널과 주소, 안 쓰는 채널, 신청 페이지가 꼬리표를 읽는지. 답을 받으면 `account.md` 로 저장하자고 제안한다.

**`voice.md` · `tone.md` 가 없으면** 말투와 독자를 **한 번 묻고** 시작한다.

**이걸 안 읽고 네 곳을 만들면 목소리가 네 개가 된다.**

## 하는 일과 안 하는 일

| | |
|---|---|
| **한다** | 원자 뽑기 · **채널 제약** · 채점 · 채널 스킬 호출 · 링크와 꼬리표 · **발행 순서** · 검수 · **발행 로그** · 회고 |
| **안 한다** | 주제 발굴 · 원본 쓰기 · 스레드 문장 다듬기 · 캐러셀 디자인 · 보도자료 · **적법성 판정** |

```
주제가 없다   →  주제 발굴 도구로 (예: threads-writing 의 topic-mining)     ← 여기가 제일 앞
주제는 있다   →  원본 한 편을 쓴다 (예: blog-writing)
원본이 있다   →  ★ 이 스킬
```

**원본이 어떻게 만들어졌는지는 따지지 않는다.** 스킬로 썼든, 손으로 썼든, 예전 글이든, 강의록이든.

### 문구는 채널 스킬에 맡긴다 — **있으면**

`account.md` 「부를 채널 스킬」에 적힌 것을 부른다.

| 채널 | 부를 스킬 | 없으면 |
|---|---|---|
| 인스타 | 캐러셀 스킬 | `references/carousel.md` |
| 스레드 | 스레드 스킬 | STEP 4 의 최소 규칙 |
| **카톡 채널 · 오픈 채팅방 · 뉴스레터 · 인스타 캡션** | **없다 — 여기서 직접** | `tone.md` · `newsletter.md` |
| **규제 업종의 표현 검수** | 그 업종용 검수 스킬 | **적법성은 여기서 판정하지 않는다** |

**스킬이 있으면 반드시 부른다.** 그쪽에 말투와 계정 성격이 들어 있다.
넘길 때는 **원본 전체가 아니라 맡긴 원자 하나 + 그 채널 청중 한 문장 + 붙일 주소**를 넘긴다 —
원본을 통째로 넘기면 그 스킬이 다시 요약해서 다른 채널과 겹친다.

**없으면 멈추지 않는다** — 최소 규칙으로 쓰고 「더 다듬으려면 ○○ 스킬을」을 덧붙인다.

---

## 이 스킬이 지키는 것

**원본을 하나 정한다 — 대개 블로그다.** 검색되는 긴 글이 하나 있고, 나머지가 그것을 가리킨다.
원본 없이 따로 쓰면 말이 조금씩 달라지고, 나중에 어느 게 맞는지 모르게 된다.

> ⚠️ **거꾸로는 절대 안 된다.** 다른 곳에 쓴 문장을 **원본으로 가져와 붙이지 않는다** —
> 네이버는 **중복 문서로 판정하면 글 전체를 묻는다.** 흐름은 **원본 → 나머지** 한 방향뿐이다.

**같은 주제, 다른 컷.** 네 곳을 다 구독한 사람은 같은 내용을 네 번 본다 — 그때 「재탕만 하네」가 된다.
**원자를 채널마다 다르게 맡기는 것이 이걸 막는 장치다.**

**자리마다 「다음으로 갈 곳」이 다르다.** 같은 링크 순서를 여러 곳에 복사하면 틀린다 —
오픈 채팅방에 있는 사람에게 오픈 채팅방을 권하게 된다.

**채널마다 「링크를 붙일지」부터 정한다.** 행동은 하나지만, **행동이 없어도 된다.**

> **링크가 붙으면 앞의 진심이 미끼처럼 보인다.** 네 곳에 다 박으면 네 곳이 전부 미끼로 보인다.
> 채널 스킬에 그 계정의 CTA 규칙이 있으면 **그것이 우선이다.**

**이미지는 이미 온 사람에게, 텍스트는 올 사람에게.** 검색도 AI도 글자만 읽는다.

**불안을 키워 닫지 않는다.** 반응은 오지만 쌓이는 건 신뢰가 아니라 경계심이고, 그게 네 곳에 동시에 쌓인다.

**자동으로 발행하지 않는다.** 후보를 늘어놓고 사용자가 고른 뒤에 만든다.

**발행 결과를 봤다고 말하지 않는다.** 스킬은 발행된 화면을 볼 수 없다. 못 본 것은 「미확인」으로 두고,
사용자가 30초 안에 확인할 것 세 가지를 준다.

---

## 묻는 법

- **찾아볼 수 있는 것은 묻지 않는다.** `account.md` · 원본 · 발행 로그를 먼저 본다
- 물어볼 것은 **한 라운드에 몰아서**, 질문마다 **번호 + 내 추천안**
- 갈림길에는 **(A)/(B) 선택지 + 무엇을 얻고 잃는지.** 「어떻게 하고 싶으세요?」로 묻지 않는다
- 모든 질문에 **「모르겠어요」 탈출구** — 그러면 추천안으로 간다

**확인은 세 번이다. 처음에 이렇게 말해 둔다.**

> 세 번 여쭙겠습니다 — ① 원자 표 ② 채널 배정 ③ 검수 점수를 붙인 최종 문구.

**사용자가 「추천대로」라고 하면** 남은 확인도 추천안으로 채우고 ③ 까지 간다. ③ 은 건너뛰지 않는다.

# STEP 0 · 모드와 원본을 받는다

> **새 글을 올리시나요, 이번 달 것을 묶으시나요?**
> **A** 원본 한 편을 여러 곳에  ·  **B** 쌓인 글을 뉴스레터 한 통으로

## 모드 A

> 원본 주소나 본문을 주세요.

### 원본을 가져오는 법

**네이버 블로그는 일반 웹 가져오기로는 요약만 온다.** 모바일 주소로 받아 본문을 직접 뽑는다.

```
https://m.blog.naver.com/PostView.naver?blogId={아이디}&logNo={글번호}
본문     class="se-main-container" 안의 글자
굵게     <b> · <strong> 로 감싼 문장 → STEP 1 「저자가 가리킨 문장」
인용 상자  se-quotation
미리보기  og:title · og:description · og:image — og:description 은 링크 카드에 실리는 문장이다
```

**og:description 을 적어 둔다.** 링크 카드가 이 문장을 싣고 오므로, 같은 채널 본문에 같은 말을 또 쓰지 않는다.

**어디에 올릴지는 묻기 전에 `account.md` 에서 「운영 중」인 채널을 체크해 보여준다.**
「안 씀」인 채널은 목록에서 뺀다. 사용자는 빼기만 하면 된다.

**원본이 아직 없으면 여기서 멈춘다.** 이 스킬 안에서 주제를 만들지 않는다 —
주제 발굴 도구나 원본을 쓸 스킬을 알려주고 끝낸다.

## 모드 B

**발행 로그(STEP 8)를 먼저 읽는다.** 있으면 후보를 제시한다.

> 지난 달에 네 편 올리셨네요. 이 중 셋을 묶을까요?

없으면 묻는다 — **제목과 주소 3~5개.**

### 묶는 기준 — 시간순이 아니라 하나의 실로 꿴다

「9월에 쓴 글 모음」은 아무도 안 읽는다.

```
관통하는 한 줄을 먼저 찾는다     "이번 달엔 잠드는 시각보다 일어나는 시각 얘기를 계속 했네"
그 줄에 안 맞는 글은 뺀다        네 편 중 셋만 써도 된다
```

모드 B 는 STEP 1~3 을 건너뛰고 **STEP 4-B** 로 간다. 원자는 각 글의 발행 로그에 이미 있다.

# STEP 1 · 원자로 쪼갠다

`references/atoms.md`.

```
글 하나  →  원자 3~7개  →  원자 하나당 출력물 하나
```

1. **논지를 먼저 한 문장으로 쓴다.** 안 써지면 원본이 덜 된 것이다 — 멈추고 말한다
2. 여섯 종에서 뽑는다 — **논지 · 핵심 포인트 · 일화 · 수치 · 인용문 · 실행 항목**
3. **3~7개**로 추리고 **날카로움 → 새로움 → 근거** 순으로 세운다
4. **저자가 손가락으로 가리킨 문장**은 순위와 상관없이 맨 위

**없는 종류는 비워 둔다. 지어내지 않는다.** 에세이에 수치가 없는 건 정상이다.

**원본에 연재·카테고리 이름이 나오면 실제 블로그 카테고리와 대조한다.** 블로그 글쓰기 스킬의 프로필 파일
(예: `blog-writing/references/blog-profile.md`)이 있으면 거기서 본다. 다르면 파생 글에는 **실제 카테고리 이름**을 쓰고,
원본을 고칠지는 사용자에게 알린다 — 파생 글을 보고 블로그에 온 사람은 카테고리 이름으로 찾는다.

### 🔴 맥락에 기대는 원자는 못 뿌린다

「어제 그 얘기」 「지난번에 말했듯」으로만 서는 원자는 **채널마다 처음 보는 사람이 전부 이탈한다.**
원문 없이 떼어 봐도 서는지 여기서 한 번 본다. 채점은 STEP 3 에서 한다.

> **확인 ①** — 원자 표를 보여준다. 「빼거나 더할 게 있으면 번호로 알려주세요.」

# STEP 2 · 채널과 청중을 먼저 못박는다

**문구를 쓰기 전에 정한다.** 다 쓰고 고르면 늦다.

## 쓰고 나서 바꾸면 처음부터 다시 써야 하는 것

| 채널 | 먼저 정할 것 | 왜 |
|---|---|---|
| **스레드** | 커뮤니티(태그) | **발행하면 못 바꾼다.** 태그와 글이 어긋나면 노출돼도 답글이 없다 |
| **카톡 채널 소식** | 사진이냐 링크냐 | **둘 중 하나만 된다.** 고르는 쪽에 따라 본문이 달라진다 |
| **오픈 채팅방** | 공지냐 일반 메시지냐 | 누가 보는지, 카드가 붙는지가 다르다 |
| **인스타** | 캐러셀이냐 한 장이냐 | 구성이 통째로 달라진다 |
| **뉴스레터** | 보낼지 | **회수가 안 된다** |

**방을 먼저 정하고, 그 방 사람이 답하고 싶어할 말로 닫는다.**

## 채널마다 「누가 읽는가」를 한 문장으로

> **청중 보정은 명시하지 않으면 반드시 기본값으로 무너진다.**
> 한 문장이라도 적어 두면 문구가 달라진다.

**기본값** — 계정마다 다르면 고친다.

| 채널 | 누가 읽나 |
|---|---|
| 오픈 채팅방 | 이미 나를 알고 방에 들어온 사람. **공지는 나중에 들어온 사람도 본다** |
| 카톡 채널 소식 | 찾아와야 본다. **맥락 없이 처음 보는 사람** |
| 인스타 | 피드를 넘기다 멈춘 사람, 또는 검색으로 온 사람 |
| 스레드 | **팔로워가 아닌 사람이 더 중요하다.** 추천으로 처음 본 사람 |
| 뉴스레터 | 명단에 이름을 준 사람. **읽을 마음으로 연다** |

**청중에 맞춰 용어를 고른다.**

```
처음 보는 사람    전문용어 0.  한 문장에 한 아이디어.  목적 먼저, 원리는 나중
이미 아는 사람    정확한 용어를 쓴다 — 풀어 쓰면 낮잡는다고 느낀다.  그리고 짧게
공통              쉬운 버전이 원본의 격을 깎으면 안 된다
```

# STEP 3 · 원자를 채널에 맡긴다

`references/scoring.md`.

**감으로 고르지 않고 다섯 항목으로 매긴다.**

```
훅 0.30  ·  홀로서기 0.25  ·  감정 0.20  ·  정보밀도 0.15  ·  마무리 0.10
```

**채널별로 가중치만 바꾼다** — 스레드는 훅을, 뉴스레터와 인스타는 정보밀도를, 오카방과 카톡은 홀로서기를 올린다.
표는 `scoring.md` 에 있다.

- **60점 미만은 버린다**
- **홀로서기 감점 신호 셋** — 「앞서 말했듯」 · 가리킬 데 없는 대명사 · 문장 중간에서 끊김.
  하나라도 있으면 홀로서기 5점 이하
- **한 원자는 한 채널에.** 여러 채널에서 1등이면 가장 필요로 하는 채널에 주고 나머지는 2등을 받는다
- **새 문구가 없는 채널은 「배정 없음」.** 기존 소식의 주소만 바꾸는 경우처럼. 억지로 원자를 끼우지 않는다
- **링크 카드가 실어 오는 문장(og:description)과 같은 원자는 그 채널 본문에 맡기지 않는다.** 한 메시지 안에서 겹친다

> **확인 ②** — 원자 × 채널 점수표와 배정을 보여준다. 「바꿀 칸이 있으면 알려주세요.」
>
> 사용자가 점수 낮은 원자를 고르면 그대로 간다. 다만 홀로서기가 낮으면 **왜 낮은지 한 줄**은 말한다.

---

# STEP 4 · 채널별 문구

**하나씩 처리한다.** 한꺼번에 넷을 쏟지 않는다 — 고칠 데를 못 찾는다.

맡긴 원자를 **재료**로 쓴다. 원문 문장을 옮겨 붙이지 않고 다시 짠다.

```
훅             이 채널의 첫 줄
알맹이 한 방     맡긴 원자
닫는 말         STEP 5 의 「다음으로 갈 곳」, 또는 행동 없이 닫기
```

**훅 후보는 채널마다 서로 다른 유형에서 하나씩.** 같은 유형에서 여러 개를 뽑으면 선택지가 아니라
같은 글 여러 벌이 된다. 훅 유형 자료(예: `threads-writing/references/hooks.md`)가 있으면 그것을 본다.

**줄일 때 지우는 것과 못 지우는 것.**

```
지운다      필러 · 인사말 · 헤지 · 연결 접속사
못 지운다   부정어(안 · 못 · 만 · 제외) · 숫자 · 단위 · 링크 · 조건
```

> 🔴 **줄이면 단정해진다.** 「~일 수 있다」를 지우면 「~이다」가 남는다.
> 건강·금융처럼 규제 업종이면 조건과 여지를 지우지 않는다. `clinical-facts.md` 가 있으면 사실은 거기 기준이다.

## 4-1 · 오픈 채팅방 — 공지와 메시지를 둘 다 쓴다

```
공지          카드 없음 · 전원이 본다 (새로 온 사람 포함)   → 상시 안내
일반 메시지    카드 붙음 · 그때 있던 사람만                → 새 글 알림
```

### 공지

```
① 이번에 알릴 핵심          두세 줄.  이것만 읽어도 뜻이 통해야 한다
② 「더 자세한 이야기는」 + 원본 주소                ← 꼭 넣는다
③ 이미지 한 장 (선택)       카드가 없으니 이미지가 유일한 시각 요소다
```

**🔴 「전체 보기」가 뜨면 진 것이다.** 접힌 아래는 안 읽힌다.

```
전체 400자 이내   경계는 약 500자.  줄 수가 아니라 글자 수 기준이다
주소도 글자 수에 들어간다    꼬리표까지 붙으면 60~80자.  본문은 320자쯤으로
```

**다 쓰면 글자 수를 세서 적어 준다.** 400자를 넘으면 줄여서 다시 낸다.

> **공지를 갈아 끼우기 전에 지금 공지가 무엇인지 본다.**
> 공지가 **「방 안내」**(이 방이 무엇인지 · 규칙 · 신청 링크)면 **공지는 그대로 두고 일반 메시지만** 쓴다.
> 방 안내를 글 소개로 바꾸면 나중에 들어온 사람이 방이 뭔지 모른다.
> 공지가 **「글 소개」**일 때만 대표작으로 갈아 끼운다.

### 일반 메시지

**첫 링크에만 카드가 붙는다.** 원본 주소를 첫 줄에 두고, 이미지는 따로 넣지 않는다 (카드가 이미 갖고 온다).

## 4-2 · 카카오톡 채널 소식 — 매번이 아니다

**소식을 올려도 친구에게 알림이 가지 않는다.** 푸시는 유료 메시지에만 붙는다.
**찾아와야 보이고, 채널홈에서 보이는 건 공지 카드에 걸린 것뿐이다.**

```
매번        올리지 않는다
가끔        대표작만.  그리고 공지 카드를 그것으로 갈아 끼운다
```

**공지는 밀리지 않는다** — 내가 걸어야 걸리고, 내가 바꿔야 바뀐다.

**새 소식을 올리기 전에, 공지 카드에 걸린 기존 소식의 주소만 바꿔도 되는지 먼저 본다.**
소개 소식이 블로그 첫 화면을 가리키고 있으면 그 줄만 대표작 주소로 바꾸는 것이 가장 싸다 — 소식 수가 안 늘고 사진도 그대로다.

```
제목    핵심 한 줄
본문    도입 두세 줄 + 원본 주소
사진 또는 링크 중 하나만 (STEP 2 에서 정했다)
```

## 4-3 · 인스타 → 캐러셀 스킬

슬라이드는 캐러셀 스킬에 넘긴다 — **맡긴 원자 · 청중 한 문장 · 이야기 방식 · 이미지 색.** 없으면 `references/carousel.md`.

**캡션 본문은 이 스킬이 쓴다.** 슬라이드가 아직 없어도 쓸 수 있다. 톤은 `tone.md` 「인스타」.

```
첫 두 줄       훅 + 검색어.  「더 보기」 전에 보이는 자리다
본문          맡긴 원자.  한계 문장이 붙어 있으면 떼지 않는다
질문          끝에 하나.  답하고 싶은 것으로 — 댓글이 도달을 부른다
DM 약속       「댓글 남기시면 원문 링크를 DM으로」  ← 질문과 같은 동작으로 묶는다
해시태그       3~5개
```

**대체 텍스트**는 슬라이드가 나온 뒤 장마다 쓴다 — 무엇이 보이는지 + 검색어 한 번.
**위치 태그**는 규제 업종이면 비워 둔다.

**프로필 링크로 몰지 않는다** — 알고리즘이 깎는다. 댓글 → DM → DM 안에서 링크.

## 4-4 · 스레드 → 스레드 스킬

넘길 것 — **맡긴 원자 · 청중 한 문장 · 원본 주소.** 없으면:

```
50~150자        알고리즘은 첫 150자로 판단한다
답글로 잇는다     1편 → 답글에 2편
링크는 답글에    본문에 링크가 있으면 덜 퍼진다
```

**답이 달릴 여지를 남긴다.** 다 설명하면 「그렇군요」로 끝나고, 댓글이 없으면 확산이 멈춘다.

## 4-B · 뉴스레터 한 통 (모드 B)

`references/newsletter.md`.

```
제목 + 미리보기    한 세트.  미리보기는 제목을 반복하지 않는다.  40~90자
관통하는 한 줄     STEP 0 에서 찾은 것
글 3~5편          한 편에 3~4줄 + 원본 주소
행동             한 통에 하나
추신              두 번째로 많이 읽히는 자리
```

**링크는 원본으로 보낸다.** 체류시간이 거기 쌓이고, 다음 행동이 이미 거기 있다.

**여기서 바로 보여주지 않는다.** STEP 5~7 을 거쳐 검수 점수를 붙인 뒤 한 번에 보여준다 — 확인 ③.

# STEP 5 · 링크와 꼬리표

## 파생 글의 링크는 원본이 먼저

**파생 글이 가리키는 곳은 원본이다.** 아래 「다음으로 갈 곳」(명단 · 오픈 채팅방)은
**원본의 맺음말**이나 **DM 의 두 번째 줄**이 맡는다. 한 글에 두 곳을 나란히 걸면 행동이 둘이 된다.

## 자리마다 「다음으로 갈 곳」이 다르다

**「내가 아직 못 가진 것」으로 보낸다.**

| 서 있는 자리 | 이미 가진 것 | 보낼 곳 |
|---|---|---|
| 블로그 · 스레드 · 인스타 | 없음 (플랫폼 것이다) | **명단**(메일) 또는 오픈 채팅방 |
| 오픈 채팅방 | 카톡 도달 | **명단**(메일) |
| 카톡 채널 | 부를 수단이 없음 | **오픈 채팅방** |
| 뉴스레터 | 명단 | **원본** (거기서 다음으로) |

## 꼬리표

**값은 `account.md` 에 있다.** 채널마다 정해진 값을 붙인다. 비어 있으면 붙이지 않는다.

**꼬리표는 그 값을 읽는 페이지로 가는 링크에만 붙인다** — 대개 신청 페이지다.
블로그 · 인스타 · 오픈 채팅방 주소에 붙여도 아무 데도 기록되지 않는다. 그런 링크는 주소 그대로 쓴다.

**안 붙이면 어디서 왔는지 영영 모른다.** 인쇄물(QR)은 특히 미리 붙인다 — 인쇄하면 못 고친다.

**UTM 은 `account.md` 에 규칙이 적혀 있을 때만 붙인다.** 읽을 도구 없이 붙이면 아무 데도 기록되지 않고,
나중에 규칙이 달라지면 두 형식이 섞인다.

## 주소는 본문에 글자로도 쓴다

**링크 카드나 버튼이 붙어도 뺀다고 하지 않는다.** 중복이 아니라 이중 안전장치다 —
미리보기는 실패할 때가 있고(회색 빈 카드), 글자 주소는 복사가 되고 PC 에서도 보인다.

# STEP 6 · 발행 순서

**가장 강한 채널 한 곳을 먼저 확정하고 나머지를 파생시킨다.** 네 곳을 동시에 다듬지 않는다.

**같은 날 네 곳에 다 뿌리지 않는다.** 네 곳을 구독한 사람이 하루에 네 번 보고,
첫 채널의 반응을 보고 다음 채널을 고칠 기회도 사라진다.

```
D0      링크 미리보기 확인 → 원본 → 오픈 채팅방 일반 메시지 (새 글 알림)
D0~1    STEP 3 에서 점수가 가장 높은 공개 채널 하나 (스레드 또는 인스타)
        올린 뒤 스레드는 10분, 인스타는 1시간을 비워 둔다
D2~3    나머지 공개 채널
대표작    카톡 채널 — 기존 소식 주소 교체, 또는 새 소식 + 공지 카드 교체
        오픈 채팅방 — 공지가 「글 소개」일 때만 교체. 「방 안내」면 그대로
월말     뉴스레터 (모드 B)
```

**링크 미리보기(`og:image`)는 링크를 하나라도 뿌리기 전에 확인한다.** 카카오는 한 번 박힌 미리보기를
갱신할 방법이 없다. `references/publish-check.md` 1장.

**거꾸로 하면 링크할 곳이 없다.**

# STEP 7 · 검수

**완성된 문구를 STEP 3 의 다섯 항목으로 다시 매긴다** — 그 채널 가중치로.

| 점수 | 할 일 |
|---|---|
| **85 이상** | 통과 |
| 70~84 | 조건부 — 고칠 곳 한두 개 |
| 55~69 | 다시 쓴다 |
| 54 이하 | 이 채널에서 뺀다 |

**알림형(새 글 알림 · 주소 교체)은 통과선이 75다.** 알맹이를 링크 너머 원본에 맡기는 글이라
정보밀도가 구조상 낮다. 85 를 넘기려고 다른 채널의 원자를 끌어오면 채널끼리 겹친다.

**채널마다 검수자를 갈아끼운다.** STEP 2 에서 적은 「누가 읽나」 한 문장의 눈으로 읽는다.
기준은 고정하고 눈만 바꾼다.

## 품질 게이트 — 셋 다 「예」여야 낸다

```
같은 저자로 읽히나                 채널마다 말투가 다른 사람이 되지 않았나
채널마다 진짜 알맹이가 있나          「새 글 올라왔어요」만 있는 곳은 없나
복붙된 문장이 없나                 두 채널에 같은 문장이 있으면 하나를 고친다
```

## 고칠 곳은 셋에서 다섯만

**「무엇을 → 어떻게」로 적는다.** 위치를 원문 인용으로 짚는다.
**사용자가 승인한 것만 고친다.** 다시 매겨서 또 걸리면 한 번 더 — **세 번까지.** 그래도 남으면 사용자에게 넘긴다.

## 규제 업종이면 마지막에 한 번

`account.md` 에 규제 업종과 검수 스킬이 적혀 있으면 **모든 채널 문구가 확정된 뒤 한 번** 부른다.
축약 단계마다 부르지 않는다 — 확정 전에 보면 고칠 때마다 다시 봐야 한다.
**검수 스킬이 없으면 판정하지 않고, 「적법성은 확인하지 않았다」고 적는다.**

그다음 `references/publish-check.md` 로 훑는다. **걸린 것만 보여준다.**

> **확인 ③** — 채널별 문구를 모아 보여준다. 채널마다 **글자 수 · 점수 · 통과 여부**를 같이 적는다.
> 규제 업종 검수가 아직이면(슬라이드 등이 남아서) 「검수 전」이라고 적는다.

# STEP 8 · 발행 로그를 남긴다

**모드 A 가 끝나면 채널마다 한 줄씩 남긴다.** 위치는 `account.md` 에 있다. 없으면 처음 쓸 때 만든다.

```
| 날짜 | 원본 | 채널 | 맡긴 원자 | 첫 문장 유형 | 물어본 것 | 사진 | 주소(꼬리표) |
|---|---|---|---|---|---|---|---|
| 2026-09-12 | 일어나는 시각 | 스레드 | 일화 | 대사 | 경험 묻기 | 없음 | …?from=threads |
```

**변수를 셋으로 고정한다 — 첫 문장 유형 · 물어본 것의 종류 · 사진 유무.**
칸이 매번 달라지면 비교가 안 된다. 쌓이면 그게 이 계정의 감이 된다.

**두 번 일한다** — 모드 B 의 재료가 되고, STEP 9 회고의 재료가 된다.

# STEP 9 · 회고

**48시간 뒤 볼 숫자**는 `publish-check.md` 5장.

## 표본이 모자라면 판단하지 않는다

```
채널별로 발행이 5편 미만이면        결론을 내지 않는다
설정을 바꾼 지 3일 이내면           성과로 판단하지 않는다
```

**다만 「보류」로 끝내지 않는다.** 대신 **다음에 해 볼 것 셋 + 다시 볼 날짜**를 낸다.
표본이 얇아 방향이 오락가락하면 「관계없다」고 결론 내지 말고, **한 번 일부러 바꿔 보자고** 제안한다.

## 지난 권고부터 본다

새로 진단하기 전에 **지난번에 무엇을 권했고, 무엇을 했고, 무엇을 일부러 뺐는지** 먼저 확인한다.
효율은 올랐는데 총량이 줄었으면 **직전 권고가 틀린 것** — 명시적으로 거둔다.

## 다음 소재 후보

**반응이 온 원자를 다음 원본 후보로 적어 둔다.** 이 스킬은 주제를 발굴하지 않지만,
지나가면서 떨어뜨리는 것은 줍는다. 건질 게 없으면 **「이번엔 없다」**고 적는다 — 지어내지 않는다.
