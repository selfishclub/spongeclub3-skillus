# 내보내기 전 점검

> **걸린 것만 보여준다.** 통과한 항목을 나열하면 안 읽는다.

---

## 1. 링크 미리보기 — **뿌리기 전에 끝낸다**

**한 번 잘못 뿌리면 되돌리기 어렵다.** 「이미지 없음」이 상대 서버에 캐시되고,
**카카오는 공개된 캐시 갱신 도구가 없다.**(페이스북은 있다)

```
① og:image 를 먼저 배포한다
② 그 다음에 링크를 뿌린다
③ og:url 은 넣지 않는다
```

### ③이 왜 중요한가

`og:url` 을 박아두면 스크래퍼가 **꼬리표 붙은 주소를 그 주소로 되돌려서** 옛 캐시를 다시 꺼낸다.
**꼬리표로 캐시를 피하는 유일한 길을 페이지가 스스로 막는다.**

### 이미 캐시가 박혔으면

**주소를 바꾸는 것이 유일한 우회다.** 꼬리표 뒤에 `&v=2` 를 붙인다.
안 되면 `&v=3`. **같은 주소로 다시 올리는 것은 소용없다.**

### og 태그 한 벌

```html
<meta property="og:title" content="{{제목}}">
<meta property="og:description" content="{{한 줄}}">
<meta property="og:type" content="website">
<meta property="og:image" content="https://{{도메인}}/og.png">   <!-- 절대주소 -->
<meta property="og:image:width" content="1200">
<meta property="og:image:height" content="630">
<meta property="og:site_name" content="{{브랜드}}">
<meta name="twitter:card" content="summary_large_image">
```

**`noindex` 가 걸려 있으면 뺀다.** 링크를 뿌리기 시작한 순간 「아직 비공개」라는 전제는 이미 깨졌고,
스크래퍼가 그걸 존중해 미리보기를 만들지 않을 수 있다.

**og:image 는 도착 화면과 같은 색이어야 한다.** 미리보기가 남색인데 열린 화면이 크림색이면
**잘못 온 줄 안다.** 미리보기는 브랜드 자랑이 아니라 **「여기가 맞다」는 확인**이다.

## 2. 꼬리표

**값은 `account.md` 에 있다.** 채널마다 다른 값을 붙인다 — 예: 블로그 `?from=blog`, 오픈 채팅방 `?from=chat`.
**인쇄물·QR 은 인쇄하면 못 고친다. 미리 붙인다.**

**안 붙이면 어디서 왔는지 영영 모른다.** 나중에 알아낼 방법도 없다.

**구현은 열 줄이면 된다** — 주소의 `?from=` 을 읽어 **이미 있는 「신청경로」 칸 뒤에 이어 붙인다.**
표를 새로 만들지 않으면 스키마도 폼도 안 건드린다.

> ⚠️ **구글 폼에 보낸다면 문항 유형을 먼저 본다.** 라디오·드롭다운에 목록에 없는 값을 보내면
> **응답 전체가 거부된다.** 단답형이어야 자유 값이 통과한다.

### UTM — **[[아직 정하지 않았다]]**

**GA 를 붙일 때 규칙을 정하고 `account.md` 의 UTM 칸에 적는다.**
그전에는 붙이지 않는다 — **읽을 것이 없어 아무 데도 기록되지 않고**,
나중에 규칙이 달라지면 두 형식이 섞인다.

**대소문자·한글·띄어쓰기가 섞이면 GA 에서 다른 출처로 집계된다**(`Naver` ≠ `naver`).
그래서 규칙을 한 곳에 적어두고 매번 같은 형식으로 뽑는 것이 도구로 하나씩 만드는 것보다 낫다.

**UTM 과 겹치지 않는다.** `?from=` 은 **전환**(누가 신청했나), UTM+GA 는 **방문**(누가 들어왔나)이다.
`?from=blog&utm_source=…` 처럼 **같이 붙는다.** 나중에 UTM 을 넣어도 지금 것을 지울 일이 없다.

## 3. 발행 순서 — 계단식

```
D0      og:image 확인 → 원본 발행 → 오픈 채팅방 일반 메시지 (새 글 알림)
D0~1    점수가 가장 높은 공개 채널 하나 (스레드 또는 인스타)
D2~3    나머지 공개 채널
대표작    카톡 채널 — 기존 소식 주소 교체, 또는 새 소식 + 공지 카드 교체
        오픈 채팅방 — 공지가 「글 소개」일 때만 교체. 「방 안내」면 그대로
월말     뉴스레터 — 원본이 확정된 뒤에
```

**거꾸로 하면 링크할 곳이 없다.**

**같은 날 다 뿌리지 않는 이유** — 네 곳을 구독한 사람이 하루에 네 번 본다.
그리고 첫 채널의 반응을 보고 다음 채널의 훅을 고칠 기회가 생긴다.

**공개 채널은 시각을 골라서 올린다.** 스레드는 **10분**, 인스타는 **1시간**이 도달을 결정한다.
**그 시간에 못 있으면 예약 발행**하고, 있을 수 있는 때로 옮긴다.

**뉴스레터를 마지막에 두는 이유** — 메일은 **회수가 안 된다.** 원본 오탈자를 고칠 시간을 벌어둔다.

## 4. 마지막 훑기

- 채널끼리 **말이 서로 어긋나지 않는가** (제목·약속·주기)
- **채널마다 행동이 하나**인가
- **첫 링크**가 그 자리에서 가장 보내고 싶은 곳인가 (카톡은 여기에만 카드가 붙는다)
- 카톡 소식에 **「댓글 미사용」**을 체크했는가
- 오픈 채팅방은 **공지**에 넣었는가 (일반 메시지는 나중에 들어온 사람이 못 본다)
- 오픈 채팅방 공지가 **400자 안**인가 (주소까지 세서. 넘으면 「전체 보기」로 접힌다)
- **주소를 본문에 글자로도** 썼는가 (카드가 실패할 때가 있다)
- 블로그 **맺음말**을 붙였는가 (모바일에 닿는 유일한 자리다)
- **규제 업종이면 표현 검수를 돌렸는가** — 채널을 늘릴수록 도달이 커져 위험도 같이 커진다
- **올린 뒤 10분을 비워뒀는가** (스레드·인스타)
- 소제목이 **사람이 실제로 묻는 말**인가 (검색 + AI 인용 둘 다 걸린다)
- 직함·소속을 **한 줄로 밝혔는가** (가장 싼 GEO다)

## 5. 발행 뒤 — 48시간

```
도달 __   저장 __   댓글 __   1차 전환 __
어디서 끊겼나   ① 봤다 → ② 멈췄다 → ③ 끝까지 → ④ 행동 → ⑤ 도착
```

**④ → ⑤가 가장 많이 끊긴다.** 콘텐츠를 다 만들고 **정작 받을 준비를 안 한 경우**다.
DM 자동응답은 켰는가, 방은 열었는가, 발송 준비는 됐는가.

**발행 결과는 사용자가 본다.** 스킬은 발행된 화면을 볼 수 없다 — 확인할 것 셋을 준다:
미리보기 카드가 제대로 떴나 · 공지가 접히지 않았나 · 링크를 눌러 꼬리표가 붙은 채 도착하나.

**채널을 접을지는 표본이 쌓인 뒤에 정한다.** 채널별로 발행이 **5편 미만**이면 결론을 내지 않고,
설정을 바꾼 지 **3일 이내**면 성과로 보지 않는다. 대신 다음에 해 볼 것 셋과 다시 볼 날짜를 정한다.
그 뒤에는 **반응이 오는 곳에 몰아주는 것**이 채널을 늘리는 것보다 빠르다.
