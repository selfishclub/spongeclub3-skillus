# 길이 · 첫 10분 · SEO · GEO · AEO

> **문구를 다 쓰고 나서 본다.** 「무엇을 쓸까」가 아니라 **「어떻게 해야 닿을까」**다.
> 2026-09 기준. 알고리즘은 바뀌므로 **숫자가 안 맞으면 그 자리에서 다시 확인한다.**

---

## 1. 길이 — 채널마다 기준이 다르다

| | 기준 | 숫자 |
|---|---|---|
| **네이버 블로그** | **글자수가 아니라 체류시간** | 60초가 최소 · **2분 30초~3분**이면 상위권 |
| **스레드** | 한도 500자 · **알고리즘은 첫 150자로 판단** | 실전 **50~150자** |
| **인스타 캡션** | 펼치기 전 **첫 두 줄** | 여기에 훅과 받는 법 |
| **카톡 채널 소식** | 길어도 된다 | |
| **오픈 채팅방 공지** | **짧게** | 스크롤하면 안 읽는다 |
| **웰컴메시지** | 400자 · 버튼 2개 | |
| **뉴스레터** | 스크롤 세 번 안쪽 | 한 통에 주제 하나 |

### 네이버는 「길게」가 아니라 「머물게」다

**글자를 늘리면 오히려 이탈한다.** 체류시간을 늘리는 것은 길이가 아니라 구조다.

```
첫 문단에 결론을 던진다        ← 스크롤할 이유를 만든다
3~5 단락마다 이미지 하나
문단은 모바일 기준 2~3줄로 끊는다
```

## 2. 첫 10분 — **후킹은 문장이 아니라 시간이다**

**이게 가장 자주 놓치는 것이다.** 좋은 글을 쓰고 아무 때나 올린다.

| | 결정 구간 | 무엇을 보나 |
|---|---|---|
| **스레드** | **업로드 후 10분** | 댓글 3개+ · 좋아요 20개+ 면 추가 노출 실험에 들어간다 |
| **인스타** | **첫 1시간** | **저장 · 공유가 좋아요보다 3~5배 강하다** |

### 「좋아요는 많은데 안 뜬다」의 정체

**댓글이 없어서다.** 알고리즘이 **「소비되지만 참여되지 않는 글」**로 분류해 확산을 막는다.

> **그래서 글 자체가 질문이어야 한다.** 「그렇군요」로 끝나는 글에는 댓글이 안 달린다.
> **답을 다 주지 말고 하나를 남긴다.**

### 올리는 시각을 정한다

**첫 10분에 사람이 없으면 아무 일도 안 일어난다.**
**내 계정 인사이트에서 사람이 가장 많은 시간대**를 보고 거기에 맞춘다.
그 시간에 못 올리면 **예약 발행**한다.

### 올리고 나서 10분 동안 할 것

```
① 댓글 하나를 스스로 단다        ← 보충 설명이나 출처. 자문자답이 아니라 이어 쓰기
② 답글에 다음 편을 잇는다        ← 스레드는 이게 체류시간을 만든다
③ 오는 댓글에 바로 답한다
```

### 캐러셀은 두 번 노출된다

**끝까지 안 넘긴 사람에게 2~3일 뒤 첫 장이 다시 노출된다**(re-serve).
**그래서 1장은 두 번 일하고, 6장은 1장과 같은 비주얼이어야** 시리즈로 읽힌다.

## 3. SEO — 네이버는 **주제 집중도**

| | 무엇 |
|---|---|
| **C-Rank** | **한 주제를 꾸준히 쓴 사람**을 우대한다 |
| **D.I.A** | 문서 품질. **키워드 빈도가 아니라 문맥** |

**주제를 흩뜨리는 것이 가장 큰 손해다.** 한 주제로 20편이 30편 잡탕보다 세다.

**카테고리를 주제별로 나눈다.** 「강의·활동」처럼 갈래가 보이면 C-Rank 에 유리하고,
읽는 사람도 「이 사람은 이걸 하는 사람」으로 기억한다.

### 제목과 도입

```
제목      주제 키워드를 앞에, 맥락을 뒤에
첫 100~150자   핵심 키워드와 「이 글을 읽으면 뭘 얻는지」
```
**기관명·브랜드만 있는 제목은 검색이 안 된다.** 사람들이 실제로 치는 말이 앞에 와야 한다.

### 소제목을 **검색어 형태로**

```
🔴  효과는?
✅  ○○에 정말 효과가 있을까
```
**사람들이 검색창에 치는 말에 가깝게.** 이게 GEO 의 「질문–답변 구조」와 같은 일이다 —
**한 번 쓰고 검색과 AI 인용에 둘 다 걸린다.**

### 최소 분량은 있다

**체류시간이 기준이지만 바닥은 있다.** 네이버는 **본문 1500자 이상**을 기준으로 삼는 것이 안전하다.
너무 짧으면 검색에서 밀린다. **다만 길이를 채우려고 같은 말을 반복하지 않는다.**

### 태그

**고정 태그 + 글마다 다른 태그.** 고정 쪽이 주제 집중도(C-Rank)를 쌓고,
변동 쪽이 개별 검색을 잡는다. **합쳐서 10개 안팎.**
계정에 정해둔 고정 태그가 있으면 그것을 쓴다.

### 🔴 다른 곳에서 복사한 문장을 넣지 않는다

**중복 문서로 판정되면 글 전체가 묻힌다.** 인용이 필요하면 짧게 하고 출처를 밝힌다.
**리퍼포징의 흐름은 블로그 → 나머지 한 방향뿐이다.**

## 3-b. 인스타는 **검색도 된다** — 인앱 SEO

**해시태그만 보는 게 아니다.** 인스타 검색은 **캡션 · 대체 텍스트 · 이름 필드 ·
사용자명 · 위치**를 같이 읽는다. 그래서 **같은 검색어를 여러 곳에 심는다.**

### 같은 말을 세 곳에

```
① 캡션 첫 줄      검색될 말을 여기에. 「더 보기」를 받는 자리이기도 하다
② 대체 텍스트      ← 안 쓰는 사람이 대부분이다
③ 이름 필드        30자. 검색에 잡힌다. 비워두면 손해
   (릴스면 자막도)
```

### 해시태그는 **3~5개**

**30개 도배는 끝났다.** 인스타그램이 공식적으로 **「적은 수의 관련 해시태그가 낫다」**고 밝혔다.
**관련 없는 인기 태그는 도달에 오히려 손해**다.

### 대체 텍스트 쓰는 법

```
게시물 작성 → 고급 설정 → 대체 텍스트 쓰기
(이미 올린 것도 ⋯ → 수정 → 대체 텍스트에서 가능)
```

**이미지를 설명하되 핵심 키워드 1~2개를 흐름 속에 녹인다.**
「수면 생체리듬 한방신경정신과 불면」처럼 나열하면 **스팸 패턴으로 잡혀 노출이 제한된다.**

> **키워드를 억지로 반복하면 역효과다.** 가독성이 망가지면 팔로우 전환이 떨어진다.
> **자연스럽게 한 번**이면 된다.

### 도달의 사슬

```
시각이 탭을 받고
  → 캡션 첫 줄이 「더 보기」를 받고
    → 끝의 질문이 댓글을 받고
      → 댓글이 도달을 받는다
```

**캡션 끝에 질문이 없으면 사슬이 끊긴다.** 「첫 10분」(위 2번)과 같은 이야기다.

> ⚠️ **위치 태그는 업종에 따라 신중하게.** 검색에는 걸리지만, **규제 업종에서는
> 사업장 위치를 다는 것 자체가 광고로 읽힐 수 있다.** 넓은 지역만 쓰거나 비워둔다.

## 4. GEO · AEO — AI 답변 안에 들어가기

**Generative Engine Optimization.** ChatGPT · Claude · Perplexity 가 답할 때
**그 답 안에 내 내용이 인용되게** 하는 것이다.

**AEO(Answer Engine Optimization)** 는 거의 같은 말이다. 범위가 조금 넓어서
구글 AI 개요 · 추천 스니펫 · 「사람들이 많이 묻는 질문」 · 음성 비서까지 포함한다.
**성공을 세는 것만 다르다** — SEO 는 순위, AEO 는 **답으로 뽑혔나**, GEO 는 **인용됐나.**

| | SEO | GEO |
|---|---|---|
| 목표 | 검색 결과 **순위** | **AI 답변 안에 인용** |
| 여정 | 검색 → 클릭 → 페이지 | 질문 → **단일 답변**. 클릭이 없다 |
| 보는 것 | 키워드 · 권위 신호 | **사실 밀도 · 출처 · 구조** |

### GEO 가 요구하는 다섯

```
① 질문–답변 구조        사람이 실제로 묻는 말 그대로 소제목을 단다
② 사실 밀도             숫자 · 기전 · 조건. 「좋습니다」가 아니라 「몇 시간, 왜」
③ 출처 표기             근거가 있는 문장에는 출처를 붙인다
④ 엔티티 일관성          이름 · 소속 · 표기를 모든 채널에서 똑같이 쓴다
⑤ 기계가 읽을 수 있는 구조  소제목 · 목록 · 표. 줄글 덩어리는 인용되지 않는다
```

### 「자주 받는 질문」이 곧 GEO 다

**따로 할 일이 아니다.** 이 스킬이 이미 요구하는 구조가 그대로 GEO 다.

```
「{{사람들이 실제로 묻는 말}}」
→ 답 두세 문장 + 근거 한 줄
```

**소제목을 질문으로 달면** 검색에도 걸리고 AI 도 인용한다. **한 번 쓰고 두 번 먹는다.**

### 질문 바로 아래에 40~60자 답을 먼저

**스니펫과 AI 개요는 질문 소제목 아래의 첫 문장을 통째로 들어올린다.** 그 문장이 답이어야 한다.

```
「주말에 몰아 자면 피로가 풀리나요?」
→ 잠의 양은 채워도 리듬은 오히려 밀립니다. 월요일이 더 힘든 이유입니다.   ← 여기까지 40~60자
→ 그다음에 설명을 편다
```

**도입부터 돌아 들어가면 뽑히지 않는다.** 배경 설명은 답 뒤로 보낸다.

### 이 스킬 밖의 AEO

구조화 데이터(`schema.org` FAQ 등) · `llms.txt` · 사이트맵은 **자기 도메인 홈페이지가 있어야** 한다.
네이버 블로그 · 인스타 · 스레드 · 카톡에는 넣을 자리가 없다. 홈페이지가 있으면 별도 작업으로 한다.

### GEO 는 유입이 안 잡힌다

**클릭 없이 끝나므로** `?from=` 에도 안 남고 GA 에도 안 뜬다.
**그래서 SEO 를 대체하지 않는다.** 순서는 **SEO 가 먼저, GEO 는 구조를 바꿔서 공짜로 따라오는 것**이다.

> **전문 자격 · 실무 경험 · 실제 근거가 있으면 GEO 에 유리하다.**
> AI 는 인용해도 되는 출처를 고르고, 그 판단에 **누가 썼는가**가 들어간다.
> **직함과 소속을 글마다 한 줄로 밝히는 것**이 가장 싼 GEO 다.

## 5. 채널별로 무엇을 챙기나 — 한 장 요약

| | 길이 | 결정 구간 | 챙길 것 |
|---|---|---|---|
| **블로그** | 체류 2분 30초+ | 없음 (검색은 느리다) | **SEO · GEO** · 주제 집중 |
| **스레드** | 50~150자 | **10분** | 훅 · **댓글이 달릴 여지** |
| **인스타** | 캡션 두 줄 | **1시간** | **저장 · 공유** · 1장 · **캡션 첫 줄 + 대체 텍스트 + 태그 3~5개** |
| **카톡 채널** | 자유 | 없음 | 첫 링크 · 카드 |
| **오픈 채팅방** | 짧게 | 없음 | 공지에 넣기 |
| **뉴스레터** | 짧게 | 없음 | 제목 · 첫 줄 |

**검색 채널(블로그)과 피드 채널(스레드·인스타)은 시간 감각이 다르다.**
블로그는 **몇 주에 걸쳐** 오고, 피드는 **한 시간 안에** 끝난다.
**같은 잣대로 평가하면 블로그를 너무 일찍 접는다.**
