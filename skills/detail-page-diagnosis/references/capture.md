# 자료 모으는 법

진단은 자료가 전부다. 못 본 걸 「없다」고 쓰면 오진이 된다.

자료를 모으는 길은 둘이다.

- **A. 클로드가 직접 연다** — 브라우저 조작 도구가 있고 사이트가 막혀 있지 않을 때
- **B. 사용자에게 받는다** — 도구가 없거나 **사이트가 막혔을 때.** 브라우저 도구(앱 브라우저·Claude in Chrome 모두)는 네이버 **스마트스토어·브랜드스토어·네이버쇼핑 검색**을 안전 제한으로 막는다. 크롬 확장은 **사용자가 직접 연 탭도 읽지 못한다**(확장이 만든 탭 묶음만 본다). 이때 다른 경로로 우회하지 않고 B로 간다

어느 길이든 마지막에 **C. 받은 자료 점검**을 한다.

| # | 자료 | 누구 페이지 | 어디서 | 형식 | |
|---|---|---|---|---|---|

| 4 | 상품정보 표 · 상품정보제공고시 | 전부 | 상품 페이지 버튼 | 스크린샷 | 필수 |
| 5 | 리뷰 전체 | 내 상품 | 판매자센터 리뷰 관리 | **엑셀 파일** | 필수 |
| 5' | 리뷰 (낮은 점수) | 경쟁사 | 상품 페이지 리뷰 창 | 스크린샷 여러 장 | 필수 |
| 6 | 판매자 답글 | 내 상품 | 클로드가 고른 리뷰만 | 복사 또는 스크린샷 | 필요할 때 |

## A. 클로드가 직접 열 때

### A-1. 모바일로 연다
뷰포트 **375×812**. 모바일 전용 도메인(`m.`)으로 넘어가면 그게 실제 모바일 손님이 보는 페이지다.

내 페이지면 **방문 집계에 안 잡히는 방법**(미리보기 파라미터 등)이 있는지 먼저 묻는다. 진단하느라 내 데이터를 오염시키지 않는다.

### A-2. 첫 화면을 캡처한다
스크롤하기 **전에** 캡처. 팝업·쿠키 배너가 떠 있으면 그것도 첫 화면이다.

브라우저 도구의 캡처가 파일로 저장되지 않으면 헤드리스 브라우저로 한 장 더 찍는다.
```
msedge --headless=new --hide-scrollbars --window-size=375,812 --force-device-scale-factor=2 \
  --user-agent="Mozilla/5.0 (Linux; Android 14) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/128 Mobile Safari/537.36" \
  --screenshot=first.png "<URL>"
```
(맥은 `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"`). 모바일 흉내가 불완전해 **오른쪽이 잘릴 수 있다** — 기록용으로만 쓰고 판정은 브라우저 도구 화면으로 한다.

### A-3. 끝까지 스크롤해 지연 로딩을 깨운다
```js
window.scrollTo(0, document.body.scrollHeight);
await new Promise(r => setTimeout(r, 2500));
window.scrollTo(0, 0);
```
이미지가 1×1 자리표시자로 남으면 진짜 주소가 다른 속성에 있다.

| 플랫폼 | 진짜 주소가 든 속성 |
|---|---|
| 카페24 | `ec-data-src` |
| 흔한 지연 로딩 라이브러리 | `data-src`, `data-original`, `data-lazy` |

### A-4. 섹션 위치와 텍스트를 뽑는다
```js
[...document.querySelectorAll('section, header, footer, [data-sec]')].map(s => ({
  name: s.dataset.sec || s.id || s.tagName,
  top: Math.round(s.getBoundingClientRect().top + scrollY),
  h: s.offsetHeight,
  text: s.innerText.replace(/\s+/g, ' ').slice(0, 200)
}))
```
결과가 수만 자면 셀렉터가 너무 넓다. `section`만으로 좁힌다.

### A-5. 텍스트가 비면 이미지를 읽는다
- 상세 영역 안 **가로 300px 이상** 이미지만 내려받아 한 장씩 읽는다
- 세로 3,000px 넘는 이미지는 잘라서 읽는다 (C-1)
- 이미지 속 **작은 글씨**(사이즈·소재·두께·주의사항)를 특히 본다

### A-5-1. 글자를 뽑으면 **보이는지** 확인한다
`innerText`·`textContent`로 뽑은 글자에는 **화면에 안 보이는 문구**가 섞인다 — 닫힌 탭 안 글자, 스킨에 늘 들어 있는 숨김 안내문(`displaynone`, `display:none`). 카페24 스킨의 「글읽기 권한이 없습니다 · 19세 미만의 미성년자는 출입을 금합니다」가 실제로는 숨김 문구였는데 「보인다」고 보고한 적이 있다.

```js
const visible = e => !!(e.offsetWidth || e.offsetHeight || e.getClientRects().length);
[...document.querySelectorAll('*')]
  .filter(e => e.children.length < 4 && /찾는 문구/.test(e.innerText || ''))
  .map(e => ({ cls: String(e.className).slice(0, 60), visible: visible(e) }))
```
**보이는 것만 [관찰]로 쓴다.** 탭 안 내용은 탭을 **눌러 연 뒤** 다시 확인한다. 게시판 글이 어느 게시판 것인지는 링크 주소(`board_no`)로 확인한다.

### A-6. 탭·옵션·더보기를 연다
- **탭**: 상세정보 / 구매안내 / 후기 / Q&A — 각 영역 `innerText`를 따로 뽑는다
- **옵션 선택창**: `option` 텍스트를 전부 적는다. 추가금은 여기서만 보이는 경우가 많다. 장바구니에 담지는 않는다
- **상품 정보 표**: 「모델명」「비고」 같은 엉뚱한 칸에 수량 규칙이 들어 있기도 하다
- **더보기 / 펼치기**는 누른다

### A-7. 고정 버튼
```js
[...document.querySelectorAll('*')]
  .filter(e => getComputedStyle(e).position === 'fixed' && e.offsetHeight > 0)
  .map(e => e.innerText.trim().slice(0, 40))
```

### A-8. 후기·Q&A
개수, 평균 별점, 별점 낮은 순 목록. 0건이면 「0건」이라고 기록한다. 규칙은 B-5와 같다.

## B. 사용자에게 받을 때 (초보자용 안내)

아래 문단은 **사용자에게 그대로 보여줘도 되게** 썼다. 필요한 번호만 골라 보여준다.

### B-1. 상세페이지 전체 — GoFullPage로 PDF 저장

**GoFullPage**는 긴 페이지를 자동으로 스크롤하면서 한 장으로 찍어주는 크롬 확장 프로그램이다. 무료 버전으로 충분하다.

**처음 한 번만**
1. 크롬 웹스토어에서 「GoFullPage - Full Page Screen Capture」를 설치한다
2. 주소창 오른쪽 **퍼즐 아이콘** → GoFullPage 옆 **핀**을 눌러 고정한다
3. GoFullPage 아이콘 → **톱니(설정)** → PDF 크기를 **「full image」** 로 바꾼다 — 페이지 전체가 한 장으로 저장된다

**매번**
1. **PC** 크롬에서 상품 페이지를 연다
2. **팝업·알림 배너·다른 확장 프로그램 창을 전부 닫는다** (열린 창이 그대로 찍혀 내용을 가린다)
3. 페이지를 **맨 아래까지 한 번 천천히** 내린다 — 사진을 미리 불러오게
4. 맨 위로 올린다
5. GoFullPage 아이콘을 누르거나 **Alt + Shift + P**
6. 자동 스크롤이 끝날 때까지 **마우스·키보드를 건드리지 않는다**
7. 새 탭에 결과가 뜨면 **PDF 아이콘**으로 저장한다 (처음이면 다운로드 권한을 허용)
8. 저장된 PDF를 대화창에 **파일로 첨부**한다

**이 캡처에 안 담기는 것** — 리뷰·Q&A 탭 내용, 닫힌 옵션 선택창, 「펼쳐보기」 안쪽. 그래서 B-3~B-6을 따로 챙긴다.

**⚠ 「리뷰 전체보기」 팝업은 GoFullPage로 찍지 않는다.** 팝업은 스크롤이 따로 있어서 **같은 화면이 계속 반복해서** 찍힌다(58건 대신 3건이 13번 반복된 적이 있다).

### B-2. 모바일 첫 화면 — 휴대폰 스크린샷

손님 대부분은 휴대폰으로 본다. 첫 화면 3초 점검은 **휴대폰 화면으로만** 한다.

1. 휴대폰에서 상품 페이지를 열고 **스크롤하기 전에** 1장
2. 조금 내려 **가격 · 혜택 · 배송**이 보이는 화면 1장

### B-3. 옵션 선택창
PC에서 **옵션 선택을 펼친 상태**로 찍는다. 옵션 이름·추가금이 여기서만 보이기도 한다.

### B-4. 상품정보 표 · 상품정보제공고시
상세정보 탭 위쪽의 **「상품정보 펼쳐보기」**, **「상품정보제공고시 보기」** 를 눌러 펼친 뒤 찍는다. 제조사·원산지·길이 같은 사실이 여기 있고, 상세 이미지와 **다른 말**을 하는 경우가 있다.

### B-5. 리뷰

**내 스마트스토어 상품 — 엑셀로 전부**
1. 스마트스토어센터 → 왼쪽 **문의/리뷰관리** → **리뷰 관리**
2. **리뷰작성일** 기간을 고른다. 「선택한 리뷰작성일로 조회」를 **체크하지 않으면** 기간과 상관없이 전체가 나온다
3. 리뷰구분 · 리뷰타입 · 채널 · 구매자평점 · 혜택 지급 · 전시상태를 **전부 체크된 상태**로 둔다
4. **상세검색**에서 「상품번호」를 고르고 번호를 넣는다
   - 상품번호 = 상품 주소 끝의 숫자 (`…/products/10433390647`), 또는 상품정보 표의 「상품번호」
5. **검색** → 결과를 **엑셀로 내려받는다**
6. 엑셀을 대화창에 파일로 첨부한다

엑셀에 **없는 것** — 판매자 **답글 내용**(답글여부 Y/N과 등록일시만 있다), 리뷰 속성 **값**(「평소 신발 사이즈」라는 항목 이름만 있고 240mm 같은 값은 없다). 답글은 B-6으로 받는다.

**경쟁사 상품 — 캡처로**
1. 가격 아래 **「4점 이상 리뷰가 N%예요」** 로 3점 이하 건수를 먼저 계산한다 (58건 × 3% ≈ 2건)
2. 리뷰 창에서 **「평점 낮은 순」** 정렬
3. **맨 위부터**, 3점 이하가 끝날 때까지 한 화면씩 찍는다
4. 리뷰 창 위쪽 **키워드**(「얇아요」「두꺼워요」 등)도 한 장

**쓰지 않는 방법** — 커머스API(리뷰 조회 기능이 없다), 크롤링·자동 대량 수집(네이버가 막고 약관 문제가 있다), 유료 리뷰 추출기(답글 항목이 없다).

### B-6. 판매자 답글 — 클로드가 골라서 묻는다

답글을 전부 모을 필요는 없다. 진단에 필요한 건 **불만이 있는 리뷰의 답글**뿐이다.

클로드가 할 일:
1. 엑셀에서 **불만 리뷰를 고른다** — 점수와 상관없이 문장에 불만이 있는 것 전부. 5점 안에도 불만이 있다(「한번 빨았는데 박음질 터졌어요」가 5점이었다)
   - 신호: 3점 이하, 또는 얇다·두껍다·크다·작다·마감·실밥·박음질·터짐·구멍·보풀·늘어남·미끄러짐·아쉽다·불편·개선
2. **답글여부로 나눈다**
   - **Y** → 답글에 판매자 설명이 있을 수 있다. **답글 내용을 요청한다**
   - **N** → 가져올 답글이 없다. **그 불만에 대한 사실을 판매자에게 묻는다** (이미 같은 주제로 답을 받았으면 묻지 않는다)
3. **한 번에 최대 5건**, 이 형식으로 묻는다
   > **[R3] 2026.06.12 · ★4 · 한달사용리뷰 · 블랙 3켤레**
   > 「…발바닥두께가 얇아요.」
   > → 6/15에 답글이 있어요. 답글 내용을 복사하거나 캡처해 주세요.
4. 긍정 리뷰의 답글은 묻지 않는다

사용자가 할 일: 상품 페이지 리뷰에서 그 리뷰를 찾아 **「더보기」를 눌러 펼친 뒤** 답글을 복사하거나 찍는다.

### B-7. 통계 — 무엇에 쓰는지 알려주고 받는다

통계는 **없어도 진단할 수 있다.** 달라고 할 때는 용도를 같이 말한다.

| 데이터 | 쓰는 곳 | 스마트스토어에서 |
|---|---|---|
| 섹션 도달률 · 히트맵 · 스크롤 깊이 | 새는 곳을 숫자로 확인 | **받을 수 없다** — 판매자가 스크립트를 넣을 수 없어 Clarity·Hotjar 등이 안 붙는다 |
| 상세 조회수 · 결제 건수 (결제율) | 고친 **뒤** 비교할 기준점 | 판매자센터 통계 |
| 유입 검색어 | 상품명·키워드 판단 | 판매자센터 통계 |
| 채널별 유입·결제 | 어느 콘텐츠가 사는 사람을 데려오나 | 링크에 **NT 파라미터**를 붙여야 잡힌다 (아래) |
| 톡톡 문의 내용 | 사기 **전** 질문 = 페이지에 답이 없는 곳 | 톡톡 상담 내역 |

**NT 파라미터** — 스마트스토어 통계는 `utm_*` 대신 `nt_*`를 읽는다.
```
…/products/10433390647?nt_source=threads&nt_medium=social&nt_detail=0916-toe
```
`nt_source`·`nt_medium`은 필수(영문만), `nt_detail`·`nt_keyword`는 선택(한글 가능). 결과는 판매자센터 통계의 마케팅분석 → 사용자정의채널에서 본다(메뉴 이름은 바뀌었을 수 있다).

**네이버 애널리틱스** — 판매자센터 노출관리 → 노출 서비스 관리에서 연결한다. 방문·유입·체류시간 정도이고 스크롤·섹션 도달은 없다.

**섹션별로 꼭 재야 하면** — 같은 상세 내용을 **자사몰(카페24 등, 스크립트를 넣을 수 있는 곳)** 상품 페이지에 두고 Clarity를 붙여 잰다. 거기서 찾은 이탈 지점을 네이버 페이지 수정에 쓴다.

### B-8. 판매자만 아는 사실 — 질문지

페이지만 봐서는 알 수 없는 것. 진단 중에 필요한 것만 묻는다.

- **업계에서 이 상품을 뭐라고 부르나요?** (예: 「등산 파일 이중바닥양말」) — 리뷰 불만이 그 기준과 비교해서 나온다
- **무엇과 비교해서 「두껍다/따뜻하다/튼튼하다」인가요?** (일반 양말 기준 / 같은 용도 제품 기준)
- **이 표기·링크·문구는 일부러 넣은(뺀)건가요?** — 가린 가격, 다른 상품 링크, 빠진 치수, 상품명의 겹친 키워드
- 제조 · 원산지 · 불량 처리 방식
- 내 다른 채널(자사몰 등)에도 같은 상품이 있나요?

## C. 받은 자료 점검

### C-1. 긴 캡처는 원본 해상도로 꺼내 잘라 읽는다
PDF든 PNG든 **파일 경로**로 받았으면, 통째로 보지 말고 원본을 꺼내 1500px 높이로 잘라 한 조각씩 읽는다.

```python
# pip install pymupdf pillow
import pymupdf, io
from PIL import Image
Image.MAX_IMAGE_PIXELS = None
doc = pymupdf.open("capture.pdf")
xrefs = []
for page in doc:                      # 페이지마다 같은 이미지가 반복 등록될 수 있다 → 중복 제거
    for img in page.get_images():
        if img[0] not in xrefs:
            xrefs.append(img[0])
parts = [Image.open(io.BytesIO(doc.extract_image(x)["image"])).convert("RGB") for x in xrefs]
W, H = max(p.width for p in parts), sum(p.height for p in parts)
full = Image.new("RGB", (W, H), "white"); y = 0
for p in parts:
    full.paste(p, (0, y)); y += p.height
for i, top in enumerate(range(0, H, 1500)):
    full.crop((0, top, W, min(H, top + 1500))).save(f"slice_{i:02d}.jpg", quality=88)
```
사진만 이어지는 구간(DETAIL VIEW 등)은 건너뛰어도 되지만, **건너뛴 구간을 진단서 한계에 적는다.**

### C-2. 반복 캡처인지 확인한다
같은 리뷰·같은 화면이 여러 조각에 되풀이되면 **실패한 캡처**다. 읽은 척하지 말고 다시 받는다.

### C-3. 리뷰 엑셀 읽기
주요 열: `구매자평점` · `리뷰상세내용` · `리뷰구분`(일반/한달사용) · `관련리뷰상세내용`(한달사용리뷰의 원래 리뷰) · `답글여부` · `답글등록일시` · `리뷰등록일` · `상품명`(옵션명은 리뷰 화면에만 있다)

1. 별점 분포와 평균
2. 주제별로 센다 — 두께·사이즈·마감·색·용도 등. **같은 주제가 긍정·부정으로 갈리면 누가(어떤 용도로) 말했는지** 같이 본다
3. 불만 리뷰 표(R1…)를 만들고 B-6으로 답글을 받는다
4. 진단서 `reviews`에 「몇 건 중 몇 건 읽음」과 함께 넣는다

### C-4. 같은 사실을 여러 곳에서 대조한다
상품명 · 옵션명 · 상품정보 표 · 상품정보제공고시 · 상세 이미지 속 제품정보 · **포장 사진**. 길이(장목/중목), 두께, 제조·원산지, 사이즈가 서로 다른 말을 하는 경우가 많다.

### C-5. PC로 한 판정은 모바일로 다시 본다
PC 캡처만 있을 때 한 판정(특히 첫 화면·위치)은 [확인 필요]로 두고, 모바일 캡처를 받으면 다시 판정한다.

## 내 페이지에 방문 데이터가 있을 때 (직접 만든 랜딩·자사몰)

| 데이터 | 진단에 쓰는 자리 |
|---|---|
| 섹션 도달률 | 섹션 지도의 「도달률」 칸, 누수의 [데이터] |
| 클릭 히트맵 | 끊긴 길 — 버튼이 아닌 곳을 누르는가 |
| 세션 녹화 (Clarity 등) | 도달률이 떨어지는 자리에서 **나갔는지, 버튼을 눌렀는지** 가르기 |
| 평균 스크롤 깊이 | 늦은 답 — 답이 평균 깊이보다 아래 있나 |

도달률은 **첫 화면 도달 수를 100%** 로 놓고 계산한다. 비밀번호·토큰이 필요한 데이터는 **읽기 전용 권한**으로만 읽고, 값은 화면에 출력하지 않는다.
