# 개인별 리포트 — 고객의 답을 읽고 한 사람에게 돌려주는 법

**왜 쓰나.** 진단을 마친 고객에게 결과를 돌려주는 순간이 관계가 가장 가까워질 수 있는 자리다. 누구에게나 보낼 수 있는 결과지는 거기서 관계를 끊는다. **고객 한 명 한 명의 답이 문장마다 반영된 리포트**를 받으면 「이 사람이 내 답을 읽었다」를 체감하고, 그 체감이 가두리망으로 들어올 이유가 된다.

**그래서 순서가 정해져 있다.** 진단지를 먼저 확인하고 → 고객의 답을 진단지와 한 줄씩 맞추고 → 그 매칭 위에 살을 붙인다. 답에 닿지 않는 문장은 일반론이고, 일반론이 섞일수록 「직접 읽었다」가 무너진다.

**산출물은 초안이다.** 사람이 읽고 고쳐서 보낸다. 자동 발송은 만들지 않는다. 「직접 읽고 돌려드립니다」가 혜택의 값이기 때문이다.

## 🔴 이 스킬은 기준을 갖고 있지 않다

리포트의 **내용을 정하는 기준은 전부 사용자의 것**이다. 서비스마다 고객이 다르고, 무엇이 그 고객에게 「가장 필요한 한 가지」인지는 서비스를 만든 사람만 안다.

| 누가 정하나 | 무엇 |
|---|---|
| **사용자가 제시한다** | 진단지 · 리포트 칸 구성 · 보기마다 리포트에서 무엇을 말할지 · 핵심을 고르는 기준 · 실천 조건 · 쓰지 않을 말 · 목소리 · 가두리망 |
| **스킬이 지킨다** | 진단지 먼저 · 매칭표 · 답에 닿지 않는 문장 빼기 · 쌍둥이 검사 · 개인정보 없이 답만 · 초안만 쓰고 사람이 보냄 · 가두리망 한 곳으로 닫기 · 고친 말 쌓기 · 메일용 판 |

**스킬이 하는 일은 환기와 추천이다.** 정해야 할 것마다 「이걸 안 정하면 무슨 일이 생기나」를 먼저 말하고, 추천안을 **추천이라고 밝혀** 보여 준 뒤, 사용자가 고르거나 적게 한다.

- 사용자가 「알아서 해줘」라고 해도 **보기마다 리포트에서 무엇을 말할지는 채우지 않는다.** 선택지 두세 개를 만들어 고르게 한다
- 추천안은 **어느 특정 서비스의 것이 아니다.** 예시가 필요하면 `[자리표시]` 로 쓴다
- 사용자의 기준과 추천이 다르면 **사용자 기준을 따른다.** 추천은 한 번만 말한다

고객 리포트를 만드는 과정을 세 단계로 나눴다. **📥 는 사용자가 자기 자료·답을 넣는 자리**이고, 스킬은 거기를 대신 채우지 않는다.

## 이 스킬이 하는 일과 안 하는 일

| | 맡는 곳 |
|---|---|
| 무엇을 줄지 · 왜 리포트인지 | `lead-offer-design` |
| 신청을 받아 담을 그릇 · 진단 문항 설계 | `lead-form` |
| 어디서 온 사람인지 세기 | `lead-source` |
| **받은 답을 진단지에 맞춰 읽고, 한 사람에게 리포트 초안 쓰기** | **이 스킬** |

진단지가 없으면 여기부터 하지 않는다. 맞출 기준이 없다.

## 0단계 · 설정이 있는가

리포트 폴더(사용자가 정한 **공개 저장소 밖** 폴더) 안에 `_설정/` 이 있는지 본다.

| 있는가 | 할 일 |
|---|---|
| 없다 | `references/setup.md` 대로 설정부터. **리포트를 먼저 쓰지 않는다** — 기준 없이 쓰면 AI 기본값으로 쓰게 되고, 그건 누구에게나 보낼 수 있는 글이다 |
| 있다 | **`_설정/진단지.md` 부터** 읽고, 나머지 설정을 읽은 뒤 ① 로 |

명단에 **진단지에 없는 보기 값**이 나오면 쓰기 전에 멈추고 진단지를 다시 받는다. 옛 진단지로 매칭하면 고객이 고르지 않은 보기를 고른 것처럼 쓰게 된다.

## 하드 게이트 — 기준이 무엇이든 지킨다

| | |
|---|---|
| **개인정보** | 이메일·이름·전화·id 를 받지 않는다. 입력은 **신청 시각 + 답**뿐 |
| **짝 맞추기** | 누구에게 보낼지는 사람이 자기 명단에서 **신청 시각**으로 맞춘다. 스킬은 「○월 ○일 ○시 ○분 신청자」까지만 안다 |
| **시각** | 명단 화면과 **같은 시간대**로 적는다. DB 는 대개 UTC 라, 그대로 자르면 시간대 차이만큼 어긋나 엉뚱한 사람을 찾는다 |
| **매칭** | 리포트의 문장은 매칭표 줄 하나 이상에서 온다. **고르지 않은 보기를 고른 것처럼 쓰지 않는다** |
| **확인 못 하는 사실** | 빈칸 + `[확인 필요]`, 또는 받는 분이 채울 `[대괄호]`. 틀린 예는 빈칸보다 나쁘다 |
| **가두리망** | 모든 리포트가 사용자가 정한 **한 곳**으로 닫힌다. 링크는 맨 끝에 한 번. 내용 기준이 아니라 이 스킬의 목적(가두리망으로 잇기)에서 나온 구조 규칙이다 — 어디로 어떤 문장으로 닫을지는 사용자가 정한다 |
| **산출 위치** | 공개 저장소 **밖.** 답변이 들어 있다 |

## 흐름

### ① 재료 받기

📥 **사용자가 넣는 것** — 명단을 받는 곳(구글폼·DB·붙여넣기)과, 그중 **시각 열 · 자유서술 열 · 객관식 열의 이름**. 이메일 열은 이름을 받지 않는다.

**명단 전체**를 받는다. 쌍둥이를 찾으려면 한 사람이 아니라 전원이 필요하다. 방법은 `references/data.md`.

```
python scripts/codes.py csv <내보낸.csv> <리포트 폴더>/_codes --time <시각 열> --free <자유서술 열> --keys <객관식 열들>
```

`codes.json` 과 `twins.md` 가 나온다. 스크립트는 **지정한 열만** 읽는다. 이메일 열은 이름을 주지 않으면 읽히지 않는다.

### ② 진단지와 답 맞추기 — 매칭표

**쓰기 전에** 고객의 답을 진단지와 한 줄씩 맞춘다. 코드가 아니라 **고객이 화면에서 본 글자**로 적는다.

```
자유서술  "고객이 쓴 문장 그대로"

| 문항 (진단지 원문) | 고른 보기 (화면 글자 그대로) | 역할 | 사용자 기준 (역할표) | 이 고객 리포트에서 |
|---|---|---|---|---|
| [문항 원문] | [보기 글자] | [역할] | [그 보기에 사용자가 정한 한 줄] | [어느 칸에서 무엇이 되나] |
```

- **「사용자 기준」 열은 `_설정/역할표.md` 에서 그대로 옮긴다.** 스킬이 새로 만들지 않는다. 비어 있으면 그 자리에서 사용자에게 묻는다
- **마지막 열이 살을 붙일 자리다.** 쓸 데가 없는 답은 비워 둔다 — 전부 쓰려고 하면 설문 요약이 된다
- **두 답이 어긋나는 줄**에 표시한다 (`roles.md` 「두 답이 어긋나면」). 그 고객만의 관찰이 거기서 나온다

### ③ 쌍둥이 찾기

`twins.md` 표에서 그 고객의 줄을 본다. `references/twins.md` 「쓰기 전」. 동률이면 전부, 문턱 미만이면 쌍둥이 없음.

### ④ 칸마다 쓰기

`_설정/리포트틀.md` 의 칸 순서대로, **매칭표의 마지막 열을 문장으로 푼다.** 칸마다 사용자가 정한 조건(분량·실천 조건·금지)을 지킨다.

- 자유서술이 있고 사용자가 「첫 줄에 그대로」를 골랐으면 **한 글자도 안 고친다**
- 핵심을 고를 때는 `_설정/역할표.md` 의 **사용자가 정한 순서**를 따른다
- 끝은 `_설정/가두리망.md` 의 문장과 링크로 닫는다

### ⑤ 검사

순서대로. 걸리면 **그 칸만** 다시 쓴다.

1. **매칭표에 닿는가** — 문장마다 매칭표 줄 하나 이상에서 왔는가. 어느 답에서도 오지 않은 문장은 일반론이니 빼거나, 고객만 아는 사실이면 `[대괄호]`로 비운다
2. **하드 게이트** 일곱 줄
3. **사용자 기준** — `_설정/리포트틀.md` 의 조건 · `_설정/목소리0층.md` 의 쓰지 않는 말
4. **추천 검사 중 사용자가 채택한 것** — `_설정/리포트틀.md` 「채택한 검사」
5. **쌍둥이** — 쌍둥이 **전원**과 핵심 칸이 다른가

### ⑥ 산출 — 두 벌

```
<리포트 폴더>/<YYYY-MM-DD>-초안/<번호>-<MMDD-HHMM>.md          검토용
<리포트 폴더>/<YYYY-MM-DD>-초안/<번호>-<MMDD-HHMM>.메일용.txt   붙여넣기용
```

검토용 맨 위에 보내기 전 확인, 매칭표, `---`, 리포트 본문.

```
☐ 가두리망 링크를 눌러 봤다
☐ 쌍둥이(<신청시각>, …)와 핵심 칸이 다르다   /   쌍둥이 없음 (최대 N/M)
☐ [확인 필요] 표시가 남아 있지 않다

(매칭표)

---

(리포트 본문)
```

메일용은 `python scripts/mailtxt.py <검토용.md>` 로 만든다. `---` 위를 떼고, **코드블록을 위아래 가로줄로 바꾼다.** 코드블록을 메일에 그대로 붙이면 모양이 깨져서 손보는 데 시간이 든다. 사람이 검토용을 고치면 메일용을 다시 만든다.

## 여러 건을 한 번에 쓸 때

한 건씩 ②~⑥ 을 돈다. **다 쓰고 나서 한꺼번에 검사하지 않는다** — 쌍둥이 검사가 앞 것과 뒤 것 사이에서 걸려야 한다.

**쌍둥이끼리 붙여서 연달아 쓴다.** 명단 순서대로 쓰면 겹치는 두 사람 사이에 다른 사람이 끼어서 차이를 놓친다.

다 쓰고 나서 **전체를 나란히 놓고 핵심 칸이 같은 자리인 쌍이 있는지** 한 번 더 본다. 폴더에 `_작성메모.md` 를 남긴다 — 건별 핵심 한 줄 표, **사용자 기준끼리 부딪힌 곳**, 같은 사람일 수 있는 짝, 사람이 정할 것. 기준이 부딪히면 스킬이 고르지 않고 적어서 묻는다.

초안이 다 나오면 `references/send.md` 보내기 단계로 넘어간다.

## 사람이 고치면

보내기 전에 사람이 고친 곳을 받아서 **그 자리의 설정에 날짜와 함께 한 줄** 더한다.

| 고친 것 | 어디에 |
|---|---|
| 말 (단어·말투) | `_설정/목소리0층.md` |
| 판단 (핵심 자리·보기 해석) | `_설정/역할표.md` 해당 보기 줄 |
| 모양 (칸·분량·조건) | `_설정/리포트틀.md` |

**고친 사람의 말로 적는다.** 스킬이 일반화해서 규칙으로 바꾸지 않는다.
