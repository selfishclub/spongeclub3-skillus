# setup — 준비 단계 (처음 한 번, 약 30분)

리포트 폴더에 `_설정/` 이 없으면 여기부터 한다. **이 단계를 건너뛰고 쓰면 AI 기본값으로 쓰게 되고, 그건 누구에게나 보낼 수 있는 글이다.**

단계마다 네 칸으로 진행한다.

```
📥 넣는 것   사용자가 자기 자료·답을 넣는 자리. 스킬이 대신 채우지 않는다
🔔 환기     이걸 안 정하면 무슨 일이 생기나
💡 추천     추천안. 「추천」이라고 밝히고, 한 번만 말한다
📤 남는 것   _설정/ 에 사용자의 말로 남는 파일
```

**한 번에 한 질문.** 선택지가 있으면 AskUserQuestion, 추천을 첫 번째에. 자료를 받는 질문은 열린 질문으로 받는다.

**리포트 폴더는 공개 저장소 밖이다.** 고객 답이 들어간다. 맨 처음에 사용자가 정하게 하고, 공개 저장소 안 경로를 주면 한 번 더 묻는다.

---

## 준비 1 · 약속을 확인한다

| | |
|---|---|
| 📥 넣는 것 | **랜딩 · 결과 화면 · 확인 메일**에서 리포트에 대해 쓴 문장. 주소·캡처·복사한 글 무엇이든. 코드 저장소가 있으면 스킬이 직접 찾아 읽고 맞는지만 묻는다 |
| 🔔 환기 | 고객은 **약속한 것**을 기다린다. 「지금 위치와 해볼 것 하나」를 약속했는데 긴 분석이 오면, 잘 써도 약속과 다른 것이 온 것이다. 「언제까지」를 약속했다면 그 기한이 쓰는 방식을 정한다 |
| 💡 추천 | 찾은 약속 문장을 표로 보여 주고, **리포트 틀(준비 3)을 약속에 맞추기**. 약속을 고칠지는 사용자가 정한다 |
| 📤 남는 것 | `_설정/리포트틀.md` 맨 위 「고객에게 약속한 것」 |

## 준비 2 · 진단지를 확인한다

| | |
|---|---|
| 📥 넣는 것 | **진단지 원문** — 문항 · 보기 글자 · (있으면) 보기 코드 · 자유서술 문항 · 결과 화면에서 이미 보여준 것(유형 이름·요약). 폼 주소 · 캡처 · 문항 파일 무엇이든 |
| 🔔 환기 | 리포트는 **고객이 실제로 본 글자**로 써야 「내 답을 읽었다」가 된다. 코드(`opt_3`)나 AI 가 바꿔 말한 표현으로 쓰면 고객은 자기 답인지 못 알아본다. 자유서술 문항이 없으면 가장 강한 신호가 빠진다 |
| 💡 추천 | 자유서술이 없으면 **다음 판에 한 칸 더하기**를 한 번 권한다. 억지로 만들지 않는다 |
| 📤 남는 것 | `_설정/진단지.md` |

```markdown
# 진단지 · [진단 이름] · 확인한 날 YYYY-MM-DD

| 번호 | 문항 원문 | 보기 코드 → 화면 글자 | 자유서술 |
|---|---|---|---|
| [q1] | [문항 원문] | [코드] → [보기 글자] · … | |
| [q8] | [문항 원문] | — | ✔ |

## 결과 화면에서 이미 보여준 것
- [유형 이름 · 요약 등]
```

진단지를 고치면 **이 파일도 같이 고치고 확인한 날을 바꾼다.**

## 준비 3 · 리포트 틀을 정한다

| | |
|---|---|
| 📥 넣는 것 | **성공 기준 한 문장** (「받은 고객이 무엇을 하면 성공인가」) · 칸 구성 · 칸마다 조건 · **핵심 칸**(쌍둥이끼리 달라야 하는 칸) · 쓰지 않을 것 · 분량. 이미 보낸 결과지나 상담 후 보내던 글이 있으면 그것도 — 사용자의 원래 모양이 추천보다 낫다 |
| 🔔 환기 | 안 정하면 AI 기본 결과지(요약→강점→약점→추천)가 나온다. 누구에게나 같은 모양이다 |
| 💡 추천 | `frame.md` 의 성공 기준 · 다섯 칸 · 칸마다 조건 · 쓰지 않을 것. **질문과 함께만** 보여 준다 |
| 📤 남는 것 | `_설정/리포트틀.md` — 약속 · 성공 기준 · 칸 · 조건 · 핵심 칸 · 쓰지 않을 것 · 분량 · 채택한 검사 |

## 준비 4 · 문항에 역할과 기준을 잇는다

| | |
|---|---|
| 📥 넣는 것 | ① 문항마다 역할 (추천 초안을 보고 틀린 칸만 고친다) ② **보기마다 「이 보기를 고른 고객에게 리포트에서 무엇을」 한 줄** ③ 핵심을 고르는 순서 ④ 자유서술과 보기가 어긋나면 어느 쪽을 따를지. 재료로 쓸 **서비스 소개 · 상담 기록 · 자주 받는 질문**이 있으면 같이 |
| 🔔 환기 | ②가 리포트의 판단이고, 서비스의 전문성이 들어가는 유일한 자리다. **AI 가 채우면 이 스킬을 쓸 이유가 없어진다** |
| 💡 추천 | 역할 배정 초안 · 고르는 순서(바라는 끝 → 막힌 곳 → 현재 수준) · 어긋날 때는 자유서술. ②는 추천하지 않는다 — 막히면 **그 보기 글자와 사용자 자료에서만** 선택지 두세 개 |
| 📤 남는 것 | `_설정/역할표.md` |

`roles.md` 「보기마다 기준을 받는 법」 대로 한 보기씩 묻는다. 보기가 많으면 **바라는 끝 · 막힌 곳** 두 역할부터 받고, 나머지는 첫 리포트를 쓰면서 채운다.

## 준비 5 · 가두리망을 정한다

| | |
|---|---|
| 📥 넣는 것 | 모든 리포트가 닫힐 **한 곳의 이름과 링크** · 그 자리에 **지금 글이 쌓여 있는지** · 들어온 고객이 무엇을 남기면 좋은지 · 사용자가 거기서 무엇을 해 줄지(예: 직접 답을 단다) |
| 🔔 환기 | 리포트가 관계를 만들어도 **이어질 자리가 없으면 거기서 끝난다.** 두 곳이면 아무 데도 안 간다. 빈 방인데 「다른 분들 것도 보입니다」라고 쓰면 리포트 전체가 의심받는다 |
| 💡 추천 | 한 곳 · 리포트의 한 걸음을 해본 결과를 **한 줄 남기게** · 사용자가 **직접 답을 단다**고 약속 · 파는 말 없이 |
| 📤 남는 것 | `_설정/가두리망.md` — 이름 · 링크 · 닫는 문장(사용자 말투로) · 지금 글이 쌓였나 |

## 준비 6 · 목소리 재료를 받는다

| | |
|---|---|
| 📥 넣는 것 | **사용자가 직접 쓴 글 두세 편**(블로그·뉴스레터·상담 후 보낸 메시지) · **AI 초안에서 매번 고치는 말** · **고객을 부르지 말아야 할 말**(라벨·호칭) |
| 🔔 환기 | 목소리 재료가 없으면 리포트가 AI 말투로 나가고, 「직접 썼다」는 약속이 문장에서 깨진다 |
| 💡 추천 | 없으면 **비워 두고 시작한다.** 짐작으로 채우지 않는다. 첫 리포트를 고치면서 쌓인다. `voice.md` 의 추천 검사 중 채택할 것을 고른다 |
| 📤 남는 것 | `_설정/목소리0층.md` · `_설정/리포트틀.md` 「채택한 검사」 |

## 준비 7 · 한 통 써 보고 고친다

| | |
|---|---|
| 📥 넣는 것 | **실제 고객 한 명의 답** (자유서술이 가장 긴 사람 추천) · 초안을 읽고 **고친 곳** |
| 🔔 환기 | 표만 채우고 끝내면 표가 맞는지 모른다. 이 한 통이 준비의 마지막 단계다 |
| 💡 추천 | `SKILL.md` 쓰기 단계로 한 통 → 사용자가 고친 곳을 받아 설정으로 돌려보낸다 |
| 📤 남는 것 | 고친 말 → `목소리0층.md` · 판단 → `역할표.md` · 모양 → `리포트틀.md` |

## 끝낼 때

```
_설정/
  진단지.md  리포트틀.md  역할표.md  가두리망.md  목소리0층.md
```
