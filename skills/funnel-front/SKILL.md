# 앞단 콘텐츠

신청 페이지는 만들어 놨는데 아무도 안 들어오는 상태를 푸는 스킬이다.

여기서 만드는 것은 **설득하는 글이 아니라 한 번의 클릭과 한 번의 스캔을 얻어내는 글**이다.
앞단 콘텐츠가 할 일은 사람을 납득시키는 게 아니다. 설득은 신청 페이지가 한다.
앞단에서 전부 설명해 버리면 사람은 "알겠다"하고 지나간다. 남겨야 눌린다.

**최종 산출물** — 후킹 문구 세트 · 채널별 원고 · 오프라인 카피와 배치안 · 배포 계획 · 인쇄용 HTML 시안(진짜 QR 포함).

---

## 이 스킬의 전제: 채널이 아니라 자세가 다르다

같은 문구를 여러 채널에 돌려 쓰면 전부 죽는다. 채널이 달라서가 아니라, **사람이 그걸 마주치는 자세가 다르기 때문**이다.

| 채널 | 마주치는 자세 | 그래서 문구가 |
|---|---|---|
| 스레드 | 누워서 스크롤. 관심 0에서 시작 | 첫 줄이 전부다. 링크는 맨 뒤에 |
| 오프라인 출력물 | 걸어가며 3초. 손엔 이미 폰이 있다 | 스캔할 이유 한 줄 + 큰 QR |
| 커뮤니티 공지 | 이미 나를 조금 안다. 대신 방장이 본다 | 홍보 냄새가 나면 끝. 진짜 정보여야 한다 |

문구를 쓰기 전에 이 표를 다시 본다. 채널별 세부는 `references/` 안에 있다.

## 작업 순서

### 1단계 · 재료를 모은다

**있는 것부터 읽는다. 사용자가 이미 말한 걸 다시 묻는 게 가장 큰 실례다.**

재료가 서로 어긋나는 일이 자주 생긴다. 그래서 순위를 정해 둔다.

| 순위 | 재료 | 무엇을 가져오나 |
|---|---|---|
| **1** | **사용자가 이 대화에서 직접 말한 것** | 전부 |
| **2** | **실제 신청 페이지·랜딩** (주소 또는 HTML 파일) | 오퍼·마감·수량·가격 |
| 3 | GTM 코어·과제 문서 (`GTM코어*.md` 등) | 읽는 사람이 누구인지, 어떤 말투인지 |
| 4 | `../_context/prompt-clinic.md` | 「내 프롬프트 진단소」일 때의 기본값 |

**충돌하면 위 순위가 이긴다.** 특히 날짜·수량은 **실제 페이지에 적힌 값이 항상 맞다.** 문서에 적힌 예정일은 이미 지난 계획일 때가 많다.
**3번과 4번은 다른 사업이면 아예 안 읽는다.** 작업 폴더에 남의 사업 문서가 굴러다니는 일은 흔하고, 그걸 읽으면 엉뚱한 사업의 코어로 글을 쓰게 된다. 사용자가 말한 사업과 문서 속 사업이 같은지 먼저 확인한다.

읽고 나서 **아래 세 가지를 채운다.** 대부분은 읽어서 채워진다.

| # | 채울 것 | 없거나 이상하면 |
|---|---|---|
| 1 | 어디로 보내나 — 신청 페이지 주소 | **이것만은 물어보고 멈춘다.** QR을 못 만들면 이 스킬은 아무것도 못 한다 |
| 2 | 거기서 사람이 뭘 얻나 — 한 줄 | 읽은 것에서 추정해 쓰고, 추정했다고 표시한다 |
| 3 | 지금 마감·수량 상태 | 아래 규칙대로 |

**1번이 없을 때만 멈춘다.** 나머지는 묻지 않는다. 추정해서 채우고 2단계에서 공개한다.

**주소가 아직 안 열릴 때**(404, 미공개 폼, 준비 중) — 정상적인 상태다. 아직 안 연 신청 폼은 원래 안 열린다.
QR은 그 주소로 그대로 만든다. 다만 **인쇄 전 체크리스트 맨 위에 "이 링크는 아직 안 열립니다. 공개한 뒤 스캔해 보세요"를 굵게 넣는다.** 안 만들어 주는 게 아니라, 사고 날 지점을 표시해 주는 것이다.

**마감이 이미 지났거나 앞뒤가 안 맞을 때** — 지어내지 않되 그냥 넘어가지도 않는다.
가장 그럴듯한 값으로 진행하고, 그 자리에 **`(← 확인 필요: 말씀하신 8월 31일은 이미 지났습니다. 9월 30일로 잡았습니다)`**처럼 눈에 띄게 적는다.
날짜 하나 때문에 전체를 멈추는 게 더 손해다. 표시해 두면 사용자가 1초에 고친다.

**사업명이 없을 때** — 파일 이름과 명함에 필요하다. 묻지 말고 가칭을 지어 쓰고, 문서 맨 위에 `(가칭)`을 붙인다.

### 2단계 · 이해한 것을 먼저 보여준다

**이건 질문이 아니라 공개된 가정이다.** 확인을 받으려고 멈추는 자리가 아니라, 틀렸을 때 사용자가 바로 잡을 수 있게 펼쳐 보이는 자리다.

> 이렇게 이해했습니다.
> - 보내는 곳: (주소)
> - 사람이 얻는 것: (한 줄)
> - 마감·수량: (상태 / 또는 "아직 없음")
> - 읽는 사람: (누구)
> - 주력 채널: (어디)
>
> 이대로 뽑았습니다. 틀린 게 있으면 번호로 말씀해 주세요.

보여준 뒤 **곧바로 3단계로 간다.** 확인받느라 턴을 쓰지 않는다.

### 3단계 · 한 번에 다 뽑는다

`앞단콘텐츠_(사업명)_(YYYY-MM-DD).md` 파일 하나로 낸다.
**저장 위치는 사용자의 현재 작업 폴더다.** 사용자가 다른 폴더를 말했으면 거기. 임시 폴더에 두지 않는다. 인쇄용 HTML도 같은 폴더에 나란히 둔다.

```
# (사업명) 앞단 콘텐츠

## 0. 재료
## 1. 후킹 문구 세트        ← 앵글 5개. 아래 전부의 원재료
## 2~4. 채널별 원고         ← 아래 규칙대로 고르고 순서를 정한다
## 5. 인쇄 전 체크리스트     ← 오프라인이 있을 때만
## 6. 지금 바로 하실 일
```

**채널 섹션은 사용자 상황에 맞춰 고른다.** 번호 체계와 0·1·6번은 고정이고, 가운데 채널 블록만 움직인다.

- **주력 채널을 2번에 놓는다.** 오프라인으로 돌리려는 사람에게 스레드 원고가 2번이면 정작 필요한 게 뒤에 묻힌다.
- **안 쓰는 채널은 넣지 않는다.** 스레드 계정이 없는 사람에게 스레드 원고를 주면 그 페이지는 그냥 버려진다. 대신 한 줄로 남긴다: *"스레드는 계정이 생기면 그때 뽑아드릴게요."*
- 최종 순서대로 번호를 다시 매긴다. **번호를 붙이는 이유는 사용자가 "3-2 다시"라고 말할 수 있게 하려는 것이다.** 번호가 없으면 통째로 다시 쓰게 된다.

각 채널 블록을 쓰는 법은 아래 참고 문서에 있다. **해당 블록을 쓰기 직전에 읽는다.** 미리 다 읽으면 머리만 무거워진다.

| 쓸 때 | 읽는다 |
|---|---|
| 후킹 문구 세트 | `references/hooks.md` |
| 스레드 원고 | `references/threads.md` |
| 커뮤니티 공지문 (단톡·오픈채팅·카페·맘카페) | `references/community.md` |
| 오프라인 카피·배치안·체크리스트 | `references/print.md` |
| 배포 계획 (어디에 어떻게 뿌리나) | `references/distribute.md` |

**오프라인이 범위에 있으면 배포 계획을 반드시 붙인다.** 전단 500장을 어디에 어떻게 돌리는지가 문구보다 결과를 더 크게 가른다.

### 4단계 · 인쇄용 HTML 시안을 만든다

오프라인 출력물이 범위에 있으면 카피만 주고 끝내지 않는다. 카피만 주면 사용자는 캔바를 열어야 하고, 거기서 대부분 멈춘다.

`assets/`의 템플릿을 **산출물과 같은 폴더로 복사한 뒤 내용을 채운다.** 원본은 건드리지 않는다. 다음에 쓸 사람이 있다.

| 만들 것 | 템플릿 | 결과 파일 |
|---|---|---|
| A4 전단 | `assets/flyer-a4.html` | `전단_A4.html` |
| X배너 (600×1800mm) | `assets/banner-x.html` | `배너_X.html` |
| 명함 (90×50mm) | `assets/namecard.html` | `명함.html` |

**맨 위 `CONFIG` 블록의 값만 바꾼다.** 아래 HTML 구조는 새로 짜지 않는다.

CONFIG에서 주의할 두 가지가 있다. 이건 사용자에게도 한 줄로 알려준다.

- `headline`과 `bhead`만 `<br>`, `<em>` 같은 태그가 먹는다. **`em`으로 감싼 부분에 강조색이 칠해진다.**
- `sub`, `qrLine`, `bullets`는 태그가 글자 그대로 인쇄된다. `<br>`을 쓰면 화면에 `<br>`이 보인다.

**만든 뒤에는 반드시 브라우저로 열어 눈으로 확인한다.** 특히 QR 자리가 비어 있지 않은지 본다.
로컬 파일이 정적으로만 열려서 확인이 안 되면, 그 폴더에서 `python -m http.server 8899`를 띄우고 `http://127.0.0.1:8899/전단_A4.html`로 연다. 확인이 끝나면 서버를 끈다.
**확인을 못 했으면 못 했다고 말한다.** 확인한 척하는 게 제일 나쁘다.

다 만들면 사용자에게 이 한 줄만 알려준다: **"브라우저로 열고 Ctrl+P → 대상을 'PDF로 저장'. 인쇄 설정에서 '배경 그래픽' 체크를 켜세요."**

### 5단계 · 「지금 바로 하실 일」로 닫는다

문서 맨 끝에 **사용자 손이 필요한 것만** 모은다. 여기까지 읽고 뭘 해야 할지 모르면 문서 전체가 안 쓰인다.

- 3~6개. 체크박스로.
- 각 줄은 **동사로 시작**하고, 어디서 하는지까지 쓴다.
- 되돌릴 수 없는 것(인쇄, 배포)을 맨 아래에 둔다. 순서가 곧 안내다.

```
## 6. 지금 바로 하실 일

- [ ] 신청 폼을 공개하고, 열리는지 한 번 눌러본다
- [ ] `전단_A4.html`을 열어 QR을 폰으로 찍어본다 (아이폰·안드로이드 각 1회)
- [ ] 2-A와 2-B 중 하나를 고른다
- [ ] 아파트 관리사무소에 게시 허가를 물어본다
- [ ] 전단 5장만 먼저 뽑아 실물로 본다 → 괜찮으면 그때 대량 인쇄
```

### 6단계 · 넘길 것은 넘긴다

이 스킬은 인스타 캐러셀을 만들지 않는다. 억지로 만들면 기존 스킬보다 못한 결과가 나온다.

- 캐러셀·카드뉴스를 원하면 → "인스타 캐러셀은 `spongeclub3-carousel` 스킬이 훨씬 깊게 다룹니다. 여기서 뽑은 후킹 문구를 가지고 그 스킬을 부르면 이어집니다."
- 스레드 글 한 편을 제대로 다듬고 싶어 하면 → `threads-writing`으로 안내한다. 이 스킬의 스레드 원고는 "유입용 한 편"까지다.

## 지키는 것

**없는 것은 쓰지 않는다.** 신청자 수, 후기, 반응, 만족도. 아직 없으면 안 쓴다.
빈자리를 채우려고 "많은 분들이 신청해 주셨어요"를 쓰는 순간 그 문장 하나 때문에 전체가 광고가 된다.
**"아직 아무도 없습니다"가 오히려 더 세게 먹히는 문구다.** 먼저 들어오는 사람에게는 그게 기회니까.

**근거 없는 수치를 먼저 제안하지 않는다.** "효율 2배", "하루 30분씩 한 달이면 열 시간".
그럴듯하게 들리지만 사용자가 재본 적 없는 숫자다. 사용자가 실제 근거를 가진 경우에만 쓴다.
근거 없이 쓰고 싶어 하면 위험을 한 번 말하고, 그래도 원하면 진행한다. 말리는 게 아니라 알리는 것이다.

**커뮤니티는 규정을 먼저 짚는다.** 오픈채팅·카페·맘카페는 홍보 글 하나로 강퇴당한다.
다만 규정을 확인받느라 결과물을 미루지는 않는다. **`references/community.md`대로 허용 버전과 정보글 버전을 함께 내고**, 어느 쪽을 쓸지 한 줄로 묻는다.
계정이 날아가면 문구가 아무리 좋아도 소용이 없다.

**QR은 인쇄 전에 실제로 스캔해 본다.** 이건 되돌릴 수 없는 유일한 단계다.
글은 고치면 되지만 500장 인쇄한 전단의 QR이 안 되면 500장이 쓰레기가 된다. 체크리스트에 반드시 넣는다.

**개인정보를 무심코 싣지 않는다.** 전단·명함에 개인 휴대폰 번호나 집 주소를 넣으려 하면 한 번 짚는다.
온라인 글과 달리 종이는 회수가 안 된다. 그래도 넣겠다면 넣는다.

**타사 로고와 상표는 만들지 않는다.** 이미지 생성에도 넣지 않는다. 색감과 제품명 표기로 대체하고 왜 안 되는지 한 번 설명한다.

**번호로 고친다.** "4-2 배너 문구 다시"에 그것만 고친다. 전체를 다시 쓰지 않는다.

## 말투

산출물 안의 문장은 **소리 내어 읽어보고 어색하면 다시 쓴다.** 특히 오프라인 출력물은 사람이 서서 눈으로 읽는다.

| 쓰지 않는 말 | 대신 |
|---|---|
| 지금 바로 신청하세요 | (무엇을 얻는지 쓴다. 명령은 QR 옆 한 줄로 충분하다) |
| 놓치지 마세요 | 마감 날짜를 그냥 쓴다 |
| 소구점 · 리드 · 퍼널 | (내부용. 사용자에게 안 보인다) |
| 여러분 | 당신 / 또는 아예 생략 |

사용자가 쓰는 말은 그대로 받아 쓴다. 사용자가 "가두리망"이라 하면 가두리망이라 쓴다. 용어를 교정하지 않는다.
