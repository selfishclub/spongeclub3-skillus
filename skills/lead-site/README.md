# lead-site

**한 줄:** 모집 랜딩 · 신청 폼 · 신청자 어드민을 한 세트로 만들어 Vercel 배포까지 끝내는 스킬

## 어떤 스킬인가요?

행사·모집·강의 신청을 받는 사이트를 한 세트로 만들어 Vercel에 올려줍니다. 모집 랜딩 페이지, 신청 폼, 신청자를 관리하는 어드민까지 세 덩어리가 한 번에 나옵니다. 신청 데이터는 Supabase에 쌓이고, 운영자는 어드민에서 명단을 보고 상태를 바꿉니다.

구글폼으로는 브랜딩이 안 되고, 노션 폼으로는 어드민이 없어서 아쉬웠던 자리를 메우는 스킬입니다.

## 어떤 걸 해주나요?

- 주제·대상·받을 항목·수집 주체를 한 번에 물어보고 바로 제작합니다. 중간에 다시 묻지 않습니다
- 디자인 프리셋 4종 중에 고르게 합니다
- Next.js + Supabase 코드를 통째로 생성합니다 (랜딩 / 신청 폼 / 완료 / 어드민 / 어드민 로그인 / 서버 API / 미들웨어)
- 이름·전화번호·이메일·개인정보동의 4개는 고정, 나머지 질문은 jsonb 한 칸에 넣습니다. 질문이 바뀌어도 테이블을 안 고쳐도 됩니다
- 개인정보 수집·이용 동의 문구를 실제 받는 항목·수집 주체·보유 기간으로 채워서 써줍니다. 필수 동의와 선택(마케팅) 동의를 분리합니다
- Supabase 계정 만들기부터 환경변수 등록까지, 클릭할 버튼 이름 단위로 안내합니다
- 배포 후 확인 3종을 시킵니다 — 테스트 신청 넣어보기 / 어드민에 뜨는지 보기 / 로그아웃 상태에서 /admin 막히는지 보기

## 이럴 때 쓰세요

모집 기획은 끝났는데 "그래서 신청은 어떻게 받지"에서 막혔을 때. 신청자 명단을 남의 서비스가 아니라 내 DB에 쌓고 싶을 때. 행사가 끝나도 다음 모집에 그대로 재사용하고 싶을 때.

## 이건 안 해요

- 이미 배포된 사이트의 문구만 고치기
- 이미 쌓인 신청 데이터 분석·정산

## 짚고 넘어갈 것

남의 개인정보를 받는 사이트라서 보안 규칙을 세게 잡아뒀습니다. 신청 저장은 반드시 서버 라우트를 거치고, service_role 키는 절대 브라우저로 나가지 않으며, 어드민은 URL을 숨기는 게 아니라 실제로 잠급니다. 토큰·비밀번호는 대신 입력해주지 않고 절차만 안내합니다.

날짜·인원·장소·참가비처럼 안 알려준 정보는 지어내지 않고 `{{모집 인원}}` 형태로 비워둡니다.
