# lead-source

**한 줄:** 링크를 배포한 뒤에 누가 어디서 왔는지 확인하고, 어디서 끊겼는지 짚어주는 스킬

## 어떤 스킬인가요
랜딩을 만들어놓고 막상 링크를 공유하려니까, 나중에 신청자가 어디서 왔는지를 어떻게 구분하지? 싶어서 만들었습니다.

## 뭘 해주나
"링크 배포할 건데 유입 추적 붙여줘. 채널은 카톡, 링크드인, 스레드." 하면 채널별 링크를 만들어주고, 클릭이랑 신청 수를 링크마다 따로 집계합니다.

어디서 끊겼는지는 이렇게 나눠서 봐요. 링크 단위로 세야 채널끼리 안 섞입니다.

 - 클릭이 아예 없으면 → 채널이나 문구부터
 - 클릭은 있는데 신청이 없으면 → 랜딩 첫 화면부터
 - 폼까지 왔는데 제출을 안 하면 → 폼에서 막히는 부분

원인을 바로 짚는다기보다, 어디부터 확인할지 좁히는 용도입니다.

직접 붙여보다 발견한 것들도 규칙으로 넣어놨어요. 제일 중요한 건 클릭 수에 봇이 섞인다는 겁니다. 카톡이나 링크드인에 링크를 올리면 미리보기 카드를 만들려고 서버가 먼저 열어봐요. 아무도 안 눌렀는데 클릭이 올라갑니다.

직접 만든 사이트면 사람인지 기계인지 보고 거를 수 있는데, 단축링크 서비스는 그게 안 됩니다.

그 밖에 카카오에서 짧은 링크 미리보기가 안 뜨는 것, 옛날 탭에서 신청을 끝내면 유입이 "직접 방문"으로 뜨는 것, 테스트 데이터를 지우면 지난주 숫자까지 날아가는 것도 겪은 대로 적어놨어요.

코드 안 쓰시는 분들용 방법(단축링크 서비스 + 구글폼)도 따로 있습니다.

"UTM 만들어줘", "이 사람 어디서 왔지", "클릭은 있는데 신청이 없어", "카톡에 미리보기가 안 떠" 같은 말로 시작하셔도 됩니다.

## 더 하고 싶은 말
노슈니님이 유닛 자료에 적어주신 08번 "유입 경로 추적 스킬"입니다.

제 랜딩에 실제로 붙여서 배포하고, 카톡으로 첫 발송까지 해본 다음에 정리했습니다.

봇 클릭 건은 첫 발송 30분 전에 겨우 발견했어요. 그때 모르고 넘어갔으면 이번 주 클릭 수를 그대로 믿고 볼 뻔했습니다.

아직 확인 못 한 것도 있어요. 저는 짧은 링크를 직접 만들어서 썼는데, Bitly 같은 서비스를 쓰면 카카오 미리보기가 어떻게 되는지는 안 해봤습니다.

SKILL.md만 받지 마시고 references/ 폴더도 꼭 같이 받으세요. 본문엔 "무엇을 왜"까지만 있고, 어떻게 붙이는지는 참고 파일에 나눠 뒀습니다.
