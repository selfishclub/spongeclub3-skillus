# mkt-plan

**"우리 제품 좋아요"가 아니라 고객이 실제로 한 말에서 출발해 마케팅 결과물을 만드는 Claude 스킬.**

광고 카피, 랜딩·상세페이지, SNS 게시물, 뉴스레터, 브랜드 콘셉트, A/B 테스트 카피를 다룬다.

---

## 왜 만들었나

대부분의 카피 도구는 제품 설명을 넣으면 그럴듯한 문장을 뱉는다. 문제는 그 문장이 **아무 근거 없이 만들어진다**는 것이다. "고객이 왜 안 사는가"를 AI가 혼자 상상해서 채우면 결론은 늘 비슷한 곳으로 간다. 신뢰가 없어서, 가격이 비싸서, 잘 몰라서.

mkt-plan은 그 자리를 **사용자가 실제로 들은 말**로 채운다. 문의 로그 한 줄, DM 한 마디, 반응 없던 게시물 하나면 충분하다. 거기서 진짜 이유를 뽑고, 카피와 페이지 구조를 역산한다.

들은 말이 하나도 없으면 기획서를 쓰지 않는다. 대신 임시안과 함께 **일주일 안에 무엇을 누구에게 물어볼지**를 준다.

## 누가 쓰면 좋은가

고객이 뭐라고 하는지는 아는데, 그걸 어떻게 카피로 바꿔야 할지 모르는 사람.

- 혼자 파는 사람 — 반응을 직접 듣지만 그게 기획 재료인 줄 모르는 경우
- 마케팅을 배우는 사람 — 제품 설명은 쓰지만 전부 자기 자랑이 되는 경우
- 팀·에이전시 — 자료는 많은데 어디까지가 근거고 어디부터가 상상인지 섞여 있는 경우

**안 맞는 경우:** 아직 뭘 팔지 안 정했다면 이 스킬 이전 단계가 필요하다. 인터뷰 도중에 그게 드러나면 스킬이 스스로 멈추고 알려준다.

## 무엇을 받는가

질문 3턴이면 끝난다. 결과물은 마크다운 파일 한 장이고, 네 덩어리로 되어 있다.

| 섹션 | 내용 |
|---|---|
| 바로 쓰는 것 | 붙여넣을 수 있는 완성 카피. 프레임워크 용어 0개 |
| 왜 이렇게 썼나 | 고객이 한 말 원문 → 진짜 이유 → 방향. 추측 구간은 `⚠︎ 확인 필요`로 표시 |
| 버린 안 | 검토했다 접은 방향 2개와 접은 이유. 1안이 실패하면 여기서 갈아탄다 |
| 판정 기준 | 볼 지표 / 기간·표본 / 접는 기준. 근거 없는 예측 수치는 쓰지 않는다 |

실제 산출물은 [`examples/`](./examples) 참고.

## 설치

```bash
git clone https://github.com/SallyjisunPark/mkt-plan.git
cp -r mkt-plan ~/.claude/skills/
```

Claude Code·Cowork는 `~/.claude/skills/` 또는 프로젝트의 `.claude/skills/` 아래에 폴더째 두면 된다.
Claude.ai에서는 `SKILL.md`를 업로드해 스킬로 저장한다.

## 쓰는 법

그냥 말하면 된다. 스킬 이름을 부를 필요는 없다.

```
상세페이지 카피 좀 써줘. 반려견 수제간식 파는데
장바구니까지는 오는데 결제를 안 해
이 카피 왜 안 먹히는지 모르겠어
```

그러면 세 가지를 묻는다.

1. 무엇을 파는지, 누가 사는지 (첫 메시지에 있으면 건너뜀)
2. **고객이 실제로 뭐라고 하던가요** — 안 산 사람의 말 / 최근에 산 사람의 이유 / 반응 없던 것, 아는 것 하나만
3. 진짜 이유 확인 + 오늘 뭘 만들지 + 지금 가진 증거

2번이 전부다. 여기에 실제 문장 하나를 넣느냐 아니냐로 결과물의 질이 갈린다.

## 구조

```
mkt-plan/
├── SKILL.md                  질문 흐름, 아웃풋 규칙, 지킬 것
├── references/
│   ├── framework.md          사고 뼈대 10단계 (내부용)
│   └── playbook.md           콘텐츠 유형별 산출물 형식 + 표준 출력 형식
└── examples/                 실제 산출물 샘플
```

`references/`는 Claude가 기획서를 쓸 때만 읽는다. 사용자에게 프레임워크를 설명하지 않는 것이 이 스킬의 원칙이다.

## 다른 스킬과의 관계

`sponge-gtm-core`, `sponge-first-conversion`, `threads-writing`이 함께 설치돼 있으면 경계에서 그쪽으로 넘긴다. 팔 아이템이 아직 없으면 GTM 코어부터, 리드를 모으는 전환 페이지면 그쪽으로, 스레드 본문이면 그쪽으로.

**셋 다 없어도 mkt-plan은 그대로 작동한다.** 넘길 곳이 없으면 직접 처리한다.

## 설계 원칙

- **Real Why는 사용자가 준 말에 닿아 있어야 한다.** 이 스킬의 가장 중요한 규칙.
- **없는 숫자를 만들지 않는다.** 증거가 없으면 "무엇을 어떻게 구하라"를 대신 적는다.
- **만들 것은 사용자가 고른다.** 목표에서 유형을 역산해 랜딩페이지를 내밀지 않는다.
- **질문은 최대 3턴.** 답을 못 쓰게 만드는 질문은 좋은 질문이 아니다.
- **무게중심은 완성물에.** 사용자는 기획론을 읽으러 온 게 아니다.

사고 뼈대는 박신영 《기획의 정석》의 구조를 마케팅 콘텐츠에 맞게 옮긴 것이다.
