# 산출물 표준 양식 (output-formats.md)

산출물을 만들기 전 이 파일에서 해당 양식을 따른다. 양식은 출발점이며, 프로젝트에 맞게 조정한다.

## 기능정의서 / 서비스기획서 (마크다운 또는 워드)

```
# [서비스명] 서비스기획서 · 기능정의 (MVP / 문서 vX.X)
0. 핵심 위계 (과금·구조의 최상위 개념을 표로)
1. 서비스 개요 (한 줄 정의 / 차별점 / "왜 돈을 내는가")
2. 타겟 사용자 (페르소나 — 공급/수요 양면이면 둘 다)
3. 서비스 구조 (핵심 객체 표 + 관계)
4. 기능 정의 (액터별 표: 기능ID·영역·기능·우선순위·관련화면)
5. 화면 목록 & 흐름 (시나리오별)
6. 핵심 유저스토리 (Given/When/Then)
7. 상태 정의 (객체별 상태 흐름)
8. 비기능 요건 (접근성·다국어·결제·보안·법무 선행)
9. MVP 범위 (포함 / 제외)
10. KPI & 성공 지표 (북극성 지표 1개 + 검증 가설)
11. 남은 결정 (Open Questions — 추천 기본값 + [결정 필요])
```
- 기능은 "사용자가 ~할 수 있다" 형식. 우선순위 [M]/[L] 표기.
- 과금 단위가 바뀌면 문서 전체가 흔들리므로, 위계(0번)를 항상 맨 위에 둔다.

## IA(정보구조) 구조도

- 루트(서비스) → 사용자 유형별 영역(예: 게스트/호스트/어드민) → 영역별 화면.
- 하단에 *공통 시스템*(번역·결제·인증·알림 등)을 가로 띠로.
- *MVP 제외* 항목을 점선 박스로 별도 표기.
- 영역별 색 구분으로 스캔하기 쉽게.

### 화면목록 표 (엑셀/문서 공통)
| 화면ID | 영역 | 화면명 | 설명 | 상위/진입 | 우선순위 |

## 와이어프레임 규칙 (저해상도)

- 브라우저/앱 프레임 안에 *회색 박스=UI 요소, 점선 박스=이미지·미정*.
- 주요 화면은 사용자 유형별 핵심 동선을 포함(탐색 → 전환 → 핵심 경험 → 재방문 등).
- *기획 메모*는 별색 이탤릭으로 각 화면 옆/아래에 — "왜 이렇게 설계했는가"가 보이게.
- 시각 디자인(색·폰트·여백)은 입히지 않는다. 그건 목업 단계.
- 가장 먼저 그릴 화면: 전환(결제/구독) 화면 + 핵심 경험 화면.

## 엑셀 정리 워크북 (xlsx 스킬과 함께)

시트 구성:
1. **개요** — 핵심 위계, 범례(우선순위·영역색), 확정 결정 요약, MVP 제외, 주의사항.
2. **화면목록(IA)** — 화면ID·영역·화면명·설명·상위·우선순위.
3. **기능정의** — 기능ID·영역·기능·우선순위·비고·관련화면.
4. **데이터정의** — 객체·속성·타입·필수·설명.
5. **상태정의** — 객체·상태 흐름·설명.

서식: 전문 폰트(Arial), 헤더 진한 배경+흰 글씨, 고정행·자동필터, 영역별 셀 배경색, [L] 항목은 회색 이탤릭. 수식이 있으면 반드시 recalc로 오류 0 확인.

## 단계별 의사결정 비교 (투자/내부 검토용)

여러 방향(A/B/C)을 검토했다면 *나란히 비교*하는 표 한 장을 둔다: 각 안의 *파는 것 / 강점 / 약점 / 전략적 역할*. 채택안을 표시하고, 결론(어느 것을 입구로, 어느 것을 확장으로)을 한 줄로. 투자자용에는 단일 추천 로드맵만, 내부용에는 비교 흔적을 부록으로 — 외부엔 확신, 내부엔 비교.
