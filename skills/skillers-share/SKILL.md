# 공유회-OS

스폰지클럽 스킬러스 유닛의 **1시간 공유회**를 주제 선정부터 발표 스크립트까지 만든다.

> ⚠️ **환경을 먼저 확인하고, 되는 만큼 이어간다 (막지 않는다).**
>
> 시작할 때 로컬 접근 가능 여부를 본다 — `~/.claude/projects` 가 읽히나, bash·python 이 도나.
>
> **A. Claude Code (터미널, 로컬 접근 O) — 전체 기능**
> 대화 기록 자동 스캔 → 질문 → 제목 → 목차 → 덱 → 대본 → `deploy.sh` 로 인터넷 링크까지. 아래 흐름 그대로.
>
> **B. claude.ai 웹·데스크톱 앱 (로컬 접근 X) — 제한 모드로 이어간다**
> 로컬 파일·셸이 없어 **① 대화 기록 자동 스캔**과 **② GitHub Pages 자동 배포**는 물리적으로 안 된다. 여기서 멈추지 말고 이렇게 대체한다:
> 1. **①(스캔) 건너뛴다.** "여기선 예전 대화 기록 스캔이 안 돼서, 발표 주제를 직접 여쭤볼게요" 라고 먼저 말하고 Q1을 `직접 쓸게요` 경로로 연다. 소재 후보를 지어내지 않는다.
> 2. 질문·제목·목차·덱·대본 흐름은 **그대로** 간다.
> 3. **완성 덱은 인터넷 링크 대신 자체완결 HTML 파일로 만들어 내려받게** 준다(환경이 지원하면 Artifact로 띄운다). 표지 시안용 headless-chrome 캡처가 안 되면 표지는 덱 안에서 직접 렌더한다.
> 4. 덱 빌드 스크립트(bash/python)조차 못 도는 환경이면, 최소한 **목차 + 발표 대본 + `brief.json` 을 텍스트로** 완성해 건네고 그 사실을 말한다.
>
> **부르는 스킬**(훅카피·크리틱디렉터·spec-guard)은 터미널에선 형제 스킬로 호출한다. claude.ai 업로드 패키지에선 이 폴더의 `bundled/` 안에 함께 들어있으니(`bundled/hookcopy`=훅카피, `bundled/critic-director`=크리틱디렉터, `bundled/spec-guard`), 별도 스킬 호출이 안 되면 그 폴더의 **`INSTRUCTIONS.md`** 를 직접 읽어 규칙을 적용한다. (claude.ai는 zip에 SKILL.md가 1개만 허용돼서, 번들 스킬의 진입 파일은 `INSTRUCTIONS.md` 로 담긴다.)
>
> **못 하는 걸 되는 척하지 않는다.** 스캔·자동배포가 빠지는 환경이면 그 사실을 먼저 밝히고, 할 수 있는 최대치로 끝까지 간다.

## 이 스킬이 푸는 것

공유회 차례가 오면 두 군데서 막힌다.

- **주제** — "내가 발표할 게 있나". 소재가 없는 게 아니라 자기 것을 별거 아니라고 본다
- **PPT** — 구성·디자인 정하느라 시간을 다 써서 정작 발표 연습을 못 한다

이 둘만 푼다. 나머지는 따라온다.

**전제** — 공유회는 셸(4~12셸)을 내고 들어오는 유료 상품이고, VOD는 입장가의 2배로 재판매된다. 제목은 표지 문구가 아니라 **모객 문구**이고, 덱은 남는 자산이다.

## 흐름

```
① 스캔        대화 기록 → 소재 후보            interview.md
② 질문 3개    소재 · 대상 · 디자인             interview.md
③ 락 걸기     발표 SPEC-LOCK                  spec-guard 호출
④ 내용 듣기   유형 뼈대의 칸을 발표자가 채움     types.md
⑤ 제목        내용 → 후보 5개 → 고르기          titles.md + 훅카피 호출
⑥ 목차        받은 내용 → 슬라이드 목차          timeline.md
⑦ 덱 생성     brief.json → 웹덱 HTML          themes.md + engine/
⑧ 스크립트    슬라이드 대본 · 데모 · Q&A       script.md + 훅카피 호출
⑨ 검수        락 대조 → 후킹 크리틱            spec-guard · 크리틱디렉터 호출
```

**각 단계 끝에서 확인을 받고 다음으로 간다.** 한 번에 다 뱉지 않는다.

**꼭 필요한 확인은 6번이다** — 질문 3개 · 내용 듣기 · 제목 · 목차. 이 여섯은 건너뛰지 않는다.

**다만 6번으로 끝난다고 약속하지 않는다.** 덱을 보고 고치는 과정에서 확인이 더 생기는 게 정상이다. 문서에 적힌 숫자와 실제가 다르면 나머지 설명도 신뢰를 잃는다. 대신 **"필수 6번 + 수정하면서 몇 번 더"** 라고 처음에 말해둔다.

**모든 선택은 `AskUserQuestion` 으로 받는다.** 제목 고르기·목차 확인·검수 강도·재작업 여부까지 전부. 본문에 "1번 2번 3번 중 고르세요"라고 적고 사용자가 타이핑하게 만들지 않는다. 하위 스킬을 호출해 받은 후보도 이 스킬이 다시 `AskUserQuestion` 으로 차려서 고르게 한다.

**선택지에는 반드시 미리보기를 붙인다.** `AskUserQuestion` 의 `preview` 필드에 그 선택지를 고르면 나올 실제 결과를 넣는다 — 제목 후보면 표지에 얹힌 모습, 목차 수정이면 바뀐 목차, 덱 수정이면 해당 슬라이드 내용. **보여주지 않고 "고칠까요?"라고 묻지 않는다.** 뭐가 있는지 모르는데 뭘 고칠지 답할 수 없다.

**선택지 문구는 쉬운 말로 쓴다.** 하위 스킬 이름(`크리틱디렉터`·`spec-guard`)을 그대로 노출하지 않는다. "검수해드릴까요", "약속한 기준과 대조할까요" 처럼 무슨 일이 일어나는지로 쓴다. 사용자는 그 스킬이 뭔지 모를 수 있다.

## 함께 쓰는 스킬

이 번들에 **동봉되어 있고 `install.sh` 가 같이 설치한다.** 따로 받을 필요가 없다.

| 스킬 | 쓰는 자리 |
|---|---|
| `훅카피` | ⑤ 제목 · 표지 문구 · ⑦ 전환 문장 |
| `크리틱디렉터` | ⑧ 후킹 검수 (`visual-inspection.md` 렌즈) |
| `spec-guard` | ③ 락 생성 · ⑧ 락 대조 |

`install.sh` 는 설치할 때마다 원본(`github.com/Koo-bon/webdeck`, `github.com/Koo-bon/spec-guard`)에서 **최신을 받아온다.** 네트워크가 없으면 `bundled/` 동봉본으로 떨어진다. 이미 설치된 스킬은 건드리지 않으며, 교체하려면 `bash install.sh --force` 를 쓴다.

webdeck 덱 엔진(`generate_deck.py`·`index.html`)은 동봉하지 않는다. `install.sh` 가 원본에서 받아오므로 항상 최신이고 수정 위험이 없다.

## ① 스캔

`references/interview.md` 의 스캔 규칙을 따른다. `~/.claude/projects/` 최근 6주치에서 소재 후보를 뽑고 **각 후보에 근거 한 줄**을 붙인다. 근거 없는 후보는 넣지 않는다.

기록이 빈약하면 그 사실을 먼저 말한다. **없는 걸 지어내지 않는다.**

## ② 질문 3개

`references/interview.md` 의 Q1·Q2·Q3를 그 순서로 `AskUserQuestion` 으로 묻는다.

- 문항 문구는 고정, 보기만 스캔 결과로 채운다
- **모든 문항에 `모르겠어요` 또는 `알아서`가 있어야 한다**
- Q1은 세 문항을 한 화면에 묶는다. 하나만 답해도 넘어간다

## ③ 락 걸기

`spec-guard` 를 호출해 `.claude/SPEC-LOCK.md` 를 만든다. **⑧에서 대조하려면 기준이 먼저 있어야 한다.**

합격 기준은 **지금 O/X로 판단 가능한 것만** 쓴다.

- 총 슬라이드 25~35장인가
- 데모 구간이 12분 이상인가 (데모 있는 경우)
- 데모 백업(스크린샷·녹화본)이 준비됐는가
- Q&A에 "저는 안 되던데요" 답이 있는가
- 표지에 여백·흰 박스가 없는가
- 오프닝이 자기소개가 아니라 문제로 시작하는가
- 따라하기 슬라이드가 있는가

"완성도 높게", "임팩트 있게" 같은 건 기준이 아니다.

## ④ 내용 듣기

**목차를 짜기 전에 발표자가 무슨 이야기를 갖고 있는지 듣는다.** 이 단계를 건너뛰면 목차부터 AI의 상상이 되고, 그 아래 내용은 전부 지어내게 된다.

### 범용 5문항으로 묻는다

**유형별로 다른 질문을 만들지 않는다.** 유형은 6종이고 발표자의 직종도 제각각이다. 주제가 스킬일 수도, AI와 무관한 본업일 수도 있다. 질문이 주제를 전제하는 순간 답을 못 받는다.

모든 발표는 이야기다. **이야기 구조 5칸이 곧 범용 질문**이다.

| # | 뼈대 | 왜 |
|---|---|---|
| 1 | **[소재] 만들기 전엔 뭐가 불편했나요?** | 도입(0–5분). 청중이 "내 얘기네" 하는 지점 |
| 2 | **[소재] 하면서 제일 막혔던 건?** | 본론 전반. 발표에서 가장 잘 들리는 부분 |
| 3 | **그래서 어떻게 했나요?** | 본론 후반. 청중이 가져갈 방법 |
| 4 | **[소재] 쓰고 나서 뭐가 달라졌나요?** | 결과. 숫자든 상태든 발표자 말로 |
| 5 | **아직 안 되는 건?** *(선택)* | 신뢰가 여기서 생긴다. 없으면 뺀다 |

1~4가 필수, 5는 선택이다. **하나만 답해도 진행한다.**

**`[소재]` 자리에 ②에서 받은 소재를 반드시 끼워 넣는다.** 뼈대를 그대로 읽으면 "뭐 때문에 시작했나요?" 가 되는데, **뭘 시작했다는 건지가 빠져 있어 답을 못 한다.** 범용으로 만들려다 의미를 비우면 안 된다. 범용인 건 **뼈대**이지 문장이 아니다.

```
✗ 뭐 때문에 시작했나요?
✓ 상세페이지 자동화를 만들기 전엔, 뭐가 제일 불편했나요?
✓ 학원 상담 스크립트를 쓰기 전엔, 뭐가 제일 번거로웠나요?
```

받은 답을 `references/types.md` 의 유형별 뼈대에 매핑한다 — 매핑은 이 스킬이 하고, **발표자에게 뼈대 용어를 노출하지 않는다.**

### 질문 쓰는 법 — 여기서 제일 많이 틀린다

**직종을 전제하지 않는다.** "키비주얼은 어떻게 하셨나요"는 디자이너에게만 통한다. 이 스킬은 마케터·기획자·사업자·개발자가 다 쓴다. 단계 이름을 미리 정해놓고 묻지 말고, **발표자가 자기 말로 적게 한다.**

**쉬운 말로 묻는다.** "이어 붙일 때 무엇이 병목이었나요"가 아니라 **"제일 귀찮았던 게 뭐예요?"** 로 묻는다. ①·② 질문에 적용한 원칙을 여기서도 그대로 지킨다 — 어려운 질문은 답을 못 받고, 답이 없으면 결국 AI가 채우게 된다.

**내 답을 고르게 하지 않는다.** 선택지에 내가 지어낸 내용을 넣고 "맞나요?" 라고 물으면 그건 확인이지 듣기가 아니다. 선택지는 **스캔에서 근거와 함께 나온 것**이나 **답의 방향**(예: `시간이 줄었다` / `실수가 줄었다` / `아예 안 하던 걸 하게 됐다`)이어야 하고, **`직접 쓸게요` 를 항상 둔다.**

**필수 질문은 최소로.** 없으면 발표가 성립 안 되는 것만 필수다. 나머지는 **선택이라고 명시한다.** 답이 없으면 그 슬라이드를 뺀다. 필수가 아닌 걸 필수인 척 물으면 발표자가 지친다.

**각 질문에 "왜 묻는지" 한 줄을 붙인다.** 어디에 쓰일지 알면 답이 훨씬 잘 나온다.

### 그 밖의 요령
- 스캔에서 답할 수 있는 칸은 **미리 채워서 확인만 받는다.** 빈칸을 다 물으면 지친다
- 답이 짧아도 캐묻지 않는다. 짧은 답은 그 항목을 짧게 다루라는 신호다
- **모르겠다고 하면 그 항목은 목차에서 뺀다.** 억지로 채우지 않는다

받은 답이 곧 슬라이드 내용이 된다. **여기서 안 나온 이야기는 덱에 넣지 않는다.**

## ⑤ 제목

**내용을 들은 뒤에 제목을 뽑는다.** ④에서 나온 실제 이야기(제일 막혔던 것·달라진 것)를 재료로 써야 모객되는 제목이 나온다. 내용을 듣기 전에 지으면 상상으로 짓게 된다.

`references/titles.md` 의 브리프 형식으로 `훅카피` 를 호출해 후보 5개를 받는다 — ④의 핵심과 ②의 대상을 함께 물린다. **직접 짓지 않는다.**

제목이 정해지면 표지 문구를 위해 훅카피를 **한 번 더** 호출한다 — 8자 이내 한 덩어리.

## ⑥ 목차

**④에서 받은 내용을 슬라이드로 자른다.** 유형은 ④ 전에 이미 추론돼 있고, 여기서는 `references/timeline.md` 로 시간을 배분한다.

- **④에서 나온 이야기만 목차가 된다.** 받은 답이 얇은 항목은 슬라이드를 적게 준다
- 답이 없던 항목은 **목차에서 뺀다.** 채우려고 지어내지 않는다
- 25~35장이 안 나오면 억지로 늘리지 말고 **④로 돌아가 한 항목을 더 묻는다**
- `references/timeline.md` 의 "텍스트만 나오면 안 된다" 를 지킨다 — 3~4장마다 시각 요소, 필요한 이미지는 여기서 목록으로 요청한다

확인 화면에 아래를 한 번에 보여준다. **추론 항목에는 근거 한 줄을 붙이고, 각 슬라이드가 ④의 어느 답에서 나왔는지 알 수 있게 한다.**

```
제목      [고른 것]
유형      [6종 중 하나] — 이렇게 판단한 이유
대상      [Q2 답변]
가져갈 것 [추론 결과]
데모      있음/없음 — 이렇게 판단한 이유
시간 배분 [표]
목차      슬라이드 제목 25~35개
```

## ⑦ 덱 생성

**내용은 지어내지 않는다. 이 절의 첫 번째 규칙이다.**

발표자가 무대에서 말할 문장을 AI가 만들어내면, 겪지도 않은 일을 말하게 된다. 청중은 셸을 내고 들어왔고 질문한다. 지어낸 숫자와 사례는 그 자리에서 무너진다.

| 구분 | 출처 | 처리 |
|---|---|---|
| **구조** — 목차, 구간 배분, 슬라이드 타입 | 이 스킬이 제안 | 그대로 만든다 |
| **사실** — 숫자, 날짜, 횟수, 만든 것 목록 | 스캔에서 **근거와 함께** | 근거를 함께 표기 |
| **경험** — 겪은 일, 실패담, 판단 이유, 체감 시간 | **발표자만 안다** | 빈칸으로 두고 묻는다 |

빈칸은 이렇게 남긴다.

```json
{ "type":"core", "lines":[["여기 실제 겪으신 일",false]],
  "sub":"[채워주세요] 방향을 바꿔서 되돌아간 적이 있나요? 언제, 왜였나요?" }
```

덱을 만든 뒤 **빈칸 목록을 한 번에 보여주고 `AskUserQuestion` 으로 받는다.**

### 만드는 법 — 한 줄이면 끝난다

```bash
bash engine/build-deck.sh <brief.json> <출력폴더> <테마> [notes.json]
```

테마 값: `minimal-bw` `bold-color` `soft` `editorial` `dark-tech`

**발표가 특정 서비스·OS·제품을 다루면, 5종을 꺼내기 전에 그 서비스 톤(컬러)에 맞춘 디자인을 0번으로 먼저 추천한다.** `references/themes.md` 의 "0순위 — 발표 대상 서비스가 있으면 그 톤에 맞춘다" 를 따른다. 색은 로고·랜딩·화면에서 읽고, 모르면 지어내지 말고 링크·캡처를 요청한다. 발표자가 다른 걸 원하면 그때 Q3 5종으로.

**주제에 맞는 특수 슬라이드 타입을 1~3장 넣는다.** `references/themes.md` 의 "새 슬라이드 무기 — 주제별로" 표를 본다 — 자동화 발표면 `orchrun`·`harnessflow`, 제품 발표면 `producthero`, 전후 비교면 `feature`+`ba`/`flip`. 무난한 카드만 쓰면 PPT 티가 난다. (표지 시안 예시: `design-concepts/04-표지-볼드고딕-6종.html`)

**손으로 하지 않는다.** 예전엔 생성 → CSS/JS 복사 → `data-sd-theme` 주입 → `</body>` 앞 두 줄 삽입을 따로 했는데, 하나만 빠져도 **발표자 노트·타이머·테마 폰트가 통째로 안 붙은 덱**이 나간다. 스크립트가 주입까지 하고 검증한다.

스크립트가 잡아주는 것:
- `core`·`ending` 타입의 `lines` 누락 → **이게 있으면 덱 전체가 하얗게 죽는다.** 파일은 정상 생성되므로 열어보기 전엔 모른다
- 확장 주입 실패
- 슬라이드 수가 25~35장 범위 밖

### 만든 뒤 반드시 열어본다

```bash
cd <출력폴더> && python3 -m http.server 8080
```

**표지 글자가 보이는지, 하단 dots 수가 슬라이드 수와 맞는지** 확인한다. **확인하지 않고 링크를 건네지 않는다.**

### 표지

**표지는 내지와 다른 규칙으로 만든다.** `references/themes.md` 의 "표지" 절을 따른다 — 불변 셋(화면에 꽉 참 · 3초 안에 꽂힘 · 내지와 명백히 다름), 내지를 넘어서는 타이포 스케일, 레이아웃 패턴 6종(좌측 정렬 + 가운데 대형 포함) 중 컨셉에 맞는 것.

덱을 만들기 전에 `themes.md` 의 **"절대 금지 — PPT 티"** 표와 **"품질 기준"** 절을 읽는다. **무난하면 실패다.**

표지를 만든 뒤 **"표지 자체 점검" 6항목**을 스스로 확인한다. 하나라도 걸리면 다시 만든다.

**`generate_deck.py` 와 `index.html` 원본은 수정하지 않는다.**

## ⑧ 스크립트

`references/script.md` 형식으로 `<출력폴더>/script.md` 를 쓴다. **전체를 축어로 쓰지 않는다.**

작성한 노트를 `notes.json` 의 `notes` 에 슬라이드 번호로 채워 넣는다. 발표 중 `S` 키로 보인다.

## ⑨ 검수

**락 대조가 먼저다.** 유형이 흐려진 상태에서 크리틱을 받으면 잘못된 방향을 더 잘 다듬게 된다.

1. `spec-guard` — ③의 합격 기준을 항목별로 O/X 채점하고 근거를 SCORE-LOG에 남긴다. X는 고치고 재채점한다. 불변 원칙을 깨야 하면 **사용자 승인을 받는다**
2. `크리틱디렉터` — 표지·슬라이드는 `visual-inspection.md` 렌즈로, 흐름은 "발표 중 지루한 구간"을 찾는 관점으로

크리틱 강도는 사용자에게 묻는다. 발표를 앞두고 매운맛이 항상 도움되지는 않는다.

## 링크 블록 (모든 응답 끝에 고정 출력)

**위로 스크롤해서 찾게 만들지 않는다.** 단계마다 아래 블록을 응답 맨 끝에 붙인다.

```
──────────────────────────
📊 발표 덱   https://…
📝 스크립트  https://…
📁 로컬      ~/공유회/<날짜>-<제목>/
──────────────────────────
```

아직 생성되지 않은 항목은 `(아직 없음)` 으로 표시하되 **줄을 지우지 않는다.** 무엇이 남았는지 그대로 보인다.

**외부에서 열리려면 배포가 필요하다.** 로컬 HTML은 링크로 넘길 수 없다. **GitHub Pages** 로 배포한다 — 무료, 영구, URL이 깔끔하고, 발표 후 채널 공유와 VOD 자료로 그대로 쓴다.

```bash
bash engine/deploy.sh <출력폴더>
```

한 줄이면 저장소 생성·푸시·Pages 설정까지 끝나고 주소가 나온다. 저장소 이름은 폴더명에서 자동으로 만들되, 한글이 날아가 부실해지면 시각을 붙여 유일하게 만든다.

`gh` 가 없으면 스크립트가 **설치법과 손으로 올리는 법을 둘 다 안내하고 멈춘다.** 그때는 로컬 경로만 준다. **배포 안 된 링크를 있는 것처럼 적지 않는다.**

## 마지막에 챙길 것

- **따라하기 슬라이드** — 청중이 가져갈 것. 설치·셋업·주의사항. 1시간을 듣고 아무것도 못 따라 하면 발표가 소비되지 않는다
- **채널 공유용 링크** — 덱 URL을 채널에 올리면 못 온 사람도 본다. 공유회가 줌으로 끝나면 그날로 증발한다

## 하지 않는 것

- **발표 내용을 지어내기** — 숫자·사례·실패담은 발표자만 안다. 빈칸으로 두고 묻는다
- 없는 성과를 지어내기 — 기록에 없으면 없다고 말한다
- 추상적인 질문 — "주제가 뭐예요"를 묻지 않는다
- 전체 축어 스크립트 — 읽는 발표가 된다
- 표지 규칙 고정 — 컨셉마다 다시 정한다
- 실패를 숨기기 — 삽질기는 정식 유형이다
- webdeck 원본 파일 수정 — 확장은 `share-extend.*` 에만
