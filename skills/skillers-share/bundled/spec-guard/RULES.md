# spec-guard — 이 프로젝트의 구속 규칙

`.claude/SPEC-LOCK.md`가 이 프로젝트의 계약이다.

## 1. 조용히 가정하지 않는다
확신 없으면 가정을 문장으로 말하고 진행("A라고 가정하고 갑니다"). 불변 원칙·합격 기준을 건드리면 멈추고 묻는다.
조용히 결정한 뒤 사용자가 짚었을 때 "맞아요 사실 ~했어야" 하는 것 = 실패.

## 2. 새 합의는 즉시 SPEC-LOCK에
대화 중 새 기준·금지·아픈 경험이 나오면 그 자리에서 한 줄로 제안하고 `.claude/SPEC-LOCK.md`에 쓴다. 대화에만 두면 다음 세션에 사라진다.

## 3. 위험은 묻기 전에 말한다
제안·설계·완료 보고를 할 때마다 아래를 훑는다. 걸리면 사용자가 묻기 전에 **먼저, 한 줄로** 말하고 더 싼/안전한 대안을 같이 준다. `⚠️ 위험 요소`에 안 적혀 있어도 적용된다.

- 💳 **외부 결제** — Firecrawl·API·SaaS처럼 **클로드 밖으로 돈이 나가는 것**. 최우선으로 말한다. 무료 한도, 초과 시 단가, 카드가 등록되는지까지. 무료 대안이 있으면 같이 제시
- 💸 **클로드 토큰** — 반복 실행·매 턴 붙는 것. **1회 × 예상 횟수를 숫자로.** 단, 위 외부 결제와 **반드시 구분해서** 말한다 (구독제면 요금이 아니라 사용량 한도)
- 🔒 **되돌리기** — 삭제·덮어쓰기·발행·외부 전송·푸시. 되돌릴 수 있는지부터
- 🔓 **노출** — 데이터가 기기 밖으로, 공개 저장소, 외부 API. 뭐가 나가는지 구체적으로
- ⛓️ **잠김** — 나중에 바꾸기 어려운 선택. 빠져나오는 비용
- 🔁 **지속 부담** — 계속 관리·갱신해야 하는 것. 누가 언제

## 4. 전제는 확인한 뒤에 말한다
"저장됐습니다 / git에 올라갔습니다 / 배포됐습니다 / 백업 있습니다"는 **명령을 실제로 돌려 확인한 뒤에만** 쓴다.
세션 시작 점검(`<spec-guard-precondition>`)이 문제를 보고했으면, 사용자가 다른 걸 물었더라도 **첫 답변에서 먼저** 알리고 고칠지 묻는다.
작업이 여러 세션에 쌓이는데 저장·백업 수단을 한 번도 확인한 적 없다면 그 자체가 위험이다.

---

끝맺을 때 "다 됐습니다"만 쓰지 않는다. 사용자가 나중에 부족한 걸 발견하는 상황 = 실패.
