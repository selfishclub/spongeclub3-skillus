# 공유회-OS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 스폰지클럽 스킬러스 유닛원이 질문 3개에 답하면 1시간 공유회의 주제·제목·목차·웹덱·발표 스크립트가 나오는 스킬 번들을 만든다.

**Architecture:** `proposal-os` 형태의 오케스트레이션. `공유회-OS/SKILL.md`가 흐름을 지휘하고, 판단 기준은 전부 `references/*.md`에 둔다. 덱 생성은 webdeck 엔진(`generate_deck.py` + `index.html`)을 그대로 쓰고, 발표자 노트·구간 타이머만 `share-extend.css/js`로 얹는다. `훅카피`·`크리틱디렉터`·`spec-guard`는 복사하지 않고 호출한다.

**Tech Stack:** Markdown (스킬 정의) · Bash (install/verify) · Python 3 (webdeck `generate_deck.py`, 수정하지 않음) · Vanilla JS/CSS (엔진 확장)

## Global Constraints

- 대상 디렉터리: `/Users/jinny/project/skill/공유회-OS/`
- 문서 언어는 한국어. 스킬 이름·파일명도 설계 문서에 적힌 그대로 쓴다
- `훅카피`·`크리틱디렉터`·`spec-guard`를 번들에 복사하지 않는다 — webdeck 번들과 중복 설치 시 충돌한다
- webdeck 원본 파일(`index.html`, `generate_deck.py`, `brief_template.json`)은 **한 줄도 수정하지 않는다.** 확장은 `share-extend.css` / `share-extend.js` 에만 넣는다
- 표지 불변 규칙 2개: 화면에 꽉 참(여백 0, 레터박스 0, 흰 박스 0, 오버레이 패널 0) · 3초 안에 시선이 꽂힘. 배치·색·타이포 크기는 고정하지 않는다
- 모든 질문 문항에 `모르겠어요` 또는 `알아서` 보기가 있어야 한다
- 모든 단계 응답 끝에 링크 블록(발표 덱 / 스크립트 / 로컬)을 고정 출력한다. 미생성 항목은 `(아직 없음)`으로 표시하되 줄을 지우지 않는다
- 플레이스홀더 금지: `TBD`, `TODO`, `추후`, `...` 로 끝나는 미완성 문장

**참조 설계 문서:** `docs/superpowers/specs/2026-08-03-공유회-os-design.md`

**webdeck 실제 인터페이스** (구현 전 확인 완료):
- 입력: `brief.json` — `{ "title": str, "theme": {bg, accent, red, ink, dim}, "slides": [...] }`
- 실행: `python3 generate_deck.py brief.json 출력폴더`
- 출력: `출력폴더/index.html` + `deck.config.js` + `assets/`
- 슬라이드 타입: `cover` `core` `cards` `stat-trio` `feature` `grid` `ba` `flow` `orgchart` `loophell` `vonr` `video` `showcase` `harnessflow` `section` `ending`

**설계 대비 축소 (이유 있음):** 설계 §7의 확장 6개 중 엔진 코드가 필요한 건 **발표자 노트·구간 타이머 2개뿐**이다. 표지 풀블리드는 `cover`, 데모 전환은 `section`, 따라하기는 `flow`/`cards` 타입으로 이미 커버된다. 없는 기능을 새로 만들지 않는다.

```bash
#!/usr/bin/env bash
# 공유회-OS 번들 구조 검증. 실패하면 무엇이 왜 틀렸는지 출력하고 exit 1.
set -uo pipefail
cd "$(dirname "$0")"
fail=0

err() { echo "  ✗ $1"; fail=1; }
ok()  { echo "  ✓ $1"; }

echo "[1] 필수 파일"
for f in SKILL.md install.sh README.md \
         references/types.md references/titles.md references/interview.md \
         references/timeline.md references/script.md references/themes.md \
         engine/share-extend.css engine/share-extend.js; do
  [ -f "$f" ] && ok "$f" || err "$f 없음"
done

echo "[2] SKILL.md 프론트매터"
if [ -f SKILL.md ]; then
  head -1 SKILL.md | grep -q '^---$' || err "SKILL.md 1행이 --- 가 아님"
  grep -q '^name: 공유회-OS$' SKILL.md || err "SKILL.md에 'name: 공유회-OS' 없음"
  grep -q '^description: ' SKILL.md || err "SKILL.md에 description 없음"
fi

echo "[3] 플레이스홀더"
if grep -rnE '(TBD|TODO|추후 (작성|보완)|채워야)' --include='*.md' . ; then
  err "플레이스홀더 발견"
else
  ok "플레이스홀더 없음"
fi

echo "[4] 복사 금지 스킬"
for d in 훅카피 크리틱디렉터 spec-guard webdeck proposal-lite; do
  [ -d "$d" ] && err "$d 는 복사하지 않고 호출해야 함" || ok "$d 미복사"
done

echo "[5] webdeck 원본 무수정"
if [ -f engine/generate_deck.py ]; then
  curl -fsSL https://raw.githubusercontent.com/Koo-bon/webdeck/main/webdeck/generate_deck.py \
    -o /tmp/gd_upstream.py 2>/dev/null
  if [ -s /tmp/gd_upstream.py ]; then
    diff -q /tmp/gd_upstream.py engine/generate_deck.py >/dev/null \
      && ok "generate_deck.py 원본과 동일" \
      || err "generate_deck.py 가 원본과 다름 — 확장은 share-extend.* 에만"
  else
    ok "generate_deck.py (원본 대조 건너뜀 — 네트워크 없음)"
  fi
fi

echo "[6] 모든 질문에 탈출구"
if [ -f references/interview.md ]; then
  q=$(grep -c '^### Q' references/interview.md)
  e=$(grep -cE '모르겠어요|알아서' references/interview.md)
  [ "$e" -ge "$q" ] && ok "질문 $q개 / 탈출구 $e개" \
    || err "질문 $q개인데 탈출구가 $e개뿐"
fi

echo
[ "$fail" -eq 0 ] && echo "PASS" || echo "FAIL"
exit $fail
```

````markdown
- **대상을 좁게 잡을수록 잘 팔린다.** "사업자"보다 "매출은 아는데 영업이익은 모르는 사업자"
- **자기 비하·친근 톤이 통한다.** "핑프가", "AI 초보가"
- **숫자가 들어가면 구체성이 생긴다.** "팔로워 100명", "AI 직원 8명", "네 가지 포인트"
- 이름을 앞에 다는 형식(`코코의`, `다니 -`)은 이미 알려진 사람에게 유리하다. 처음 여는 사람은 대상·결과를 앞세우는 편이 낫다
````

````markdown
### Q1 — 소재 (세 문항, 한 화면)

문항 문구는 고정. 보기만 스캔 결과로 채운다.

**1. 최근에 누가 "그거 어떻게 했어요?"라고 물어본 적 있나요?**
남이 물어본 것은 수요가 이미 검증된 주제다. 가장 확실한 신호.

**2. 요즘 설명할 때 유독 신나는 게 있나요?**
1시간을 버티게 하는 건 완성도가 아니라 화력이다.

**3. 최근 한 달, 시간을 제일 많이 쓴 일은?**
시간을 쓴 곳에 노하우가 쌓인다. 본인만 그걸 별거 아니라고 본다.

각 문항 보기:

```
① [스캔 결과 1 — 근거 한 줄]
② [스캔 결과 2 — 근거 한 줄]
③ 클로드 밖의 일이에요 (직접 입력)
④ 모르겠어요 — 내 대화 기록 보고 골라주세요
```

③이 필요한 이유 — 실제 공유회 중 `팔로워 100명만 되도 팬은 만들어집니다`, `파티룸 창업 무물보`, `메타 광고 쌩기초` 같은 본업 주제는 대화 기록에 잡히지 않는다.

**하나만 답해도 넘어간다.** 여럿이면 겹치는 지점을 잡는다 — 남이 물어봤고 + 내가 신나고 + 시간을 많이 쓴 것이 겹치면 그게 최적 주제다.

**전부 `모르겠어요`면** 그때만 스캔 결과에서 대화량·완결성 기준으로 3개를 골라 제안한다. 여기까지 와서 빈손인 사람은 없어야 한다. 스캔 결과도 비어 있으면 솔직히 말하고, 최근 작업을 두세 문장으로 적어달라고 요청한다.
````

````markdown
공유회는 1시간이다. **혼자 1시간은 슬라이드만으로 못 버틴다** — 발표자도 청중도.

## 데모가 있을 때 (기본)

| 시간 | 구간 | 슬라이드 |
|---|---|---|
| 0–5 | 도입 — 내가 뭐에 막혔나 | 3~4장 |

## 데모가 없을 때

| 시간 | 구간 | 슬라이드 |

| 30–45 | 본론 후반 | 8~10장 |

구간 경계: `0 / 5 / 20 / 30 / 45 / 60`

**20–30분 환기 구간을 반드시 넣는다.** 슬라이드만 45분 연속은 중반에 무너진다. 청중에게 질문을 던지거나 짧게 같이 따라 해보게 한다.

## 유형별 본론 배분

| 유형 | 본론 전반 | 본론 후반 |
|---|---|---|

| 툴 사용법 전수 | 결과물 · 기본 사용법 | 내가 찾은 요령 · 한계 |
| 입문 기초 | 개념 3개 | 눈으로 확인 · 흔한 오해 |
| 삽질기 | 목표 · 1차 실패 | 2·3차 시도 · 풀린 지점 |
| 본업 전문성 | 사람들이 틀리는 것 | 내 방식 · 사례 |
| 작업 흐름 전체 | 원래 흐름 · 대체 지점 | 이어 붙일 때 문제 · 완성 흐름 |

1시간이면 소재 하나로는 얇을 수 있다. **엮을 때는 유형을 하나로 통일한다.** 소재는 여럿이어도 유형이 흔들리면 발표가 산만해진다.
````

```javascript
(function () {
  var SLIDE_SEL = '.slide';
  var state = { segments: [], notes: {}, t0: null, timerOn: false, notesOn: false };

  function el(id, tag) {
    var n = document.getElementById(id);
    if (!n) { n = document.createElement(tag); n.id = id; document.body.appendChild(n); }
    return n;
  }

  function currentIndex() {
    var slides = document.querySelectorAll(SLIDE_SEL);
    for (var i = 0; i < slides.length; i++) {
      var r = slides[i].getBoundingClientRect();
      if (r.top <= window.innerHeight * 0.5 && r.bottom > window.innerHeight * 0.5) return i;
    }
    return 0;
  }

  function segmentAt(min) {
    var name = '', next = null;
    for (var i = 0; i < state.segments.length; i++) {
      if (state.segments[i][0] <= min) { name = state.segments[i][1]; next = state.segments[i + 1]; }
    }
    return { name: name, next: next };
  }

  function tick() {
    var box = el('sd-timer', 'div');
    if (!state.timerOn) { box.classList.remove('on'); return; }
    box.classList.add('on');
    var sec = state.t0 ? Math.floor((Date.now() - state.t0) / 1000) : 0;
    var min = Math.floor(sec / 60);
    var s = String(sec % 60).padStart(2, '0');
    var seg = segmentAt(min);
    var left = seg.next ? (seg.next[0] - min) + '분 남음' : '';
    box.innerHTML = min + ':' + s + '  <span class="seg">' + seg.name + (left ? ' · ' + left : '') + '</span>';
    box.classList.toggle('over', min >= 60);
  }

  function renderNotes() {
    var box = el('sd-notes', 'div');
    if (!state.notesOn) { box.classList.remove('on'); return; }
    box.classList.add('on');
    var i = currentIndex();
    var text = state.notes[String(i + 1)] || '(이 슬라이드의 노트가 없습니다)';
    box.innerHTML = '';
    var h = document.createElement('h4');
    h.textContent = 'SLIDE ' + (i + 1) + ' — 발표자 노트  ·  S 닫기';
    var p = document.createElement('pre');
    p.textContent = text;
    box.appendChild(h); box.appendChild(p);
  }

  document.addEventListener('keydown', function (e) {
    if (e.target && /^(INPUT|TEXTAREA)$/.test(e.target.tagName)) return;
    var k = e.key.toLowerCase();
    if (k === 's') { state.notesOn = !state.notesOn; renderNotes(); }
    if (k === 't') {
      state.timerOn = !state.timerOn;
      if (state.timerOn && !state.t0) state.t0 = Date.now();
      tick();
    }
    if (k === 'r' && e.shiftKey) { state.t0 = Date.now(); tick(); }
  });

  window.addEventListener('scroll', function () { if (state.notesOn) renderNotes(); }, { passive: true });

  fetch('notes.json')
    .then(function (r) { return r.ok ? r.json() : null; })
    .then(function (d) {
      if (!d) return;
      state.segments = d.segments || [];
      state.notes = d.notes || {};
    })
    .catch(function () {});

  setInterval(tick, 1000);
})();
```

````markdown
# 공유회-OS

스폰지클럽 스킬러스 유닛의 **1시간 공유회**를 주제 선정부터 발표 스크립트까지 만든다.

## 이 스킬이 푸는 것

공유회 차례가 오면 두 군데서 막힌다.

- **주제** — "내가 발표할 게 있나". 소재가 없는 게 아니라 자기 것을 별거 아니라고 본다
- **PPT** — 구성·디자인 정하느라 시간을 다 써서 정작 발표 연습을 못 한다

이 둘만 푼다. 나머지는 따라온다.

**전제** — 공유회는 셸(4~12셸)을 내고 들어오는 유료 상품이고, VOD는 입장가의 2배로 재판매된다. 제목은 표지 문구가 아니라 **모객 문구**이고, 덱은 남는 자산이다.

## 흐름

```
① 스캔        대화 기록 → 소재 후보            interview.md
② 질문 3개    소재 · 대상 · 디자인             interview.md
③ 락 걸기     발표 SPEC-LOCK                  spec-guard 호출
④ 제목        후보 5개 → 고르기                titles.md + 훅카피 호출
⑤ 목차        유형 · 시간 배분 · 슬라이드 목차   types.md + timeline.md
⑥ 덱 생성     brief.json → 웹덱 HTML          themes.md + engine/
⑦ 스크립트    슬라이드 대본 · 데모 · Q&A       script.md + 훅카피 호출
⑧ 검수        락 대조 → 후킹 크리틱            spec-guard · 크리틱디렉터 호출
```

**각 단계 끝에서 확인을 받고 다음으로 간다.** 한 번에 다 뱉지 않는다.

**사용자 개입은 5회로 고정한다** — 질문 3개 · 제목 고르기 · 목차 확인. 이보다 늘리지 않는다.

| `훅카피` | `github.com/Koo-bon/webdeck` | ④ 제목 · 표지 문구 · ⑦ 전환 문장 |

## ① 스캔

`references/interview.md` 의 스캔 규칙을 따른다. `~/.claude/projects/` 최근 6주치에서 소재 후보를 뽑고 **각 후보에 근거 한 줄**을 붙인다. 근거 없는 후보는 넣지 않는다.

기록이 빈약하면 그 사실을 먼저 말한다. **없는 걸 지어내지 않는다.**

## ② 질문 3개

`references/interview.md` 의 Q1·Q2·Q3를 그 순서로 `AskUserQuestion` 으로 묻는다.

- 문항 문구는 고정, 보기만 스캔 결과로 채운다
- **모든 문항에 `모르겠어요` 또는 `알아서`가 있어야 한다**
- Q1은 세 문항을 한 화면에 묶는다. 하나만 답해도 넘어간다

## ③ 락 걸기

`spec-guard` 를 호출해 `.claude/SPEC-LOCK.md` 를 만든다. **⑧에서 대조하려면 기준이 먼저 있어야 한다.**

합격 기준은 **지금 O/X로 판단 가능한 것만** 쓴다.

- 총 슬라이드 25~35장인가
- 데모 구간이 12분 이상인가 (데모 있는 경우)
- 데모 백업(스크린샷·녹화본)이 준비됐는가
- Q&A에 "저는 안 되던데요" 답이 있는가
- 표지에 여백·흰 박스가 없는가
- 오프닝이 자기소개가 아니라 문제로 시작하는가
- 따라하기 슬라이드가 있는가

"완성도 높게", "임팩트 있게" 같은 건 기준이 아니다.

## ④ 제목

`references/titles.md` 의 브리프 형식으로 `훅카피` 를 호출해 후보 5개를 받는다. **직접 짓지 않는다.**

제목이 정해지면 표지 문구를 위해 훅카피를 **한 번 더** 호출한다 — 8자 이내 한 덩어리.

## ⑤ 목차

`references/types.md` 로 유형을 추론하고, `references/timeline.md` 로 시간을 배분한다.

확인 화면에 아래를 한 번에 보여준다. **추론 항목에는 근거 한 줄을 붙인다.**

```
제목      [고른 것]
유형      [6종 중 하나] — 이렇게 판단한 이유
대상      [Q2 답변]
가져갈 것 [추론 결과]
데모      있음/없음 — 이렇게 판단한 이유
시간 배분 [표]
목차      슬라이드 제목 25~35개
```

## ⑥ 덱 생성

1. `references/themes.md` 에서 `theme` 객체를 가져온다 (Q3 답변 또는 자동 매칭 또는 커스텀 추출)
2. `engine/brief_template.json` 을 복제해 `brief.json` 을 만든다. 슬라이드 타입은 `engine/references/slide-types.md` 참조
3. 실행: `python3 engine/generate_deck.py brief.json <출력폴더>`
4. `engine/share-extend.css` · `share-extend.js` 를 출력폴더에 복사하고, 출력폴더 `index.html` 의 `</body>` 앞에 두 줄을 넣는다

```html
<link rel="stylesheet" href="share-extend.css">
<script src="share-extend.js"></script>
```

5. `notes.json` 을 출력폴더에 쓴다

```json
{
  "segments": [[0,"도입"],[5,"본론 전반"],[20,"본론 후반"],[35,"데모"],[50,"Q&A"]],
  "notes": { "1": "오프닝 축어…", "2": "요지 불릿…" }
}
```

`segments` 값은 `references/timeline.md` 의 데모 유무별 구간 경계를 그대로 쓴다.

**표지 규칙 — 불변은 둘뿐이다.** 화면에 꽉 참(여백 0, 레터박스 0, 흰 박스 0, 오버레이 패널 0) · 3초 안에 시선이 꽂힘. 배치·색·타이포 크기는 테마와 컨셉이 정한다. 대각 배치 같은 특정 구도를 지침으로 박지 않는다.

**`generate_deck.py` 와 `index.html` 원본은 수정하지 않는다.**

## ⑦ 스크립트

`references/script.md` 형식으로 `<출력폴더>/script.md` 를 쓴다. **전체를 축어로 쓰지 않는다.**

작성한 노트를 `notes.json` 의 `notes` 에 슬라이드 번호로 채워 넣는다. 발표 중 `S` 키로 보인다.

## ⑧ 검수

**락 대조가 먼저다.** 유형이 흐려진 상태에서 크리틱을 받으면 잘못된 방향을 더 잘 다듬게 된다.

1. `spec-guard` — ③의 합격 기준을 항목별로 O/X 채점하고 근거를 SCORE-LOG에 남긴다. X는 고치고 재채점한다. 불변 원칙을 깨야 하면 **사용자 승인을 받는다**
2. `크리틱디렉터` — 표지·슬라이드는 `visual-inspection.md` 렌즈로, 흐름은 "발표 중 지루한 구간"을 찾는 관점으로

크리틱 강도는 사용자에게 묻는다. 발표를 앞두고 매운맛이 항상 도움되지는 않는다.

## 링크 블록 (모든 응답 끝에 고정 출력)

**위로 스크롤해서 찾게 만들지 않는다.** 단계마다 아래 블록을 응답 맨 끝에 붙인다.

```
──────────────────────────
📊 발표 덱   https://…
📝 스크립트  https://…
📁 로컬      ~/공유회/<날짜>-<제목>/
──────────────────────────
```

아직 생성되지 않은 항목은 `(아직 없음)` 으로 표시하되 **줄을 지우지 않는다.** 무엇이 남았는지 그대로 보인다.

**외부에서 열리려면 배포가 필요하다.** 로컬 HTML은 링크로 넘길 수 없다. **GitHub Pages** 로 배포한다 — 무료, 영구, URL이 깔끔하고, 발표 후 채널 공유와 VOD 자료로 그대로 쓴다.

```bash
cd <출력폴더>
git init && git add -A && git commit -m "deck"
gh repo create <저장소명> --public --source=. --push
gh api repos/:owner/<저장소명>/pages -f "source[branch]=main" -f "source[path]=/"
```

`gh` 가 없으면 로컬 경로만 주고 배포 방법을 안내한다. **배포 안 된 링크를 있는 것처럼 적지 않는다.**
````
