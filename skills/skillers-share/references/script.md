# 발표 스크립트 형식

## 훅카피를 박는 자리 4곳

전체에 바르면 1시간 내내 광고 문구가 되어 피곤하다. 네 곳만 쓴다.

| 자리 | 왜 |
|---|---|
| 오프닝 첫 문장 | 여기서 못 잡으면 1시간 내내 못 잡는다 |
| 구간 전환 (5·20·35·50분 또는 5·20·30·45분) | 늘어지는 지점을 한 줄로 끌어올린다 |
| 데모 진입 직전 | "이제 보여드릴게요"가 제일 지루한 문장이다 |
| 클로징 | 마지막에 남는 한 줄 |

구간 경계는 `timeline.md` 의 데모 유무별 표를 따른다.

## 산출

`<출력폴더>/script.md` 한 파일. 슬라이드 번호와 구간 시간이 함께 적혀 있어야 발표자 노트(`S` 키)에서 대조할 수 있다.

**전체를 축어로 쓰지 않는다.** 읽는 티가 나면 1시간이 더 길게 느껴진다. 구간마다 필요한 밀도가 다르다.

| 구간 | 밀도 | 이유 |
|---|---|---|
| 오프닝 | 축어 | 제일 떨린다. 그대로 읽을 수 있어야 한다 |
| 본문 | 요지 + 전환 문장 | 축어로 쓰면 읽게 되고, 읽으면 들킨다 |
| 데모 | 순서 체크리스트 | 손이 움직이는 구간이라 대본이 방해된다 |
| Q&A | 답변 요지 | 질문이 예상대로 안 온다 |
| 클로징 | 축어 | 마지막 인상이 여기서 결정된다 |

---

## 오프닝 (축어)

30초~1분. 세 문장이면 충분하다.

```
[훅카피가 뽑은 첫 문장]

제가 ___를 하는데 ___에서 계속 막혔습니다.
오늘은 그걸 어떻게 넘겼는지, 그리고 아직 못 넘긴 게 뭔지 말씀드리겠습니다.
```

**자기소개를 길게 하지 않는다.** 같은 유닛이라 이미 안다. 바로 문제로 들어간다.

**"별거 아닌데요"로 시작하지 않는다.** 겸손이 아니라 청중에게 기대를 낮추라는 신호가 되어, 남은 59분이 통째로 깎인다.

---

## 본문 (요지 + 전환)

슬라이드마다 이렇게 적는다.

```
── 슬라이드 7 · 2분
요지:
  - 원본 스킬은 영어 카피 기준으로 만들어져 있었다
  - 한국어에 넣으니 라임이 다 깨졌다
  - 예시 하나 보여주기 (스크린샷)
전환: "그래서 뜯어봤습니다"
```

- 요지는 **불릿 2~4개**. 문장으로 쓰면 읽게 된다
- 전환 문장은 **한 줄**. 다음 슬라이드로 넘어가는 다리
- 예상 소요를 적어둔다. 리허설할 때 어디서 초과하는지 바로 보인다

**구간이 바뀌는 자리의 전환 문장은 `훅카피`로 뽑는다.** 늘어지는 지점이라 한 줄로 끌어올려야 한다. 경계는 데모가 있으면 5·20·35·50분, 없으면 5·20·30·45분 — `timeline.md` 를 따른다.

## 데모 (체크리스트 + 백업)

대본이 아니라 순서다. 손이 움직이는 중에 대본을 읽을 수 없다.

```
── 데모 · 15분

사전 준비 (발표 전날)
  □ 터미널 폰트 크기 키우기
  □ 알림 끄기
  □ 예제 파일 미리 열어두기
  □ 결과물 스크린샷 백업 준비   ← 필수
  □ 화면 녹화본 준비            ← 필수

순서
  1. (2분) 빈 상태에서 시작 — 원래 이걸 손으로 하면 얼마나 걸리는지 말하기
  2. (3분) 스킬 호출, 결과 대기 ← 대기 시간에 할 말 준비
  3. (5분) 결과 보여주고 설명
  4. (5분) 한 군데 바꿔서 다시 실행

망했을 때
  대사: "역시 라이브는 이렇네요. 준비해둔 결과물 보시죠"
  → 백업 스크린샷으로 전환, 녹화본 재생
  → 3분 안에 정리하고 다음 구간으로. 붙잡고 고치지 않는다
```

**"망했을 때" 칸을 반드시 채운다.** 라이브 데모는 높은 확률로 한 번 막히고, 준비된 사람은 웃고 넘어가지만 준비 안 된 사람은 10분을 날린다.

**대기 시간에 할 말을 미리 정한다.** AI 응답을 기다리는 30초의 침묵이 발표에서 제일 어색한 구간이다.

## Q&A (예상 질문 + 답)

5개를 준비한다. **아래 두 개는 반드시 포함한다.**

**"저는 그거 안 되던데요"**
셋업 차이(MCP 연결 여부, API 키, OS)에서 온다. 공유회에서 가장 자주 나오는 질문이고, 답을 준비 안 하면 그 자리에서 디버깅이 시작되어 발표가 무너진다.
→ 답: 내 셋업을 먼저 밝히고, 흔한 원인 2~3개를 짚고, "끝나고 따로 봐드릴게요"로 닫는다.

**"이거 그냥 클로드한테 시키면 안 되나요"**
스킬화의 이유를 묻는 질문. 반복성·일관성·팀 공유 중 내 경우에 해당하는 걸 말한다.

나머지 3개는 각도별로:
- 삽질기 → "다른 방법은 안 해보셨어요?"
- 개조기 → "원본이랑 뭐가 제일 다른가요?"
- 절감기 → "그 숫자 어떻게 재셨어요?"
- 조합기 → "전부 다 세팅해야 하나요?"

**모르면 모른다고 한다.** 1시간을 들은 청중은 아는 척을 바로 알아본다.

## 클로징 (축어)

30초. 두 가지만 한다.

```
[훅카피가 뽑은 마지막 한 줄]

오늘 것 전부 [링크]에 올려두겠습니다.
[따라하기 한 장]대로 하시면 30분이면 됩니다. 막히면 채널에 물어보세요.
```

**요약을 다시 하지 않는다.** 1시간을 들은 사람에게 요약은 지루하다. 남길 한 줄과 가져갈 것만 준다.

---

## 리허설 체크

스크립트가 나오면 한 번은 소리 내어 읽어보게 한다.

- 구간별 예상 시간 대비 실제 — 대체로 초과한다
- 오프닝 첫 문장이 입에 붙는가 — 안 붙으면 훅카피를 다시 뽑는다
- 데모 대기 시간에 할 말이 정해져 있는가
- 슬라이드 없이도 말이 이어지는가 — 이어지면 슬라이드가 목발이 아니라는 뜻이다
