# 스마트스토어 수집 — 증거를 모은다

> **번들 스킬입니다.** `리포트_판정기준표.md`(88줄 채점 기준표)와
> `추출기.js`(브라우저에서 돌리는 추출 스크립트)가 이 폴더 안에 같이 들어 있어서,
> **이 폴더를 그대로 받으면 바로 돌아갑니다.** 원래 「셀러들의쇼핑몰」 프로젝트에서 쓰던 스킬을
> 독립적으로 쓸 수 있게 정리한 것입니다 — 기준표 88줄은 **일반 스마트스토어**(패션 카테고리 예시가
> 섞여 있음) 진단용으로 만들어졌습니다. 다른 업종·다른 기준으로 채점하고 싶다면
> `리포트_판정기준표.md` 를 자신의 기준으로 바꿔 쓰면 됩니다 — 추출기와 이 스킬의
> 순서는 그대로 씁니다.

스토어 주소 하나를 받아 **화면을 돌며 증거를 모아 파일로 남긴다.**

**최종 산출물** — `사례/<스토어 이름>/수집/` 안의 `메타.json` · `증거.json` · `shots/`

---

## 이 스킬이 절대 안 하는 것

**판정하지 않는다.** ⭕❌ 를 매기지 않는다. 「이건 잘못됐다」고 말하지 않는다.

증거와 판정을 갈라두는 이유가 있다 — **기준표는 계속 고쳐진다.** 기준표를 고칠 때마다
스토어를 다시 긁어야 한다면 느리고, 결과도 그때그때 달라지고, 남의 서버에 부담을 준다.
**수집 결과를 파일로 남기면 스토어를 안 건드리고 몇 번이든 다시 채점할 수 있다.**

수집이 판정까지 하면 기준표를 고칠 때 수집기도 같이 고쳐야 한다 — 나눈 의미가 없어진다.
증거를 뽑다가 눈에 띄는 게 있어도 **적지 말고 넘어간다.** 증거만 남기면 나중에 채점할 때 알아서 본다.

---

## 이 폴더 안의 파일

| | |
|---|---|
| **추출기** | `추출기.js` — 이 파일을 통째로 `browser_evaluate` 에 넣는다 |
| **기준표** (무엇을 뽑아야 하는지) | `리포트_판정기준표.md` — 88줄, 판정 표시(⭕❌⊘➖)와 뽑는 법(구조/캡처/사람)까지 정의돼 있다 |

**추출기는 부분 치환하지 말 것.** `\s` 이스케이프가 어긋나 조용히 실패한다. 고칠 땐 통째로 다시 쓴다.

---

## 도는 순서

> 스토어 하나를 이렇게 모읍니다.
>
> 1. 주소 확인 · 갈래 판별
> 2. 문 세기 — 어떤 화면이 있나
> 3. 화면마다 순회 (팝업 닫고 · 펼치고 · 구조 뽑고 · 전체 캡처)
> 4. 파일로 저장
> 5. 못 연 화면 보고
>
> 지금은 **1번**입니다.

### 1. 주소 확인 · 갈래 판별

```
brand.naver.com      → 브랜드스토어   (홈 컴포넌트 24종, 메뉴 16개 더)
smartstore.naver.com → 일반           ← 기준표 88줄의 기본 대상
```

**갈래를 먼저 말한다.** 기준표의 🅢 · ⚠ 표시가 갈래에 따라 달라진다.

브랜드스토어면 한 줄 알린다 — 「브랜드스토어라 일반 스토어와 항목이 정확히 겹치지 않습니다.」

### 2. 문 세기

홈에서 스토어 링크를 모아 **카테고리 · 상품 · 그 밖**으로 가른다.
네이버 공통 GNB(카페·뉴스·웹툰…)가 딸려 오므로 `#content` 안만 본다.

### 3. 화면 순회 — **추출기를 세 번 돌린다**

| | 어디서 | 어떻게 | 뽑히는 것 |
|:--:|---|---|---|
| 1 | **홈** | 이동 → 추출기 | 첫인상 · 고르기 설정 · **화면에 그려진 구역** · 목록 상품(fetch) · **쇼핑스토리(fetch)** |
| 2 | **상세 1** | `m.smartstore…/products/<번호>` 로 이동 → 추출기 | 상세 관련 줄 전체 |
| 3 | **상세 2** | **다른 상품**으로 같은 방법 | 상품마다 다른 줄 (옵션 이름 · 상품 일치 · 갤러리 리뷰 칸 등) |

**홈에서 돌리면 결과의 `증거.0` 에 다음에 열 상품 두 개가 들어 있다.**

> ★ **쇼핑스토리 화면은 열지 않는다.** 추출기가 홈 절에서 `fetch` 로 같이 받는다.
> «이동»하면 로그인으로 튕기지만 **`fetch` 는 200** 이다 — **목록 페이지와 똑같은 벽**이다.
> 탭 이름은 스토어마다 달라도 **주소는 `shoppingstory` 로 같다.**
> **「밖에서 못 본다」고 말하기 전에 이 우회로를 먼저 볼 것.**

> ⚠️ **상세를 하나만 열면 안 된다.** 옵션 이름 · 상품 일치 · 갤러리 리뷰 칸 같은 줄은
> 상품마다 다르다. 하나만 보고 그 스토어를 봤다고 할 수 없다.

**일반 스마트스토어의 상세는 `m.` 주소로 이동해야 열린다.** 데스크톱 주소로 넘어가며 다 그려진다.
목록은 `m.` 으로도 안 열린다 — 추출기가 fetch 로 받는다.

추출기가 상세에서 **알아서 눌러준다** — 팝업 닫기 · 상세정보 펼치기 · 끝까지 훑기 ·
고시 · 반품/교환안내 · 리뷰 전체보기. 사람이 따로 누를 것은 없다.

**캡처는 따로 찍는다.** 홈은 `fullPage`, 상세는 첫 화면이 보이는 상태에서 **뷰포트 캡처**.
쇼핑스토리는 **썸네일이 잘렸는지 봐야 하므로 반드시 캡처를 찍는다**.
요소 캡처(`locator.screenshot`)는 흰 화면으로 나온다.

### 3-b. 코드가 못 하는 것 — 사람이 채운다

| 무엇 | 어떻게 |
|---|---|
| SNS 를 실제로 운영 중인지 | **스토어명으로 인스타·블로그를 검색한다.** 안 할 리 없으니 스토어에 링크가 없으면 ❌ 로 본다 |
| 메인배너 문구·이미지의 질 | 기준표의 **「사람」** 줄이다. 채점하지 말고 캡처만 남긴다 |

> **검색해서 못 찾으면 「못 찾았다」고 적는다.** 없다고 단정하지 않는다.

### 4. 파일로 저장 — 규격

스킬을 나눠도 **규격이 없으면 도로 붙는다.** 이 규격대로 남기면 나중에 어떤 채점 스킬로도
다시 읽을 수 있다.

```
사례/<스토어 이름>/
  meta.md              사람이 읽는 소개 — 업종 · 왜 골랐나 · 총평
  수집/
    메타.json          주소 · 갈래 · 언제 · 어느 화면을 열었나
    증거.json          줄 번호 → 증거
    shots/             전체 캡처 (PC · 모바일)
```

### 메타.json

```json
{
  "이름": "예시스토어",
  "주소": "https://smartstore.naver.com/example",
  "갈래": "일반",
  "수집일": "2026-09-08",
  "연 화면": [
    { "종류": "홈",   "url": "...", "세로": 5817,  "캡처": "shots/홈_pc.png" },
    { "종류": "목록", "url": "...", "세로": 3619,  "캡처": "shots/목록_pc.png" },
    { "종류": "상세", "url": "...", "세로": 20214, "캡처": "shots/상세_pc.png" }
  ],
  "못 연 화면": [
    { "종류": "라운지", "이유": "로그인 벽" }
  ]
}
```

### 증거.json

```json
{
  "홈":   { "13": ["배너 문구…"], "18": "알림받기 있음", "20": ["카테고리1", "…"] },
  "목록": { "37": "23/23", "40": "23/23", "42": "23/23" },
  "상세": { "3": ["#태그", "…"], "51": "국산 등", "57": ["비슷한 상품"] }
}
```

**키는 `리포트_판정기준표.md` 의 줄 번호다.** 화면별로 나눠 담는다 —
같은 줄을 두 화면에서 볼 수 있어서다.

> **증거에는 판정이 없다.** ⭕❌ 는 나중에 기준표를 보고 매긴다.
> 수집이 판정까지 하면 기준표를 고칠 때 수집기도 같이 고쳐야 한다.

### 5. 못 연 화면 보고

**열려다 못 연 것을 반드시 말한다.** 나중에 채점할 때 그걸 알아야 ➖(확인 불가)와
미확인(그냥 안 본 것)을 구분한다.

```
못 연 화면
  멤버십 라운지 — 로그인 벽 (네이버 로그인으로 튕김)
  리뷰 2페이지 — 더보기가 안 눌림
```

## 하지 말 것

- ⛔ **로그인하지 말 것.** 비밀번호를 넣지 않는다. 로그인 벽을 만나면 거기서 멈추고 적는다
- ⛔ **판정하지 말 것.** ⭕❌ 도, 「이건 문제다」도 쓰지 않는다
- ⛔ **한 스토어를 몰아서 긁지 말 것.** 필요한 화면만 한 번씩 연다
- ⛔ **이메일 주소를 파일에 넣지 말 것**
- ⚠ **추출기를 부분 치환하지 말 것.** 통째로 다시 쓴다

## 자주 걸리는 것

| | 무슨 일 | 어떻게 |
|:--:|---|---|
| 1 | 팝업이 첫 화면 절반을 가린다 | 캡처 **전에** 닫는다 |
| 2 | 네이버 공통 GNB 가 딸려온다 (링크 대부분) | `#content` 안만 |
| 3 | 배너·상세설명 글자가 이미지 안에 구워져 있다 | 구조와 캡처를 **둘 다** |
| 4 | 리뷰 본문이 정규식에 걸린다 | 추출기가 영역을 잘라 쓴다 |
| 5 | 「상품정보 펼쳐보기」가 안 눌린다 | **미해결.** 브랜드·제조사가 안 나오면 그렇게 적는다 |

## 참고 — 원래는 3단계 파이프라인의 1단계였다

원본은 **수집 · 검수(채점) · 작성(리포트)** 셋으로 나뉜 스킬 세트 중 「수집」만 뽑아 번들한
것이다. 이 스킬은 증거만 남기고 멈춘다. 채점(⭕❌ 매기기)이나 리포트 작성까지 자동으로 하고
싶다면, 위 「파일로 저장」 규격을 그대로 읽어 기준표(`리포트_판정기준표.md`)에
대보는 스킬을 따로 만들면 이어 붙는다 — `증거.json` 의 키가 기준표 줄 번호이므로 규격은
이미 맞춰져 있다.
