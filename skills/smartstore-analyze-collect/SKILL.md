# 스마트스토어 수집 — 증거를 모은다

> **이 파일 하나로 끝납니다.** 88줄 채점 기준표와 추출기 코드를 이 문서 끝에
> **부록 A · 부록 B** 로 통째로 넣어놨습니다. 따로 받을 파일이 없습니다.
> 원래 「셀러들의쇼핑몰」 프로젝트에서 세 파일(SKILL.md · 추출기.js · 리포트_판정기준표.md)로
> 나눠 쓰던 스킬을, **파일 하나로도 완전히 돌아가게** 다시 묶었습니다.
> 기준표는 **일반 스마트스토어**(패션 카테고리 예시가 섞여 있음) 진단용으로 만들어졌습니다.
> 다른 업종·다른 기준으로 채점하고 싶다면 **부록 A** 를 자신의 기준으로 바꿔 쓰면 됩니다 —
> 추출기(부록 B)와 이 스킬의 순서는 그대로 씁니다.

스토어 주소 하나를 받아 **화면을 돌며 증거를 모아 파일로 남긴다.**

**최종 산출물** — `사례/<스토어 이름>/수집/` 안의 `메타.json` · `증거.json` · `shots/`

---

## 이 스킬이 절대 안 하는 것

**판정하지 않는다.** ⭕❌ 를 매기지 않는다. 「이건 잘못됐다」고 말하지 않는다.

증거와 판정을 갈라두는 이유가 있다 — **기준표는 계속 고쳐진다.** 기준표를 고칠 때마다
스토어를 다시 긁어야 한다면 느리고, 결과도 그때그때 달라지고, 남의 서버에 부담을 준다.
**수집 결과를 파일로 남기면 스토어를 안 건드리고 몇 번이든 다시 채점할 수 있다.**

수집이 판정까지 하면 기준표를 고칠 때 수집기도 같이 고쳐야 한다 — 나눈 의미가 없어진다.
증거를 뽑다가 눈에 띄는 게 있어도 **적지 말고 넘어간다.** 증거만 남기면 나중에 채점할 때 알아서 본다.

## 이 문서 안의 부록

| | |
|---|---|
| **추출기** | **부록 B** — 이 코드를 통째로 `browser_evaluate` 에 넣는다 |
| **기준표** (무엇을 뽑아야 하는지) | **부록 A** — 88줄, 판정 표시(⭕❌⊘➖)와 뽑는 법(구조/캡처/사람)까지 정의돼 있다 |

**추출기는 부분 치환하지 말 것.** `\s` 이스케이프가 어긋나 조용히 실패한다. 고칠 땐 통째로 다시 쓴다.

## 도는 순서

> 스토어 하나를 이렇게 모읍니다.
>
> 1. 주소 확인 · 갈래 판별
> 2. 문 세기 — 어떤 화면이 있나
> 3. 화면마다 순회 (팝업 닫고 · 펼치고 · 구조 뽑고 · 전체 캡처)
> 4. 파일로 저장
> 5. 못 연 화면 보고
>
> 지금은 **1번**입니다.

### 1. 주소 확인 · 갈래 판별

```
brand.naver.com      → 브랜드스토어   (홈 컴포넌트 24종, 메뉴 16개 더)
smartstore.naver.com → 일반           ← 기준표 88줄의 기본 대상
```

**갈래를 먼저 말한다.** 기준표의 🅢 · ⚠ 표시가 갈래에 따라 달라진다.

브랜드스토어면 한 줄 알린다 — 「브랜드스토어라 일반 스토어와 항목이 정확히 겹치지 않습니다.」

### 2. 문 세기

홈에서 스토어 링크를 모아 **카테고리 · 상품 · 그 밖**으로 가른다.
네이버 공통 GNB(카페·뉴스·웹툰…)가 딸려 오므로 `#content` 안만 본다.

### 3. 화면 순회 — **추출기를 세 번 돌린다**

| | 어디서 | 어떻게 | 뽑히는 것 |
|:--:|---|---|---|
| 1 | **홈** | 이동 → 추출기 | 첫인상 · 고르기 설정 · **화면에 그려진 구역** · 목록 상품(fetch) · **쇼핑스토리(fetch)** |
| 2 | **상세 1** | `m.smartstore…/products/<번호>` 로 이동 → 추출기 | 상세 관련 줄 전체 |
| 3 | **상세 2** | **다른 상품**으로 같은 방법 | 상품마다 다른 줄 (옵션 이름 · 상품 일치 · 갤러리 리뷰 칸 등) |

**홈에서 돌리면 결과의 `증거.0` 에 다음에 열 상품 두 개가 들어 있다.**

> ★ **쇼핑스토리 화면은 열지 않는다.** 추출기가 홈 절에서 `fetch` 로 같이 받는다.
> «이동»하면 로그인으로 튕기지만 **`fetch` 는 200** 이다 — **목록 페이지와 똑같은 벽**이다.
> 탭 이름은 스토어마다 달라도 **주소는 `shoppingstory` 로 같다.**
> **「밖에서 못 본다」고 말하기 전에 이 우회로를 먼저 볼 것.**

> ⚠️ **상세를 하나만 열면 안 된다.** 옵션 이름 · 상품 일치 · 갤러리 리뷰 칸 같은 줄은
> 상품마다 다르다. 하나만 보고 그 스토어를 봤다고 할 수 없다.

**일반 스마트스토어의 상세는 `m.` 주소로 이동해야 열린다.** 데스크톱 주소로 넘어가며 다 그려진다.
목록은 `m.` 으로도 안 열린다 — 추출기가 fetch 로 받는다.

추출기가 상세에서 **알아서 눌러준다** — 팝업 닫기 · 상세정보 펼치기 · 끝까지 훑기 ·
고시 · 반품/교환안내 · 리뷰 전체보기. 사람이 따로 누를 것은 없다.

**캡처는 따로 찍는다.** 홈은 `fullPage`, 상세는 첫 화면이 보이는 상태에서 **뷰포트 캡처**.
쇼핑스토리는 **썸네일이 잘렸는지 봐야 하므로 반드시 캡처를 찍는다**.
요소 캡처(`locator.screenshot`)는 흰 화면으로 나온다.

### 3-b. 코드가 못 하는 것 — 사람이 채운다

| 무엇 | 어떻게 |
|---|---|
| SNS 를 실제로 운영 중인지 | **스토어명으로 인스타·블로그를 검색한다.** 안 할 리 없으니 스토어에 링크가 없으면 ❌ 로 본다 |
| 메인배너 문구·이미지의 질 | 기준표의 **「사람」** 줄이다. 채점하지 말고 캡처만 남긴다 |

> **검색해서 못 찾으면 「못 찾았다」고 적는다.** 없다고 단정하지 않는다.

### 4. 파일로 저장 — 규격

스킬을 나눠도 **규격이 없으면 도로 붙는다.** 이 규격대로 남기면 나중에 어떤 채점 스킬로도
다시 읽을 수 있다.

```
사례/<스토어 이름>/
  meta.md              사람이 읽는 소개 — 업종 · 왜 골랐나 · 총평
  수집/
    메타.json          주소 · 갈래 · 언제 · 어느 화면을 열었나
    증거.json          줄 번호 → 증거
    shots/             전체 캡처 (PC · 모바일)
```

### 메타.json

```json
{
  "이름": "예시스토어",
  "주소": "https://smartstore.naver.com/example",
  "갈래": "일반",
  "수집일": "2026-09-08",
  "연 화면": [
    { "종류": "홈",   "url": "...", "세로": 5817,  "캡처": "shots/홈_pc.png" },
    { "종류": "목록", "url": "...", "세로": 3619,  "캡처": "shots/목록_pc.png" },
    { "종류": "상세", "url": "...", "세로": 20214, "캡처": "shots/상세_pc.png" }
  ],
  "못 연 화면": [
    { "종류": "라운지", "이유": "로그인 벽" }
  ]
}
```

### 증거.json

```json
{
  "홈":   { "13": ["배너 문구…"], "18": "알림받기 있음", "20": ["카테고리1", "…"] },
  "목록": { "37": "23/23", "40": "23/23", "42": "23/23" },
  "상세": { "3": ["#태그", "…"], "51": "국산 등", "57": ["비슷한 상품"] }
}
```

**키는 **부록 A** 기준표의 줄 번호다.** 화면별로 나눠 담는다 —
같은 줄을 두 화면에서 볼 수 있어서다.

> **증거에는 판정이 없다.** ⭕❌ 는 나중에 기준표를 보고 매긴다.
> 수집이 판정까지 하면 기준표를 고칠 때 수집기도 같이 고쳐야 한다.

### 5. 못 연 화면 보고

**열려다 못 연 것을 반드시 말한다.** 나중에 채점할 때 그걸 알아야 ➖(확인 불가)와
미확인(그냥 안 본 것)을 구분한다.

```
못 연 화면
  멤버십 라운지 — 로그인 벽 (네이버 로그인으로 튕김)
  리뷰 2페이지 — 더보기가 안 눌림
```

## 하지 말 것

- ⛔ **로그인하지 말 것.** 비밀번호를 넣지 않는다. 로그인 벽을 만나면 거기서 멈추고 적는다
- ⛔ **판정하지 말 것.** ⭕❌ 도, 「이건 문제다」도 쓰지 않는다
- ⛔ **한 스토어를 몰아서 긁지 말 것.** 필요한 화면만 한 번씩 연다
- ⛔ **이메일 주소를 파일에 넣지 말 것**
- ⚠ **추출기를 부분 치환하지 말 것.** 통째로 다시 쓴다

## 자주 걸리는 것

| | 무슨 일 | 어떻게 |
|:--:|---|---|
| 1 | 팝업이 첫 화면 절반을 가린다 | 캡처 **전에** 닫는다 |
| 2 | 네이버 공통 GNB 가 딸려온다 (링크 대부분) | `#content` 안만 |
| 3 | 배너·상세설명 글자가 이미지 안에 구워져 있다 | 구조와 캡처를 **둘 다** |
| 4 | 리뷰 본문이 정규식에 걸린다 | 추출기가 영역을 잘라 쓴다 |
| 5 | 「상품정보 펼쳐보기」가 안 눌린다 | **미해결.** 브랜드·제조사가 안 나오면 그렇게 적는다 |

## 참고 — 원래는 3단계 파이프라인의 1단계였다

원본은 **수집 · 검수(채점) · 작성(리포트)** 셋으로 나뉜 스킬 세트 중 「수집」만 뽑아 번들한
것이다. 이 스킬은 증거만 남기고 멈춘다. 채점(⭕❌ 매기기)이나 리포트 작성까지 자동으로 하고
싶다면, 위 「파일로 저장」 규격을 그대로 읽어 기준표(부록 A)에
대보는 스킬을 따로 만들면 이어 붙는다 — `증거.json` 의 키가 기준표 줄 번호이므로 규격은
이미 맞춰져 있다.

## 부록 A — 채점 기준표 원문 (88줄)

이 문서 하나로 완전히 돌아가게 하려고 원문을 그대로 옮겨 붙였다. 손댈 땐 아래 블록 전체를 다시 쓴다.

````markdown
# 스토어 진단 — 판정 기준표

**8판 · 2026-09-08 갱신.** 설계는 `리포트_설계.md`, 항목 출처는 `스마트스토어_세팅가능항목_전수.md`, 실제 적용 사례는 `../06_사례/`.

이 표가 **리포트 채점의 유일한 근거**다. 여기 안 적힌 기준으로 채점하지 않는다.

> **8판에서 뭐가 바뀌었나** — 2026-09-08 시뮬레이션 점검(`시뮬레이션_점검_20260908.md`)에서 나온 둘.
> ① **20 카테고리 메뉴 이름 — 조건을 갈랐다.** 상품 분류가 상품 이름이면 ⭕ 이고, **신상품·베스트를 그 옆에 덧붙이는 건 무방**하다.
>    잘 만든 스토어는 실제로 둘을 같이 둔다. 7판 문장대로면 그런 스토어가 ❌ 가 됐다.
> ② **79 상품명 키워드 — 근거 문서와 어긋나 있었다.** `네이버_상품명SEO가이드.md` 는 **「키워드 얹기(정상)」와 「동의어 반복(감점)」을 갈라서** 말하는데
>    7판이 둘을 한데 묶어 「같은 뜻의 말이 여러 번 나오는 것은 정상」이라고 적었다. **가이드가 나쁜 예로 든 것을 정상이라고 한 셈**이다. 갈랐다.
>
> **6판에서 뭐가 바뀌었나** — 루리 8차 채점에서 정숙님 교정 셋.
> ① **15 스토어명을 채점에서 뺐다** — 「그냥 브랜드명이니까」. 채점 제외가 20줄
> ② **81·82 쇼핑스토리는 ➖ 가 아니다.** 「이동」은 막히지만 **`fetch` 는 200** 이다 —
>    목록 페이지와 같은 벽인데 처음 보는 벽인 줄 알았다. `shoppingStory.list.contents` 에 다 있다
> ③ **13 프로모션 배너는 「사람」 줄이 실제로 굴러갔다.** 정숙님이 보고 ⭕ 를 주셨다
>
> **5판에서 뭐가 바뀌었나** — 정숙님 수정 55건(`기준표_수정대기_20260907.md`)을 반영했다.
> ① **☆ 「하면 좋은 것」을 새로 만들었다.** 셀러 의도에 따라 갈리는 11줄이 여기로 갔다. 점수가 두 줄로 갈린다
> ② **새 줄 8개**를 81~88에 붙였다. 쇼핑스토리 둘, 판매권한 뒷받침, 알림받기 노출, 공지 형식, 상품 일치, 베스트리뷰, 갤러리 리뷰 칸
> ③ **채점 제외가 11 → 19줄**로 늘었다. 네이버가 정한 것·셀러가 못 정하는 것이 더 걸러졌다
> ④ **6 · 79 두 줄은 조건이 통째로 뒤집혔다.** 방향이 반대였다
> ⑤ **용어를 통일했다** — 대표이미지/추가이미지 · 정상가/할인가

## 판정 표시

| 표시 | 뜻 |
|:--:|---|
| ⭕ | 조건 만족 |
| ❌ | 조건 못 만족 |
| ⊘ | **해당 없음** — 그 상품·갈래에 없는 기능이다. 분모에서 뺀다 |
| ➖ | **확인 불가** — 밖에서 원리적으로 못 본다. 분모에서 뺀다 |
| 미확인 | **안 봤다.** 게으름의 기록이지 판정이 아니다. 리포트에 이 표시가 남으면 안 된다 |

**추정해서 ⭕나 ❌를 주지 않는다.** 캡처에도 구조에도 없으면 미확인이고, 미확인이 남으면 그 화면을 더 열어야 한다.

## ☆ 꼬리표 — 「하면 좋은 것」 ★ 6판에서 새로 생김

**☆ 는 판정 표시가 아니다.** 판정 칸에 안 들어간다. **줄 자체에 붙는 성질**이고, 스토어와 무관하게 이 표에 박힌다.

```
| 54 ☆ | 상단 띠배너 | 판매자가 건 띠가 있다 · 권장: 행사 있을 때 | 둘 | |
                                                              ↑ 판정은 그대로 ⭕/❌
```

| | 뜻 |
|:--:|---|
| (없음) | **해야 하는 것.** 안 하면 손해다. 기본 분모로 간다 |
| ☆ | **하면 좋은 것.** 셀러 의도에 따라 갈린다. 안 해도 감점이 아니다. **별도 분모로 간다** |

**왜 분모를 갈랐나** — ⭕❌⊘➖ 넷은 각각 다른 질문에 답한다. ⭕❌ 는 「했나」, ⊘ 는 「해당되나」, ➖ 는 「볼 수 있나」다. 「추가이미지 9장」·「상단 띠배너」·「쿠폰」은 **넷 다 아니다.** 보이고, 해당되고, 했는지도 안다. 다만 **안 한 게 틀린 게 아니다.**

그렇다고 분모에서 그냥 빼면 안 된다. 정숙님이 못박은 문장이 둘이다.

> *「그럼에도 고객을 끌어당길 수 있는 설정이기 때문에 **점수를 어느정도 줄 수 있다**」* (할인율)
> *「**최대한 많이 등록하는 것을 최고 점수 기준으로 두고** 이는 셀러의 의도를 물어봐야한다」* (추가이미지)

빼버리면 **잘 채운 셀러에게 줄 자리가 없어진다.** 별도 분모면 안 해도 안 깎이고, 하면 보인다.

**점수는 두 줄로 낸다.**

```
해야 하는 것   48줄 중 ○○줄
하면 좋은 것   11줄 중 ○○줄
```

**리포트에서는 「셀러 의도」라고 쓰지 않는다.** 내부 용어다. 신청자에게는 **「해야 하는 것 / 하면 좋은 것」**으로 말한다.

**☆ 11줄** — `9 · 19 · 23 · 24 · 25 · 26 · 29 · 40 · 43 · 54 · 64`

> **☆ 와 「채점 제외」를 헷갈리지 말 것.**
> ☆ 는 **권장 방향이 있다.** 「하는 게 낫지만 안 해도 된다」
> 채점 제외는 **방향조차 없거나 셀러가 정한 게 아니다.** 21번(카테고리 우선순위)처럼 밖에서 옳고 그름을 정할 수 없으면 ☆ 가 아니라 제외로 간다.

## 필요한 재료

한 스토어당 아래를 뽑는다. **위쪽 한 장만 찍으면 안 된다** — 르무통에서 화면 세로의 9%만 보고 매겼다가 78줄 중 23줄이 미확인으로 남았다.

| | 화면 | 뽑는 것 |
|:--:|---|---|
| 1 | 스토어 홈 | 구조 + **전체 페이지 캡처** (PC·모바일) |
| 2 | 상품 목록 (카테고리 하나) | 구조 + 전체 캡처 |
| 3 | 상품 상세 **2개** | 구조 + 전체 캡처 + **상세정보 펼친 뒤** 한 번 더 |
| 4 | 리뷰 영역 | 구조 (답글·포인트 안내) |
| 5 | **쇼핑스토리** ★ 7판 | **`fetch` 로 받는다.** 이동하면 로그인으로 튕긴다 — 목록 페이지와 같다 |
| 6 | **SNS 실제 운영 여부** ★ 6판 | 스토어명으로 검색 |

> **★ 쇼핑스토리는 화면을 열지 않는다.** `<스토어>/shoppingstory/list?cp=1` 을 **`fetch`** 하면 200 이고
> `__PRELOADED_STATE__.shoppingStory.list.contents` 에 글이 다 들어 있다.
> 「이동」하면 로그인으로 튕기는데 **그건 우리 도구 문제이지 스토어가 막은 게 아니다.**
> 탭 이름은 스토어마다 다를 수 있지만 **주소는 `shoppingstory` 로 같다.**
> **★ 상세는 반드시 2개.** 6번(Meta description)이 상품 간 비교를 요구한다. 하나만 열면 그 줄이 영영 미확인이다.

**로그인이 필요한 화면은 열지 않는다.** 비밀번호를 넣지 않는다.

> **「왜 안 보이나」는 추출기가 단정하지 않는다.** 켬·보임 두 값만 적고, 판단은 채점에서 한다.

> **19 · 29 는 「켰는데 비어 있는」 자리다.** 설정은 `true` 인데 화면에 없다 — 발행한 쿠폰이나 올린 클립이 0개라서다.
> **판정은 ❌ 다** (손님 눈에 안 보이면 없는 것과 같다). **처방이 다르다** — 「켜세요」가 아니라 **「켜두셨으니 채우세요」**.
> **「제목만 넣으시면 됩니다」는 틀린 처방이다.** 담은 상품이 없어서 안 보이는 것이라 **상품부터 담아야** 한다.
````
