## 판정 표시

| 표시 | 뜻 |
|:--:|---|
| ⭕ | 조건 만족 |
| ❌ | 조건 못 만족 |
| ⊘ | **해당 없음** — 그 상품·갈래에 없는 기능이다. 분모에서 뺀다 |
| ➖ | **확인 불가** — 밖에서 원리적으로 못 본다. 분모에서 뺀다 |
| 미확인 | **안 봤다.** 게으름의 기록이지 판정이 아니다. 리포트에 이 표시가 남으면 안 된다 |

**추정해서 ⭕나 ❌를 주지 않는다.** 캡처에도 구조에도 없으면 미확인이고, 미확인이 남으면 그 화면을 더 열어야 한다.

## ☆ 꼬리표 — 「하면 좋은 것」 ★ 6판에서 새로 생김

**☆ 는 판정 표시가 아니다.** 판정 칸에 안 들어간다. **줄 자체에 붙는 성질**이고, 스토어와 무관하게 이 표에 박힌다.

```
| 54 ☆ | 상단 띠배너 | 판매자가 건 띠가 있다 · 권장: 행사 있을 때 | 둘 | |
                                                              ↑ 판정은 그대로 ⭕/❌
```

| | 뜻 |
|:--:|---|
| (없음) | **해야 하는 것.** 안 하면 손해다. 기본 분모로 간다 |
| ☆ | **하면 좋은 것.** 셀러 의도에 따라 갈린다. 안 해도 감점이 아니다. **별도 분모로 간다** |

**왜 분모를 갈랐나** — ⭕❌⊘➖ 넷은 각각 다른 질문에 답한다. ⭕❌ 는 「했나」, ⊘ 는 「해당되나」, ➖ 는 「볼 수 있나」다. 「추가이미지 9장」·「상단 띠배너」·「쿠폰」은 **넷 다 아니다.** 보이고, 해당되고, 했는지도 안다. 다만 **안 한 게 틀린 게 아니다.**

그렇다고 분모에서 그냥 빼면 안 된다. 정숙님이 못박은 문장이 둘이다.

> *「그럼에도 고객을 끌어당길 수 있는 설정이기 때문에 **점수를 어느정도 줄 수 있다**」* (할인율)
> *「**최대한 많이 등록하는 것을 최고 점수 기준으로 두고** 이는 셀러의 의도를 물어봐야한다」* (추가이미지)

빼버리면 **잘 채운 셀러에게 줄 자리가 없어진다.** 별도 분모면 안 해도 안 깎이고, 하면 보인다.

**점수는 두 줄로 낸다.**

```
해야 하는 것   48줄 중 ○○줄
하면 좋은 것   11줄 중 ○○줄
```

**리포트에서는 「셀러 의도」라고 쓰지 않는다.** 내부 용어다. 신청자에게는 **「해야 하는 것 / 하면 좋은 것」**으로 말한다.

**☆ 11줄** — `9 · 19 · 23 · 24 · 25 · 26 · 29 · 40 · 43 · 54 · 64`

> **☆ 와 「채점 제외」를 헷갈리지 말 것.**
> ☆ 는 **권장 방향이 있다.** 「하는 게 낫지만 안 해도 된다」
> 채점 제외는 **방향조차 없거나 셀러가 정한 게 아니다.** 21번(카테고리 우선순위)처럼 밖에서 옳고 그름을 정할 수 없으면 ☆ 가 아니라 제외로 간다.

## 필요한 재료

한 스토어당 아래를 뽑는다. **위쪽 한 장만 찍으면 안 된다** — 르무통에서 화면 세로의 9%만 보고 매겼다가 78줄 중 23줄이 미확인으로 남았다.

| | 화면 | 뽑는 것 |
|:--:|---|---|
| 1 | 스토어 홈 | 구조 + **전체 페이지 캡처** (PC·모바일) |
| 2 | 상품 목록 (카테고리 하나) | 구조 + 전체 캡처 |
| 3 | 상품 상세 **2개** | 구조 + 전체 캡처 + **상세정보 펼친 뒤** 한 번 더 |
| 4 | 리뷰 영역 | 구조 (답글·포인트 안내) |
| 5 | **쇼핑스토리** ★ 7판 | **`fetch` 로 받는다.** 이동하면 로그인으로 튕긴다 — 목록 페이지와 같다 |
| 6 | **SNS 실제 운영 여부** ★ 6판 | 스토어명으로 검색 |

> **★ 쇼핑스토리는 화면을 열지 않는다.** `<스토어>/shoppingstory/list?cp=1` 을 **`fetch`** 하면 200 이고
> `__PRELOADED_STATE__.shoppingStory.list.contents` 에 글이 다 들어 있다.
> 「이동」하면 로그인으로 튕기는데 **그건 우리 도구 문제이지 스토어가 막은 게 아니다.**
> 탭 이름은 스토어마다 다를 수 있지만 **주소는 `shoppingstory` 로 같다.**
> **★ 상세는 반드시 2개.** 6번(Meta description)이 상품 간 비교를 요구한다. 하나만 열면 그 줄이 영영 미확인이다.

**로그인이 필요한 화면은 열지 않는다.** 비밀번호를 넣지 않는다.

## ① 발견 — 검색에 걸리는가

| # | 항목 | ⭕ 라고 할 조건 | 뽑는 법 | 갈래 |
|:--:|---|---|:--:|:--:|
| 1 | 상품명 구성 | **상품종류(카테고리)와 주요 속성이 있다.** 브랜드명은 **없어도 된다**. 검색 노출을 위해 키워드를 얹은 것도 ⭕ — 셀러가 일부러 하는 정상 행위다 | 구조 | |
| 2 | 상품명 금지어 | **아래 금지어가 상품명에 하나도 없다** — 가격(가성비·즉시할인·최저가·특가) · 혜택재고(사은품·증정·품절) · 홍보성(MD추천·선착순·신상품) · 기타(A급·st·공식·모음·정품) · 타겟(10대·20대·예식장) · 특수문자(★◎) · 전화번호 · 셀러코드(IP01·_ES) · 타사 브랜드 나열 | 구조 | |
| 3 | 검색 태그 | 검색 태그가 **등록돼 있다**. **최대 10개까지 넣을 수 있으니 최대한 채우는 것을 권장** (꼭 다 채워야 ⭕는 아니다). 리포트에 **몇 개인지 숫자를 적는다** | 구조 — 상세 하단 태그 영역 | |
| 4 | 카테고리 지정 | 카테고리가 **끝까지 지정돼 정리돼 있다**. **어느 카테고리에 넣었는지는 따지지 않는다** — 네이버 분류 안에서 어디가 옳은지는 밖에서 판단할 수 없다 | 구조 — **`performance` 로 읽는다** (아래 주) | |
| 5 | Page Title | 상품명과 스토어명이 함께 들어 있다 | **구조** — `<title>` | |
| 6 | Meta description | **설정돼 있다.** ★ **조건이 뒤집혔다** — 상품마다 같아도 된다. 브랜드 성격에 따라 전 상품 같은 문장을 쓰기도 한다 | **구조** — `meta[name=description]` | |
| 7 | 네이버쇼핑 등록 | ➖ — **상품 설정단까지 들어가야 보인다.** 다만 **새 네이버쇼핑이 아니라 구버전 가격비교에 등록되므로 반드시 켜야 한다.** → 「잊지 않았나요」 | ➖ | |
| 8 | 스토어 전용 상품명 | ➖ — **상품 설정단까지 들어가야 보인다.** 다만 **쓰면 안 된다.** 상품명은 마케팅·검색 노출용으로 수시로 고치는 자리라 전용 상품명을 따로 두면 어긋난다 → 「잊지 않았나요」 | ➖ | |
| 9 ☆ | 그룹상품 묶음 | 색상·용량이 **한 상품 안에서** 골라진다 · **권장: 조건부** | 구조 — 옵션 영역 | |
| 10 | 가격비교 연결 | ➖ | ➖ | |
| 11 | ~~쇼핑윈도 입점~~ | **채점 안 함 — 수년 전 폐지된 서비스다.** 번호만 남긴다 | — | |
| 12 | 상품판매권한 | ➖ — 건강기능식품·의료기기 같은 **민감 카테고리는 서류 승인이 필요하다.** 밖에선 승인 여부를 못 본다 → 「잊지 않았나요」. **뒷받침 콘텐츠는 83번에서 본다** | ➖ | |

> **9번이 ☆ 인 이유** — 정숙님: *「실제 내가 그룹상품화 하여 운영해본 결과 페이지 순위권에서도 밀리고 광고 효율도 좋지 않은 모습이 보였음. 때문에 **상황에 따라 추천 강도가 달라짐**」*
> **옵션이 많아 드롭다운으로는 보기 어렵거나, 키워드별로 옵션을 갈라 광고를 돌리고 싶을 때만 유리하다.** 옵션이 단순하고 튀는 키워드가 없으면 기본 드롭다운이 낫다. 밖에서 어느 쪽인지 정할 수 없다.

> **4번 카테고리 경로를 뽑는 법** — 새로 두드리지 않는다. 상세 화면이 **스스로 부른** `category-navigations` 요청 주소에 `wholeCategoryName` 이 들어 있다. `performance.getEntriesByType('resource')` 로 그 주소를 읽는다. 우리가 같은 API 를 다시 부르면 막힌다.
