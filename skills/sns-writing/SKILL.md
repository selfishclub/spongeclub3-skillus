# SNS 글쓰기

이 스킬은 **「만드는 방식」만** 담는다. **「누가 쓰는가」와 「무엇을 쓰는가」는 담지 않는다.**

그 둘은 사람마다 다르고, 공개 저장소에 올라가면 안 되는 것이기 때문이다.
그래서 사용자의 재료는 **이 폴더 바깥의 「재료 폴더」** 에서 읽어온다.

---

## 시작하기 전에 ① — 재료 폴더를 찾는다

**아래 순서로 찾는다. 앞엣것이 이긴다.**

1. 지금 작업 중인 폴더의 **`kara-os-private/`** ← 지금 쓰는 이름
2. 지금 작업 중인 폴더의 `sns-writing-private/` ← 예전 이름. 쓰던 사람은 그대로 잡힌다
3. 지금 작업 중인 폴더의 **다른 `-private/` 폴더**
4. `~/kara-os-private/`

🔴 **찾은 것이 둘 이상이면 고르지 말고 묻는다.**
남이 준 재료 폴더를 말없이 읽어오면 안 된다.

```
재료 폴더가 여러 개 보입니다. 어느 걸 쓸까요?
  1) kara-os-private/
  2) sns-writing-private/
```

찾으면 그 안의 파일을 **먼저 읽고** 시작한다.

| 파일 | 무엇 |
|---|---|
| `who-i-am.md` | 글쓴이가 누구인지. 말투와 시선의 기준이 된다 |
| `material-stash.md` | 소재 보관소. 실제로 겪은 일들의 목록 |
| `my-voice.md` | 이 사람의 어투와 금지어. 글을 쓸 때마다 갱신한다 |

## 시작하기 전에 ② — 없으면 **직접 만들어 준다**

🔴 **사용자에게 `mkdir` 명령을 시키지 않는다.**
어디서 실행하느냐에 따라 엉뚱한 곳에 생기고, 그러면 이 스킬이 못 찾는다.
**지금 작업 폴더가 어디인지는 이 스킬이 안다.** 그러니 이 스킬이 만든다.

**사용자가 「재료 폴더 만들어줘」라고 직접 시켰으면 묻지 않는다.**
바로 만들고, **어디에 무엇을 만들었는지 전체 경로로 보여준다.**
시켜놓고 *"만들까요?"* 라고 되묻지 않는다.

**일하다가 없는 걸 발견했을 때만 묻는다.** 그때는 이렇게.

```
재료 폴더가 없네요. 여기에 만들어 드릴까요?
  /지금/작업/폴더/kara-os-private/

만들면 매번 "제가 누구인지"를 다시 설명하지 않아도 됩니다.
안 만들어도 됩니다 — 그때는 제가 물어보며 씁니다.
```

**만들기로 하면 순서대로 한다.**

1. `<작업폴더>/kara-os-private/` 를 만든다
   🔴 **이름은 항상 `kara-os-private`.** 스킬 이름을 붙이지 않는다 —
   스킬이 여러 개여도 재료 폴더는 **하나**여야 한다
2. 이 스킬 폴더의 `templates/` 안 견본을 복사해 넣는다
   🔑 **폴더가 이미 있어도 이 단계는 한다.** 다른 스킬이 먼저 만들어서
   이 스킬이 쓰는 파일(who-i-am.md · material-stash.md · my-voice.md)이 빠져 있을 수 있다.
   **없는 것만 채우고, 있는 것은 절대 덮어쓰지 않는다.**
   (`templates/` 가 없으면 아래 「재료 파일에 뭘 적나」를 보고 뼈대를 만들어 준다)
3. 🔴 **깃으로 관리되는 폴더인지 확인한다** — 작업 폴더에서 위로 거슬러 올라가며 `.git` 폴더가 있는지 본다.

**`.gitignore` 는 언제나 「지금 작업 폴더」에 둔다.** 두 경우로 갈린다.

**경우 ①  작업 폴더가 저장소 안쪽일 때**

```
저장소 뿌리:  ~/myrepo/              ← .git 이 여기 있어도
작업 폴더:    ~/myrepo/work/deeper/  ← .gitignore 는 여기에 만든다
재료 폴더:    ~/myrepo/work/deeper/kara-os-private/
```

뿌리 파일은 **같이 쓰는 사람들 것**이라 안 건드린다. 작업 폴더에 두면 **그 아래만** 막히고 효과는 같다.

**경우 ②  작업 폴더가 곧 저장소 뿌리일 때 — 이게 더 흔하다**

```
저장소 뿌리 = 작업 폴더:  ~/myrepo/    ← .gitignore 를 여기 말고 둘 데가 없다
```

이때는 **뿌리 `.gitignore` 에 넣는 수밖에 없다.** 대신 이렇게 한다.

- **혼자 쓰는 저장소면** 그냥 넣어도 된다
- 🔴 **여럿이 쓰는 저장소면** 그 파일이 남에게도 갑니다 — **이 사실을 밝히고 묻는다**

```
이 폴더가 곧 깃 저장소의 뿌리입니다.
.gitignore 를 여기 말고 둘 데가 없습니다.

⚠️ 여럿이 쓰는 저장소라면 이 한 줄이 같이 쓰는 분들에게도 갑니다.
   (막는 것뿐이라 남의 작업에 지장은 없습니다)

넣을까요?  ~/myrepo/.gitignore  ←  *-private/
```

**「아니오」라고 하면 넣지 않는다.** 대신 이렇게 알려준다 —
*"그러면 커밋하실 때 `kara-os-private/` 가 안 들어갔는지 직접 확인하셔야 합니다."*

**이렇게 묻는다. 무엇을 어디에 넣을지 다 보여준다.**

```
이 폴더는 깃으로 관리되고 있습니다. (.git 위치: ~/myrepo)
그대로 두면 재료 폴더가 통째로 인터넷에 올라갈 수 있습니다.

이 파일에 한 줄을 더할까요?
  ~/myrepo/work/deeper/.gitignore   (없으면 새로 만듭니다)

더할 내용:
  *-private/
```

**파일이 이미 있으면 맨 끝에 한 줄만 더한다.** 원래 내용은 건드리지 않는다.
**같은 줄이 이미 있으면 아무것도 하지 않는다.**
넣은 뒤 `git check-ignore` 로 **정말 막혔는지 확인해서 보여준다.**

🔴 **확인했는데 안 막혀 있으면 그대로 말한다.** 넘어가지 않는다.
흔한 원인은 **이미 깃에 등록된 파일**이다 — 그때는 `.gitignore` 가 소용없다.
그 경우 사용자에게 알린다: *"이미 깃에 올라간 파일이라 `.gitignore` 로는 못 막습니다.
`git rm --cached` 로 등록을 먼저 푸셔야 합니다."*

4. 만든 뒤 **무엇을 적으면 되는지 한 번에** 알려준다. 빈 파일만 주고 끝내지 않는다

### 재료 파일에 뭘 적나 — 견본

**`who-i-am.md`**

```
- 무슨 일을 하는 사람인지 한 줄
- 지금 하고 있는 일 (프로젝트·직장·공부)
- 어떤 사람으로 보이고 싶은지 한 줄
- 절대 쓰고 싶지 않은 주제
```

**`material-stash.md`** — 겪은 일을 **한 줄씩** 쌓는다. 다듬지 않는다

```
- 2026-09-07 스터디를 열었더니 아홉 시간 만에 두 명이 왔다
- 2026-09-03 스레드에 처음 글을 올렸다
```

**`my-voice.md`** — 처음엔 비어 있어도 된다. 글을 쓸 때마다 이 스킬이 채운다

```
## 이렇게 쓴다
- (예) 딱 떨어지지 않는 숫자에는 "약"을 붙인다

## 이렇게 안 쓴다
- (예) 느낌표를 두 개 이상 쓰지 않는다
```

**재료 폴더가 없어도 그냥 진행한다.** 만들라고 강요하지 않는다.
물어보며 쓰되, 글을 다 쓴 뒤에 *"이 내용을 재료 폴더로 남겨둘까요?"* 라고 **한 번만** 제안한다.

## 0단계 · 채널을 먼저 정한다

**어느 채널에 올릴지부터 확정한다.** 채널이 정해져야 글의 모양이 정해진다.

| 채널 | 읽을 파일 | 그 파일이 없으면 |
|---|---|---|
| 스레드 (Threads) | `references/channel-threads.md` | 아래 「참고 요약」의 스레드 부분 |
| 인스타그램 캐러셀 | `references/channel-instagram.md` | 아래 「참고 요약」의 캐러셀 부분 |

사용자가 말 안 하면 묻는다. **한 소재로 두 채널을 다 만들 수도 있다** —
스레드로 먼저 쓰고 그 글을 인스타 캐러셀로 옮기는 것이 가장 효율이 좋다.

## 1단계 · 소재 확정

바로 쓰지 말고, **이 글의 결론이 뭔지부터 한 줄로 합의한다.**
결론이 없으면 아무리 훅이 좋아도 중간에 흩어진다.

소재가 없다고 하면 `references/topic-mining.md`(없으면 아래 「소재 카테고리 6종」)를 보고,
**재료 폴더의 `material-stash.md` 를 1순위 재료로 삼아** 후보를 뽑아 제시한다.

## 2단계 · 사실 확인

인물, 브랜드, 작품, 통계, 시점이 등장하면 **쓰기 전에 검색한다.** 선택이 아니다.
SNS 글은 공개 기록으로 남고, 숫자 하나 틀리면 글 전체의 신뢰가 무너진다.

특히 이런 것들을 확인한다.

- 발언이 언제 어디서 나온 것인지
- 인용문의 실제 워딩
- 숫자가 최신인지, 사용자가 알고 있는 값이 옛 수치는 아닌지
- 🔴 **「어제·오늘·사흘 전」 같은 말** — 실제 날짜를 재서 맞춘다.
  **발행이 하루만 밀려도 틀린 글이 된다.** 쓴 날이 아니라 **올리는 날** 기준으로 다시 잰다

**없는 사실은 절대 지어내지 않는다.** 반응, 지원자 수, 마감일처럼 사용자만 아는 정보는
추측해서 채우지 말고 물어본다. *"아직 없다"* 는 상태 자체가 좋은 콘텐츠가 되므로 숨길 이유도 없다.

🔴 **남의 말을 그대로 옮기지 않는다.** 채팅방·댓글에서 본 남의 문장을 공개 글로 옮기려면
**허락이 필요하다.** 허락 전에는 이름을 빼고 요지만 적는다.

## 3단계 · 훅 후보 3개 제시

전체를 쓰기 전에 **첫 자리(스레드 1번 칸 / 인스타 표지) 후보를 세 개** 만들어 보여준다.
각 후보마다 어떤 각도이고 무엇을 노리는지 한 줄로 설명하고,
마지막에 어느 것을 추천하는지와 그 이유를 말한다.

**세 후보는 서로 다른 각도여야 한다.** 같은 말을 세 가지로 다듬은 건 선택지가 아니다.
훅 유형은 `references/hooks.md`, 없으면 아래 「훅 8유형」에서 고른다.

사용자가 고르거나 직접 수정한 뒤 전체를 쓴다.

## 4단계 · 전체 작성

0단계에서 정한 **채널에서 지켜야 할 것**에 맞춰 쓴다.
사용자가 그대로 복사해 붙일 수 있는 형태로 낸다.

본문 뒤에 짧은 메모를 붙인다. 어느 자리가 이 글의 승부처이고 왜 그렇게 배치했는지,
사용자가 채워야 할 빈칸이 뭔지. **메모는 본문보다 짧게.**

## 5단계 · 발행 후

사용자가 수정본을 올려주면 **뭘 바꿨고 왜 그게 나은지** 짚는다.
그리고 앞으로 반영할 원칙을 한두 줄로 뽑아 **재료 폴더의 `my-voice.md` 에 추가한다.**
이게 쌓이면 그 사람의 문체가 된다.

성과 수치를 가져오면 **왜 잘됐는지 구조로 분석한다.**
*"소재가 좋았다"* 는 식의 뭉뚱그린 평가는 다음에 쓸 수 없다.
첫 자리에 뭐가 있었는지, 어디서 끊었는지, 주인공이 누구였는지로 분해한다.

## 채널을 가리지 않는 원칙

아래 다섯 가지는 **어느 채널에서든 지킨다.**

### 1. 첫 자리가 전부다

스레드의 1번 칸, 인스타의 표지 1장. **여기서 볼지 말지가 갈린다.**

- **장면이나 인물로 연다.** 주장이나 설명으로 시작하면 **손가락이 안 멈추고 그냥 넘어간다**
- **결론을 말하지 않고 끊는다.** 미해결 상태로 끝내야 다음을 볼 이유가 생긴다
- **가능하면 남을 주인공으로 세운다.** 자기 이야기도 남 이야기처럼 열 수 있다
- 이 글을 처음 보는 사람이 **첫 자리만 읽고도 상황이 잡혀야** 한다

### 2. 자극은 세게, 상처는 없게

후킹은 세게 하되, **그 글을 읽고 상처받는 사람이 없어야 한다.**

특정 집단이나 사람을 깎아서 만드는 자극은 쓰지 않는다.
*"○○하는 사람들한테는 미안한 말인데"* 같은 문장은 눈길을 끌지만 누군가를 밟고 서 있다.

대신 두 방향으로 만든다.

- **대상을 높이기** — 남의 가치를 올려서 만드는 자극
- **자기를 낮추기** — 자기에게 붙은 험한 평가를 먼저 꺼내기

분석 대상이 실제 사람이면 특히 조심한다. 다들 믿는 말을 뒤집되
그 사람의 실력이나 존재를 **축소하는 방향으로 가면 안 된다.**

### 3. 글의 두 유형

**이야기형** — 내가 겪은 일을 장면으로 푸는 글. **가장 많은 사람에게 보인다.**
미리 알아야 할 게 없어서 누구나 읽히기 때문이다.

> 흐름: 장면 → 대사 → 반전 → 그래서 지금 무엇을 하는가

- 감정이 정리되지 않은 상태를 억지로 정리하지 않는다
- 위로나 교훈으로 닫으면 흔한 글이 된다. **관찰로 닫는다**
- 자기 희생을 강조하면 읽는 사람이 부채감을 느끼고 도망간다. 손해는 **사실로만 한 번** 놓고 지나간다

**분석형** — 많은 사람이 아는 대상을 남들과 다르게 풀어내는 글.
**보는 사람 수는 적지만** 저장하고 퍼가는 비율이 높다.

> 흐름: 다들 믿는 말 꺼내기 → 뒤집기 → 근거 → 넓혀서 말하기 → 뒤에서 내 이야기로 마무리

- 대상이 **이미 대중적으로 알려져** 있어야 한다
- 흔한 해석을 **뒤집어야** 한다. **정리는 분석이 아니다**
- 전반부에 자기 사례를 하나 심어두면 *"그래서 당신은 뭔데"* 가 미리 풀린다

### 4. 문장 기술

- **개념에 이름을 붙인다.** 사람들이 저장하고 인용하는 건 설명이 아니라 이름 붙은 개념이다
- **비유를 들었으면 끝에서 다시 그 말로 돌아온다.** 돌아오지 않는 비유는 그냥 예시로 남는다
- **인용할 땐 그 순간의 나를 같이 넣는다.** 자료만 인용하면 데이터고, 받았을 때 내가 어땠는지가 들어가면 장면이 된다
- **날것을 편집하지 않는다.** 메모·대화를 인용할 땐 말투와 오타 느낌까지 그대로 둔다
- **앞에서 쌓은 걸 마지막에 배신한다.** 순서를 열심히 알려준 뒤 *"근데 다 지켜도 터진다"* 로 꺾으면 정보 나열 글이 실행자의 글이 된다

### 5. 마무리와 CTA

**문턱을 낮추면 가치도 같이 낮아진다.** *"부담 갖지 마세요"* 는 오히려 전환을 떨어뜨린다.

- **왜 귀한지를 말한다** — 이 기회가 흔한지 아닌지까지 논증한다
- **안 움직이는 사람과의 차이를 말한다**
- **확신으로 닫지 않는다** — *"잘될지는 아직 모르겠다"* 가 남기는 여운이 더 크다

감정선이 깊은 글에는 **링크를 안 붙이는 게 낫다.** 링크가 붙으면 앞의 진심이 미끼처럼 보인다.
궁금한 사람은 프로필을 누른다.

## 다음 글을 궁금하게 만드는 법

*"다음 편도 기대해주세요"* 같은 문장은 쓰지 않는다. 아무도 안 기다린다. **구조로 만든다.**

- **숫자를 걸어둔다** — 진행 중인 카운터가 있으면 사람들이 결과를 보러 온다
- **결정권을 넘긴다** — 실제로 미정인 사항을 댓글로 정하면, 자기가 투표한 결과를 확인하러 돌아온다
- **미정 상태를 대놓고 말한다** — *"아직 협의 중"* 이 다음 글의 예고편이다

단, **실제로 없는 카운터를 만들지 않는다.** 셀 수 있게 된 다음부터 쓴다.

## 인스타 캐러셀로 만들 때 지킬 것

| 구간 | 장수 | 역할 |
|---|---|---|
| 표지 | 1 | 넘길지 말지 결정 |
| 상황 | 1~2 | 뭘 하는 얘기인지 |
| 전개 | 4~7 | 한 장에 하나씩 |
| **정리** | 1 | 🔑 **캡처해 가는 장.** 반드시 넣는다 |
| CTA | 1 | 링크 안내나 왜 하는지 |

- 전체 **8~12장.** 12장이 넘으면 **보다가 나가는 사람이 확 는다**
- **한 장에 한 문장까지 줄인다.** 스레드 한 칸이 카드 한 장이 아니다
- **표지는 상황 요약이 아니라 궁금증으로** 연다
- **반전 앞에서 장을 쪼갠다.** 넘기는 맛이 여기서 난다
- 그림 크기 **가로세로 1080** · 여러 장을 이어 만들 땐 **쓰는 색을 고정**한다
- 🔴 **인스타 캡션의 주소는 눌리지 않는다.** 링크는 프로필에 건다
- 캡션은 첫 두 줄에 훅. CTA는 하나만. 해시태그 10~15개
