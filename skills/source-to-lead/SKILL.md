# 소재 하나로 신청까지

## 이 스킬이 답하는 것 / 답하지 않는 것

| | |
|---|---|
| ✅ **답한다** | 이 소재로 **몇 편**을 만드나 · **어느 채널**에 · **어떤 순서**로 · **링크는 어디에** · **어디서 왔는지 어떻게 세나** |
| ❌ **답하지 않는다** | 문장을 어떻게 쓰나 · 훅을 어떻게 잡나 → **글쓰기 스킬이 있으면 그쪽에 넘긴다** |

**이 스킬의 목적은 하나다. 콘텐츠를 만드는 게 아니라, 콘텐츠가 사람을 「신청」까지 데려가게 만드는 것.**

---

## 시작하기 전에 ① — 재료 폴더를 찾는다

**아래 순서로 찾는다. 앞엣것이 이긴다.**

1. 지금 작업 중인 폴더의 **`kara-os-private/`** ← 지금 쓰는 이름
2. 지금 작업 중인 폴더의 `source-to-lead-private/` ← 예전 이름. 쓰던 사람은 그대로 잡힌다
3. 지금 작업 중인 폴더의 **다른 `-private/` 폴더**
4. `~/kara-os-private/`

🔴 **찾은 것이 둘 이상이면 고르지 말고 묻는다.**
남이 준 재료 폴더를 말없이 읽어오면 안 된다.

```
재료 폴더가 여러 개 보입니다. 어느 걸 쓸까요?
  1) kara-os-private/
  2) source-to-lead-private/
```

| 파일 | 무엇 | 없으면 |
|---|---|---|
| `material-stash.md` | 소재 보관소 | 사용자에게 소재를 묻는다 |
| `destinations.md` | **목적지 목록** — 신청 페이지·폼 주소 | 0단계에서 묻는다 |
| `utm-terms.md` | **쓰는 말을 고정한 표** — 채널별 `source`/`medium` | 5단계에서 만든다 |
| `who-i-am.md` | 글쓴이가 누구인지 | 없어도 진행 |

> **글쓰기 스킬의 재료 폴더가 이미 있으면 그걸 같이 쓴다.** 소재 보관소를 두 개 두지 않는다.

## 시작하기 전에 ② — 없으면 **직접 만들어 준다**

🔴 **사용자에게 `mkdir` 명령을 시키지 않는다.**
어디서 실행하느냐에 따라 엉뚱한 곳에 생기고, 그러면 이 스킬이 못 찾는다.
**지금 작업 폴더가 어디인지는 이 스킬이 안다.** 그러니 이 스킬이 만든다.

**사용자가 「재료 폴더 만들어줘」라고 직접 시켰으면 묻지 않는다.**
바로 만들고, **어디에 무엇을 만들었는지 전체 경로로 보여준다.**
시켜놓고 *"만들까요?"* 라고 되묻지 않는다.

**일하다가 없는 걸 발견했을 때만 묻는다.** 그때는 이렇게.

```
재료 폴더가 없네요. 여기에 만들어 드릴까요?
  /지금/작업/폴더/kara-os-private/

안 만들어도 됩니다 — 그때는 제가 물어보며 진행합니다.
```

**만들기로 하면 순서대로 한다.**

1. `<작업폴더>/kara-os-private/` 를 만든다
   🔴 **이름은 항상 `kara-os-private`.** 스킬 이름을 붙이지 않는다 —
   스킬이 여러 개여도 재료 폴더는 **하나**여야 한다
2. 이 스킬 폴더의 `templates/` 안 견본을 복사해 넣는다
   🔑 **폴더가 이미 있어도 이 단계는 한다.** 다른 스킬이 먼저 만들어서
   이 스킬이 쓰는 파일(destinations.md · utm-terms.md · material-stash.md · who-i-am.md)이 빠져 있을 수 있다.
   **없는 것만 채우고, 있는 것은 절대 덮어쓰지 않는다.**
   (`templates/` 가 없으면 아래 「재료 파일에 뭘 적나」를 보고 뼈대를 만들어 준다)
3. 🔴 **깃으로 관리되는 폴더인지 확인한다** — 작업 폴더에서 위로 거슬러 올라가며 `.git` 폴더가 있는지 본다.

**`.gitignore` 는 언제나 「지금 작업 폴더」에 둔다.** 두 경우로 갈린다.

**경우 ①  작업 폴더가 저장소 안쪽일 때**

```
저장소 뿌리:  ~/myrepo/              ← .git 이 여기 있어도
작업 폴더:    ~/myrepo/work/deeper/  ← .gitignore 는 여기에 만든다
재료 폴더:    ~/myrepo/work/deeper/kara-os-private/
```

뿌리 파일은 **같이 쓰는 사람들 것**이라 안 건드린다. 작업 폴더에 두면 **그 아래만** 막히고 효과는 같다.

**경우 ②  작업 폴더가 곧 저장소 뿌리일 때 — 이게 더 흔하다**

```
저장소 뿌리 = 작업 폴더:  ~/myrepo/    ← .gitignore 를 여기 말고 둘 데가 없다
```

이때는 **뿌리 `.gitignore` 에 넣는 수밖에 없다.** 대신 이렇게 한다.

- **혼자 쓰는 저장소면** 그냥 넣어도 된다
- 🔴 **여럿이 쓰는 저장소면** 그 파일이 남에게도 갑니다 — **이 사실을 밝히고 묻는다**

```
이 폴더가 곧 깃 저장소의 뿌리입니다.
.gitignore 를 여기 말고 둘 데가 없습니다.

⚠️ 여럿이 쓰는 저장소라면 이 한 줄이 같이 쓰는 분들에게도 갑니다.
   (막는 것뿐이라 남의 작업에 지장은 없습니다)

넣을까요?  ~/myrepo/.gitignore  ←  *-private/
```

**「아니오」라고 하면 넣지 않는다.** 대신 이렇게 알려준다 —
*"그러면 커밋하실 때 `kara-os-private/` 가 안 들어갔는지 직접 확인하셔야 합니다."*

**이렇게 묻는다. 무엇을 어디에 넣을지 다 보여준다.**

```
이 폴더는 깃으로 관리되고 있습니다. (.git 위치: ~/myrepo)
그대로 두면 재료 폴더가 통째로 인터넷에 올라갈 수 있습니다.

이 파일에 한 줄을 더할까요?
  ~/myrepo/work/deeper/.gitignore   (없으면 새로 만듭니다)

더할 내용:
  *-private/
```

**파일이 이미 있으면 맨 끝에 한 줄만 더한다.** 원래 내용은 건드리지 않는다.
**같은 줄이 이미 있으면 아무것도 하지 않는다.**
넣은 뒤 `git check-ignore` 로 **정말 막혔는지 확인해서 보여준다.**

🔴 **확인했는데 안 막혀 있으면 그대로 말한다.** 넘어가지 않는다.
흔한 원인은 **이미 깃에 등록된 파일**이다 — 그때는 `.gitignore` 가 소용없다.
그 경우 사용자에게 알린다: *"이미 깃에 올라간 파일이라 `.gitignore` 로는 못 막습니다.
`git rm --cached` 로 등록을 먼저 푸셔야 합니다."*

4. 만든 뒤 **무엇을 적으면 되는지 한 번에** 알려준다. 빈 파일만 주고 끝내지 않는다

### 재료 파일에 뭘 적나 — 견본

**`destinations.md`** — 사람을 보낼 곳의 목록

```
| 이름 | 종류 | 주소 또는 자리 | 남기는 것 |
|---|---|---|---|
| 스터디 모집 | 🚪 자리형 | 슬랙 #모집 채널 댓글 | 댓글 한 줄 |
| 명절카드 신청 | 🔗 링크형 | https://… | 이름·연락처 |
```

**`material-stash.md`** — 겪은 일을 **한 줄씩**. 다듬지 않는다

```
- 2026-09-07 스터디를 열었더니 아홉 시간 만에 두 명이 왔다
```

**`utm-terms.md`** — 5단계에서 정한 말을 **여기 고정**한다 (아래 5단계 참고)

**재료 폴더가 없어도 그냥 진행한다.** 물어보며 쓰되,
끝난 뒤 *"이 내용을 재료 폴더로 남겨둘까요?"* 라고 **한 번만** 제안한다.

## 0단계 · 목적지를 먼저 정한다

🔴 **이 단계를 건너뛰면 이 스킬은 그냥 콘텐츠 스킬이 된다.**

**질문은 하나다.**

> ### **이 소재로 만드는 글들이 「결국」 사람을 어디로 데려가는가?**

⚠️ **글 한 편마다 정하는 게 아니다. 「묶음 전체」의 도착지를 정하는 것이다.**

```
묶음 목적지 (0단계에서 정함)
   ├─ 1편  믿게 만드는 글   링크 없음      ← 글마다 링크를 붙일지는 4단계에서 정한다
   ├─ 2편  믿게 만드는 글   링크 없음
   └─ 3편  보내는 글 링크 있음  ──▶ 도착
```

### 🔴 목적지는 두 종류다 — 이걸 먼저 가른다

**뒤의 4·5·7단계가 이 갈래에 따라 완전히 달라진다.**

| | 🔗 **링크형** — 주소가 있다 | 🚪 **자리형** — 주소가 없다 |
|---|---|---|
| 예 | 신청 폼 · 랜딩 페이지 · 오픈채팅 초대 링크 · 뉴스레터 구독 | **슬랙·커뮤니티 댓글** · DM 보내기 · 오프라인 모임 · 프로필 팔로우 |
| 남기는 것 | 이름·연락처 · 구독 | 댓글 한 줄 · 입장 · 참석 |
| 4단계 | 「보내는 글」에 **링크**를 붙인다 | 링크 대신 **「행동 한 줄」** |
| 5단계 | **UTM 꼬리표를 만든다** | ⏭️ **건너뛴다** |
| 7단계 | 클릭 수 → 신청 수 | **행동 수만** 센다 |

**정하고 나면 이렇게 적어둔다.**

```
목적지:   (주소 또는 자리)
종류:     링크형 / 자리형
남기는 것: (이름·연락처 / 댓글 / 입장)
이번 목표: (몇 명)
```

**목적지가 없으면 여기서 멈춘다.** 없는 채로 콘텐츠를 만들면 사람이 와도 받을 곳이 없다.
*"아직 없다"* 면 그것부터 만들자고 말한다.

## 1단계 · 소재를 잰다 — **결론이 몇 개 나오나**

**질문 하나면 된다.**

> ### **이 소재에서 「서로 다른 결론」이 몇 개 나오나?**

| 결론 수 | 그러면 |
|---|---|
| **1개** | **글은 한 편.** 채널만 나눈다 (① 방식) |
| **2개 이상** | 여러 편으로 갈 수 있다 |

> **억지로 늘리지 않는다.** 같은 결론을 다른 말로 바꾼 건 **결론 두 개가 아니다.**

## 2단계 · 펼치기 방식을 고른다

`references/spread.md`(없으면 아래 「펼치기 4방식」)의 **네 가지** 중에서 고른다.

| 방식 | 언제 | 추가 판정 |
|---|---|---|
| **① 채널 나누기** | 거의 항상. 같은 소재를 채널별로 다른 그릇에 담는다 | 없음 |
| **② 다르게 보기** | 같은 일에서 결론이 두 개 이상 나올 때 | 없음 |
| **③ 결과 알리기** | 1편에 숫자를 걸어두고 **며칠 뒤 결과를 알린다.** 진행 중인 숫자가 실제로 있을 때 | 없음 |
| **④ 자르기(연재)** | 한 이야기를 1부·2부로 끊을 때 | 🔴 **아래 판정 필수** |

**고른 이유를 한 줄로 말한다.** 사용자가 다른 걸 원하면 바꾼다.

### ④ 자르기를 골랐을 때만 — **자르기 판정 3문항**

🔴 **이 판정은 ④ 전용이다.** ①②③에는 적용하지 않는다.
①②③은 **글 하나만 읽어도 끝이 나므로** 아래 조건이 필요 없다.

| # | 질문 |
|---|---|
| 1 | **1부만 읽어도 남는 게 있나?** (반전 앞에서 끊기면 아니오) |
| 2 | **다음 부를 볼 사람이 있나?** (팔로워·저장) |
| 3 | **부마다 결론이 다른가?** |

- **셋 다 예** → 자른다
- **하나라도 아니오** → **자르지 말고 ①②③ 중에서 고른다**

## 3단계 · 채널을 배정한다

**같은 소재를 채널마다 다른 각도로 배정한다.** 복사해서 붙이지 않는다.

| 채널 | 무엇이 강한가 | 여는 법 |
|---|---|---|
| **스레드** | 있었던 일을 **시간 순서대로** | **장면·숫자**로 연다 |
| **인스타 캐러셀** | 정리 · 저장 | **결론**으로 연다. 정리 장 필수 |
| **블로그** | 검색 · 오래 남음 | **질문형 제목**으로 연다 |
| **오프라인 (전단·명함·배너)** | 손에 남음 | **한 문장 + QR** |

### 「내 표시」를 하나 정한다

여러 장·여러 편을 **같은 사람이 만든 것으로 보이게 하는 표시**를 하나 정한다.
캐릭터·로고가 **있으면 그것을**, **없으면 색 하나·도형 하나·반복 문장 중 하나를** 쓴다.
자세한 규칙은 `references/placement.md`, 없으면 아래 「참고 요약」.

**배정표를 만들어 보여준다.**

```
| 편 | 채널 | 각도 | 목적지로 보내는 법 |
|---|---|---|---|
| 1 | 스레드 | (…) | 링크 없음 · 프로필로 |
| 2 | 인스타 | (…) | 마지막 장 + 프로필 링크 |
```

## 4단계 · 글마다 「어디로 보낼지」를 정한다

`references/placement.md`(없으면 아래 「참고 요약」)를 읽는다.
**채널마다 링크를 붙일 수 있는 자리가 다르다.**

🔴 **가장 중요한 규칙**

> **감정선이 깊은 글에는 링크를 붙이지 않는다.**
> 링크가 붙으면 앞의 진심이 미끼처럼 보인다. 궁금한 사람은 프로필을 누른다.

**그래서 편을 두 종류로 나눈다.**

| 종류 | 링크 | 역할 |
|---|---|---|
| **믿게 만드는 글** | ❌ 없음 | 사람이 이 계정을 믿게 만든다 |
| **보내는 글** | ✅ 있음 | 실제로 목적지로 데려간다 |

**비율은 보내는 글 하나에 믿게 만드는 글 둘 이상.** 글마다 링크를 붙이면 계정이 광고판이 된다.

### 🚪 목적지가 「자리형」이면 — 링크 대신 **행동 한 줄**

주소가 없으니 붙일 링크도 없다. 대신 **무엇을 하면 되는지**를 한 줄로 적는다.

| 나쁜 예 | 좋은 예 |
|---|---|
| *"관심 있으면 연락 주세요"* | *"댓글에 「신청」 한 줄만 남겨주세요"* |
| *"참여 원하시는 분"* | *"이 글에 손 들어주시면 제가 먼저 말 걸게요"* |

**행동이 구체적일수록 움직인다.** 「연락」은 무엇을 하라는 건지 모른다.

🔴 **다른 플랫폼에 있는 자리로는 보낼 수 없다.**
슬랙 안의 모집을 인스타에서 부를 수는 없다. **그 채널에 있는 사람만 갈 수 있는 곳**이면,
다른 채널의 글은 **전부 믿게 만드는 글**으로 두고 링크·행동 안내를 넣지 않는다.

## 5단계 · UTM 꼬리표를 만든다

> ### 🚪 **목적지가 「자리형」이면 이 단계를 통째로 건너뛴다.**
> 붙일 링크가 없다. 대신 **7단계에서 무엇을 셀지**만 정하고 넘어간다.

`references/utm.md`(없으면 아래 「참고 요약」)를 읽는다.
**뿌리는 자리마다 다른 링크를 만든다.**

### 칸은 다섯인데 **세 개만 채우면 된다**

| 칸 | 무엇 | 필수 | 예 |
|---|---|:---:|---|
| `utm_source` | **어디에** 뿌렸나 | ✅ | `threads` · `instagram` · `kakao_openchat` · `flyer` |
| `utm_medium` | **어떤 형태로** | ✅ | `post` · `profile_link` · `story` · `dm` · `qr` |
| `utm_campaign` | **어떤 건으로** | ✅ | `0913_launch` |
| `utm_content` | 같은 곳에 **여러 개**일 때 | ⬜ | `post_a` · `post_b` |
| `utm_term` | 검색어 (광고용) | ⬜ | 거의 안 쓴다 |

**적는 규칙** — 소문자만 · 띄어쓰기 대신 밑줄 · 한글 금지 · **한 번 정한 말을 계속 쓴다** · 날짜는 앞에
🔴 **대문자와 소문자를 다른 것으로 센다.** `Threads` 와 `threads` 가 따로 잡혀 표가 둘로 갈린다.

> **정한 말은 재료 폴더의 `utm-terms.md` 에 표로 적어두고 계속 같은 말을 쓴다.**

### 🔴 반드시 짧게 줄인다 — 그리고 **그게 클릭을 세는 방법이다**

긴 주소를 오픈채팅방에 그대로 던지면 아무도 안 누른다.
그리고 **짧은 링크 서비스가 클릭 수를 세어준다.** 7단계가 여기에 달려 있다.

**고르는 기준 셋**

| 기준 | 왜 |
|---|---|
| **클릭 수를 세어주나** | 이게 없으면 줄이는 의미의 절반이 없다 |
| **무료로 몇 개까지** | 링크를 자리마다 만들면 금세 는다 |
| **주소가 안 죽나** | 서비스가 닫히면 뿌린 링크가 전부 죽는다 |

**널리 쓰이는 것:** Bitly · Short.io · TinyURL · 네이버·카카오의 단축 기능
⚠️ **무료로 쓸 수 있는 개수와 조건은 자주 바뀐다.** 쓰기 전에 지금 조건을 확인한다.

**만드는 순서**

```
① 목적지 주소를 적는다        https://내신청페이지.com
② 물음표를 붙인다             https://내신청페이지.com?
③ 칸을 & 로 이어 붙인다       utm_source=threads&utm_medium=post&utm_campaign=0913_launch
④ 단축 서비스에 넣어 줄인다
⑤ 표에 기록한다
```

> **주소에 이미 `?` 가 있으면** 두 번째부터는 `?` 가 아니라 `&` 로 잇는다.

**뿌린 것을 표로 남긴다.** 안 남기면 클릭이 잡혀도 그게 뭐였는지 모른다.

```
| 날짜 | 편 | 채널 | source | medium | 짧은 링크 | 클릭 | 신청 |
```

### QR을 만들어야 하면

**QR은 「짧은 링크」를 담는다.** 긴 UTM 주소를 그대로 넣으면 무늬가 촘촘해져 잘 안 찍힌다.

| 만드는 법 | 어떻게 |
|---|---|
| **에이전트가 만든다** | 파이썬 `qrcode` 라이브러리 (`pip install "qrcode[pil]"`) 로 PNG를 뽑는다 |
| 명령줄 | `qrencode` (맥은 `brew install qrencode`) |
| 온라인 생성기 | 검색해서 쓰되, **주소가 기록되는 곳**이라 민감한 링크는 피한다 |

🔴 **인쇄 전에 반드시 실제로 찍어본다.** 인쇄하고 나면 못 고친다.
크기·여백 규칙은 아래 「참고 요약」의 QR 절.

## 6단계 · 순서와 간격을 정한다

| 정할 것 | 기준 |
|---|---|
| **어느 글이 먼저인가** | **믿게 만드는 글이 먼저**, 보내는 글이 나중 |
| **간격** | 같은 채널이면 **최소 하루**. 붙여 올리면 뒤 글이 앞 글을 덮는다 |
| **채널 간** | 같은 날 다른 채널은 괜찮다 |

**표로 낸다.**

```
| 언제 | 채널 | 무엇 | 링크 |
```

## 7단계 · 발행 후 — 어디서 왔는지 센다

| 무엇 | 어디서 |
|---|---|
| 몇 명이 눌렀나 | 짧은 링크의 클릭 수 |
| 몇 명이 남겼나 | 목적지의 신청 수 |
| **어느 채널이 제일 잘 굴렀나** | 둘을 나눈 값 |

**표 하나로 답한다.**

```
| 채널 | 눌렀다 | 남겼다 | 남긴 비율 |
```

### 🚪 자리형이면 — **셀 수 있는 것만 센다**

클릭을 못 센다. **그래도 셀 수 있는 게 남는다.**

| 무엇 | 셀 수 있나 |
|---|---|
| 클릭 수 | ❌ 링크가 없다 |
| **행동 수** (댓글·입장·참석) | ✅ **이것만은 확실하다** |
| 글의 조회·저장 | ✅ 채널 통계에서 |

```
| 날짜 | 올린 글 | 조회 | 행동 수 |
```

**「글을 올린 날 행동이 늘었나」로 답한다.** 정확하진 않지만, 없는 것보다 낫다.

> **못 채웠을 때가 더 중요하다.** 어디서 끊겼는지 셋 중 하나로 답한다.
>
> | 그랬다면 | 문제는 |
> |---|---|
> | 아무도 안 눌렀다 | **채널·콘텐츠** |
> | 눌렀는데 금방 나갔다 | **첫 화면** |
> | 끝까지 갔는데 안 남겼다 | **폼·혜택** |

## 원칙 다섯 가지

### 1. 목적지가 없으면 만들지 않는다

받을 곳 없이 사람을 부르면, 온 사람이 갈 데가 없다.

### 2. 링크는 아껴서 붙인다

**보내는 글 하나에 믿게 만드는 글 둘.** 매번 붙이면 사람들이 계정을 광고로 분류한다.

### 3. 뿌리는 자리마다 링크를 다르게 한다

같은 링크를 세 군데 던지면 **세 군데를 구분할 수 없다.** 그게 꼬리표를 붙이는 유일한 이유다.

### 4. 억지로 늘리지 않는다

**결론이 하나면 글도 한 편이다.** 같은 결론을 다른 말로 바꾼 건 두 편이 아니다.
자를 때는 **자르기 판정 3문항**을 반드시 통과해야 한다.

### 5. 없는 숫자를 만들지 않는다

*"3자리 남았습니다"* 는 **실제로 3자리가 남았을 때만** 쓴다. 카운터는 셀 수 있게 된 다음부터 쓴다.

# 참고 요약 — **참고 파일이 없어도 여기까지로 돈다**

이 스킬 폴더에 `references/` 가 있으면 **그쪽을 읽는다.** 훨씬 자세하다.
없으면 **아래 요약만으로 진행한다.** 건너뛰거나 멈추지 않는다.

> 완전판(참고 파일 3개 포함): `https://github.com/Kara75-PM/kara-os`

## 펼치기 4방식

| 방식 | 무엇 | 위험 | 효과 |
|---|---|---|---|
| **① 채널 나누기** | 같은 이야기를 **채널마다 다른 그릇**에 담는다 (스레드=이야기 · 인스타=정리 · 블로그=검색 · 종이=한 문장) | 낮음 | 노출이 채널 수만큼 |
| **② 다르게 보기** | **같은 일인데 결론이 다른 것.** 두 결론이 서로 다른 말을 해야 성립 | 낮음 | 저장·인용 |
| **③ 결과 알리기** ⭐ | 1편에 **진행 중인 숫자**를 걸고, 며칠 뒤 **결과**를 올린다 | 낮음 | **사람들이 결과 보러 다시 온다** |
| **④ 자르기(연재)** | 한 이야기를 1부·2부로 | 🔴 **높음** | 팔로워 있을 때만 |

**③이 가장 안전하면서 강하다.** 이야기를 자르는 게 아니라, **1편은 그것만으로 끝이 난 채** 다음 편이 생긴다.
🔴 **못 채운 결과가 더 세다.** *"안 찼다. 이유는 이거다"* 가 *"다 찼다"* 보다 읽힌다.

**🔴 하면 안 되는 것** — 반전 앞에서 자르기 · 결론이 같은 2편 · **없는 카운터 만들기** ·
얇은 소재 억지로 늘리기 · 매 편마다 링크 붙이기 · 같은 날 같은 채널에 두 편

**방식 고르는 표**

| 지금 상태 | 권하는 방식 |
|---|---|
| 팔로워가 거의 없다 | **① 채널 나누기 + ③ 결과 알리기** |
| 소재에 진행 중인 숫자가 있다 | **③ 결과 알리기** |
| 이야깃거리가 두껍고 결론이 여러 개 | **② 다르게 보기** |
| 팔로워가 있고 이야기가 길다 | ④ 자르기 (판정 3문항 필수) |

## 채널별 링크 놓을 자리

| 채널 | 어디에 | `medium` |
|---|---|---|
| **스레드** | **마지막 칸**에만 · 프로필 링크 | `post` · `profile_link` |
| **인스타** | 🔴 **캡션 주소는 안 눌린다.** 프로필 링크만 · 스토리 스티커(24시간) | `profile_link` · `story` |
| 블로그 | 본문 중간 · 글 끝. **맨 위는 안 된다**(읽기 전에 파는 것처럼 보인다) | `post` |
| 오픈채팅방 | 메시지 안 | `dm` |
| 메일 | 본문 · 서명 | `body` · `signature` |
| **전단·명함·배너** | **QR** | `qr` |

> **인스타 프로필 링크 자리는 좁다.** 지금 밀고 있는 목적지 **하나만** 거는 게 낫다.
> 여러 개를 걸면 사람들이 뭘 눌러야 할지 몰라서 아무것도 안 누른다.

## 「내 표시」 — 같은 사람 것으로 보이게 하는 것

**한 장 한 장 예쁜 것보다, 여러 장이 같은 계정 것으로 보이는 게 훨씬 중요하다.**

| | |
|---|---|
| 🟢 **캐릭터·로고가 있으면** | **표지 1장 + 마지막 1장, 두 곳만.** 정리 장에는 **넣지 않는다**(캡처해 가는 장이라 정보만) |
| 크기 | 표지 그림 높이의 **40~45%** · 마지막 **30~35%** |
| 시선 | 오른쪽에 두면 **왼쪽(글자 쪽)을 보게** · **마지막 장은 정면** |
| ⚠️ | **투명 배경 그림은 여백이 들어 있다.** 여백을 먼저 잘라내고 크기를 잡는다 |
| ⚪ **없으면** | **색 하나 고정 / 도형 하나 / 반복 문장 / 손글씨 서명** 중 **딱 하나**만 |

## QR — 크기와 배치

**크기 = 보는 거리 ÷ 10**

| 보는 거리 | 최소 한 변 |
|---|---|
| 손에 들고 (30cm) | **3cm** |
| 책상 위 전단 (50cm) | **5cm** |
| 벽 배너 (2m) | **20cm** |
| 명함 (15~20cm) | **1.5~2cm** |

> 작게 넣으면 안 찍힌다. **작게 넣을 바에는 빼는 게 낫다.**

**🔴 QR만 있으면 아무도 안 찍는다. 세 줄이 붙어야 한다.**

```
① 무엇이 나오나    "3분이면 카드 한 장"
② 왜 지금인가      "9월 13일까지"
③ 찍는 법 (선택)   "카메라로 비추세요"
```

**배치 규칙** — 둘레에 **흰 여백**(QR 한 칸 크기 이상) · **어두운 배경 위 흰 QR 금지** ·
접히는 자리·모서리 피하기 · **한 장에 QR 하나** · 🔴 **인쇄 전에 실제로 찍어본다**

**오프라인 카피** — 전단·배너는 지나가면서 본다. **한 문장이면 충분하고, 두 문장이면 안 읽는다.**

|---|---|

| 대소문자 섞어 씀 | 같은 채널이 표에서 **둘로 갈린다** |

| **뿌린 기록을 안 남김** | 클릭이 잡혀도 **그게 뭐였는지 모른다** |
| 링크를 안 줄임 | 아무도 안 누른다 |
