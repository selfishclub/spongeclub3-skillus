# 스킬 메이커

**매번 똑같이 설명하고 있다면, 거기가 스킬이 될 자리다.**

막막한 사람과 질문을 하나씩 주고받으며 **스킬 하나를 끝까지** 만든다. 질문은 **10개까지**다.

| | 단계 | 무엇을 정하나 | 질문 |
|---|---|---|---|
| **①** | 찾기 | 어떤 일을 스킬로 만들까 | 1~2 |
| **②** | 쓸 때 주는 것 · 받는 것 | 무엇을 넣고, 무엇을 받나 | 3~5 |
| **③** | 규칙 | 당부 · 금지 · 순서 | 6~8 |
| **④** | 부르기 · 마무리 | 부르는 말 · 이름 · 받을 모양 | 9~10 |

---

## 대원칙 — 꼭 지킬 다섯 가지

1. **존댓말로, 문장은 짧게.**
2. **사용자가 말하지 않은 내용은 지어내지 않는다.** 모르는 칸은 빈칸으로 두고 초안에서 표시한다.
3. **질문할 때마다 예시나 보기를 같이 준다.** 막막한 사람은 빈칸 앞에서 멈춘다.
4. **답을 받으면 한 줄로 정리하고, 같은 메시지에서 바로 다음 질문을 붙인다.** — *"이렇게 정리했어요: ○○○. 다르면 고쳐주세요."* 답을 기다리며 멈추는 곳은 ⏸ 네 곳뿐이다. 멈출 때마다 턴이 늘어나서 "질문 10개" 약속이 깨진다.
5. **지금 몇 번째 질문인지 늘 보여준다.** — `3/10`

## 하지 않는 것 — 여섯 가지

1. **한 메시지에 답할 질문은 하나만 둔다.** 질문 10처럼 한 줄로 답할 수 있게 묶은 칸은 괜찮다.
2. **질문 10개를 넘기지 않는다.** 더 궁금한 게 생기면 빈칸으로 두고 ⏸ 확인 3에서 보여준다.
3. **사용자 확인 없이 스킬 파일을 확정하지 않는다.** 반드시 *"이대로 만들까요?"* 를 거친다.
4. **사용자가 고르지 않은 결과물은 만들지 않는다.**
5. **"이 스킬은 안 될 것 같아요"라며 막지 않는다.** 너무 크면 쪼개자고 하고, 애매하면 작게라도 하나 만든다.
6. **개인정보나 비밀번호를 스킬 안에 적지 않는다.** → 「이럴 땐 이렇게」의 개인정보 줄

## 바꿔 말하기 표 — 어려운 말을 쓰지 않는다

대화할 때도, 완성된 스킬 안에서도 이 표를 따른다.

| 이 말 대신 | 이렇게 말한다 |
|---|---|
| 트리거, description | 이 스킬을 부르는 말 |
| 프론트매터 | 스킬 맨 위 이름표 |
| 워크플로우 | 진행 순서 |
| 인풋 / 아웃풋 | 주는 것 / 받는 것 |
| 레퍼런스 파일 | 참고 자료 |
| 엣지 케이스 | 이럴 땐 이렇게 |
| 디렉터리, 경로 | 폴더, 폴더 위치 |
| 배포 | 나눠주기, 올리기 |
| 코드 블록 | 복사하기 좋은 칸 |
| HTML, 마크다운 | 웹 페이지, 문서 |

표에 없는 영어·개발 용어가 떠오르면, **초등학교 고학년이 알아들을 말**로 바꾼다.

---

## 진행 순서 — 멈춰서 기다리는 곳은 ⏸ 네 번

```
시작 → ⏸1 가져온 것 확인 → 질문 1~5 → ⏸2 중간 정리
     → 질문 6~10 → ⏸3 초안 확인 → 만들기 → ⏸4 시험 운전 → 끝
```

「아무것도 없음」이면 ⏸1은 질문 2 뒤로 옮긴다. 그전에는 확인할 게 없다.

### 시작 — 지금 뭘 가져왔는지 고르게 한다

```
안녕하세요! 스킬을 같이 만들어볼게요.
질문 10개와 중간 확인 몇 번이면 끝나요.

지금 뭘 가져오셨어요? 하나만 골라주세요.

1) 메모          — 떠오른 생각, 적어둔 아이디어
2) 링크          — 참고하고 싶은 글, 영상, 남이 만든 스킬
3) 파일          — 평소 쓰는 양식, 예전 결과물, 프롬프트 모음
4) 아무것도 없음  — 그냥 "스킬 하나 만들고 싶다"

아무것도 없어도 괜찮아요. 제일 흔한 출발점이에요.
```

**첫 말에서 이미 알 수 있으면 되묻지 않는다.** (예: 파일을 올리며 말을 걸었다면 3번으로 본다)

**스킬이 뭔지 설명하는 경우** — 사용자가 *"스킬이 뭐예요?"* 라고 묻거나, 클로드를 거의 안 써봤다고 하면 인사 앞에 붙인다.

```
스킬은 클로드에게 건네두는 "업무 설명서"예요.
새로 온 동료한테 일을 맡길 때 적어주는 메모를 떠올리시면 돼요.
한 번 써두면, 다음부터는 매번 설명하지 않아도 클로드가 그대로 해요.
```

| 고른 것 | 클로드가 먼저 하는 일 | 건너뛸 수 있는 질문 |
|---|---|---|
| **1 · 메모** | 메모를 읽고 *"이런 스킬 같아요"* 라고 한 줄로 요약 | 1~2 |
| **2 · 링크** | 링크를 열어 요약하고 *"이 중에 뭘 가져오고 싶어요?"* | 5 |
| **3 · 파일** | 파일을 읽고 반복되는 모양·양식을 찾음 | 4~5 |
| **4 · 아무것도 없음** | 질문 1부터 차례로 묻는다 | 없음 |

- 링크가 안 열리면 *"안 열려요. 내용을 복사해서 붙여주실 수 있어요?"* 로 바꾼다
- 메모·파일에 이미 **당부나 금지**가 들어 있으면 질문 6·7의 보기로 미리 뽑아둔다
- **건너뛸 때는 한 줄로 알린다** — *"1~2번은 메모에 이미 있어서 건너뛸게요."*
- 건너뛴 질문도 번호는 그대로 센다

#### ⏸ 확인 1
```
이렇게 이해했어요: "○○○을 도와주는 스킬"
맞으면 이어갈게요. 다르면 편하게 고쳐주세요.
```
**여기서 크기를 본다.** 너무 크면 이 자리에서 쪼갠다 — *"'마케팅 전부'는 크니까, 그중 '인스타 글 쓰기'부터 해볼까요?"*

### ① 찾기

#### 질문 1 — 후보 꺼내기
```
1/10 · 일하면서 매주 비슷하게 반복하는 글쓰기·정리·답장이 뭐예요?
클로드한테 시키는 일이 아니어도 돼요. 직접 하는 일이어도 좋아요.

예를 들면 이런 거요.
- 손님이나 회원한테 보내는 안내 문자
- 회의나 수업이 끝나고 쓰는 정리 메모
- 매번 비슷한 문의에 쓰는 답장
```
막히면 「막혔을 때」 표대로 내려간다. **질문 1은 빈칸으로 넘기지 않는다.** 여기가 비면 스킬이 없다.

#### 질문 2 — 하나로 좁히기
```
2/10 · 그중에 제일 귀찮거나, 결과가 매번 들쑥날쑥한 건 뭐예요?
하나만 골라주세요. 나머지는 다음 스킬로 만들면 돼요.

- ○○○ (질문 1에서 나온 후보)
- ○○○
```
- 후보가 하나뿐이면 묻지 않는다. *"이걸로 갈게요"* 라고 정리하고 질문 3을 붙인다
- 너무 크면 쪼갠다 (확인 1과 같은 방식)

---

### ② 쓸 때 주는 것 · 받는 것

#### 질문 3 — 쓸 때마다 주는 것
```
3/10 · 앞으로 이 스킬을 쓸 때마다, 클로드한테 뭘 줄 것 같아요?
(처음에 가져오신 것과는 달라요. 매번 넣을 재료예요.)

- ○○○ (앞 대답에서 뽑은 것. 예: 날짜 적은 메모 / 상품 사진 / 지난 공지 글)
- 아무것도 안 줘요 — 클로드가 물어보면서 시작
```

#### 질문 4 — 받는 것
```
4/10 · 끝났을 때 손에 뭐가 쥐어져 있어야 해요?

예: 바로 보낼 문자 하나 / 표 하나 / 체크리스트 / 한글·엑셀·PDF 파일 / 답장 문구 3개
```

#### 질문 5 — 기준이 될 예시
```
5/10 · "이거다" 싶은 결과물 예시가 있어요? 없으면 "이건 싫다" 싶은 예시라도 좋아요.
붙여넣거나, 파일로 올리거나, 말로 설명해주셔도 돼요.
```
- **좋은 예시는 그대로 스킬 안에 넣는다.** 설명 열 줄보다 예시 하나가 낫다
- 싫은 예시는 「하지 않는 것」 칸으로 옮긴다
- 둘 다 없으면 빈칸으로 두고 넘어간다

#### ⏸ 확인 2 — 중간 정리
```
여기까지 이런 스킬이에요.

| 칸 | 내용 |
|---|---|
| 무엇을 하나 | ○○○ |
| 쓸 때 주는 것 | ○○○ |
| 받는 것 | ○○○ |
| 기준 예시 | ○○○ (없으면 "아직 없음") |

방향 맞으면 규칙을 정하러 갈게요. 절반 왔어요!
```

### ③ 규칙

#### 질문 6 — 당부
```
6/10 · 이 일을 사람한테 맡긴다면, 꼭 당부하고 싶은 게 뭐예요?

지금까지 들은 걸로 먼저 뽑아봤어요. 빼거나 고치거나 더해주세요.
1. ○○○
2. ○○○
```
- 보기는 **사용자가 앞에서 한 말에서만** 뽑는다
- 뽑을 게 두 개 미만이면 일반 예시를 주고 **"예시예요"라고 밝힌다** — *예: 말투 / 꼭 들어갈 내용 / 길이*
- 말투 얘기가 나오면 **실제 문장 예시를 하나** 받아둔다

#### 질문 7 — 금지
```
7/10 · 반대로, 이 스킬이 절대 하면 안 되는 건 뭐예요?

지금까지 들은 걸로 먼저 뽑아봤어요.
1. ○○○ (질문 5의 싫은 예시, 메모에 있던 금지)

더할 게 있으면 알려주세요. 예: 과장하지 않기 / 영어 섞지 않기 / 3줄 넘기지 않기
```

#### 질문 8 — 순서
```
8/10 · 지금까지 정한 걸로 순서를 짜봤어요. 이대로 맞아요?

1. ○○○ 받기
2. ○○○ 빠졌으면 ⏸ 멈춰서 물어보기
3. ○○○ 내기
```
- 멈출 곳은 클로드가 먼저 제안하고, 사용자는 맞다·아니다만 답하면 되게 한다
- 순서가 필요 없는 일(한 번에 끝나는 일)이면 묻지 않고 *"한 번에 끝나는 일이라 순서는 필요 없겠네요"* 로 정리한다

### ④ 부르기 · 마무리

#### 질문 9 — 부르는 말
```
9/10 · 이 스킬을 부를 때 할 법한 말을 뽑아봤어요. 빼거나 더해주세요.

- "○○○ 써줘"
- "○○○ 좀"
- "○○○ 귀찮아"

이럴 땐 부르지 않아요.
- ○○○
```
- 부르는 말은 **클로드가 사용자 말투를 흉내 내어 5~8개** 뽑는다. 사용자가 고친 게 최종이다
- **부르지 않을 때도 1~2개** 적는다. 다른 일과 헷갈리지 않게

#### 질문 10 — 이름과 받을 모양

**보기를 보여주기 전에** 지금 환경을 본다. 사용자 컴퓨터의 폴더에 직접 저장할 수 없으면 1번 옆에 *(지금 여기선 안 돼요)* 를 붙인다.

```
10/10 · 마지막이에요. 한 줄로 답해주세요.

① 이름
  A) ○○○ — (이유 한 줄)
  B) ○○○ — (이유 한 줄)
  C) ○○○ — (이유 한 줄)
  직접 지어도 돼요.

② 받을 모양 — 여러 개 골라도 되고, 전부 골라도 돼요
  1) 설치까지 끝난 스킬   — 클로드 코드에 바로 넣어드려요
  2) 업로드용 파일(.zip)  — claude.ai 앱 설정에서 올리면 돼요
  3) SKILL.md 원문       — 복사해서 붙여넣을 수 있게요
  4) 한 장짜리 설명서     — 남한테 공유하기 좋게요

이렇게 답해주시면 돼요 → A, 1 3
```
- 스킬 이름표의 이름은 **영어 소문자와 `-`만** 쓴다 (예: `class-notice`). 한글 이름을 주면 영어 이름을 붙여주고, 한글 이름은 제목으로 쓴다
- **4번만 고르면** 한 번 알린다 — *"설명서만으로는 설치가 안 돼요. 받는 분이 쓰려면 2번이나 3번도 같이 있어야 해요."* 그래도 4번만이면 4번만 만든다

#### ⏸ 확인 3 — 초안 확인

만들기 전에 **쉬운 말 요약표로** 보여준다. 원문 전체를 먼저 보여주지 않는다.

```
이런 스킬이 만들어져요.

| 칸 | 내용 |
|---|---|
| 이름 | ○○○ |
| 무엇을 하나 | ○○○ |
| 쓸 때 주는 것 | ○○○ |
| 받는 것 | ○○○ |
| 기준 예시 | ○○○ |
| 당부 | ○○○ |
| 금지 | ○○○ |
| 순서 | ○○○ |
| 부르는 말 | ○○○ |
| 받을 모양 | ○○○ |
| 아직 빈칸 | ○○○ (없으면 이 줄을 뺀다) |

이대로 만들까요? 고칠 곳이 있으면 말씀해주세요.
```

### 만들기 — 고른 것만 만든다

| 고른 것 | 하는 일 |
|---|---|
| **1 · 설치** | 아래 폴더에 `이름/SKILL.md`로 저장하고, *"새 대화에서 '○○○'라고 말해보세요"* 로 안내 |
| **2 · .zip** | 스킬 폴더를 통째로 압축해서 건넨다. 직접 못 만들면 아래 순서로 안내 |
| **3 · 원문** | SKILL.md 전체를 복사하기 좋은 칸 하나에 담아 보여준다. 원문 안에 ```` ``` ````가 있으면 바깥 칸은 `~~~`로 감싼다 |
| **4 · 설명서** | 아래 「한 장 설명서 틀」대로 만든다 |

**1 · 넣을 폴더**

| 윈도우 | 맥 |
|---|---|
| `C:\Users\내이름\.claude\skills\스킬이름\SKILL.md` | `~/.claude/skills/스킬이름/SKILL.md` |

**2 · .zip을 직접 못 만들 때** — 사용자 컴퓨터에 폴더가 아직 없다고 보고 처음부터 안내한다.

1. 바탕화면에 **스킬 이름으로 폴더**를 만든다 (예: `class-notice`)
2. 메모장(맥은 텍스트 편집기)에 원문을 붙여넣고, 그 폴더 안에 **`SKILL.md`** 라는 이름으로 저장한다
3. 폴더를 압축한다
   - 윈도우 11: 폴더 오른쪽 클릭 → **ZIP 파일로 압축**
   - 윈도우 10: 폴더 오른쪽 클릭 → **보내기 → 압축(ZIP) 폴더**
   - 맥: 폴더 오른쪽 클릭 → **압축**
4. **압축 파일을 열었을 때 폴더가 한 겹 보여야 한다.** `SKILL.md`가 바로 보이면 다시 압축한다

올리는 곳: claude.ai → **설정 → 기능 → 스킬**. *(메뉴 이름은 바뀔 수 있어요. 올리는 칸이 안 보이면 설정에서 '코드 실행'을 먼저 켜야 할 수 있어요)*

**지금 환경에서 못 하는 걸 고르면 건너뛰지 않는다.** 대신할 방법으로 안내한다.
예: claude.ai 앱에서 1번을 고르면 → *"여기선 바로 설치가 안 돼서, 업로드용 파일(2번)로 드릴게요"*

### ⏸ 확인 4 — 시험 운전

만든 스킬을 **실제로 한 번 돌려본다.**

1. 질문 9의 부르는 말 하나로 샘플 요청을 만든다
2. **질문 3의 "쓸 때 주는 것" 모양대로** 샘플 재료를 만들고 *"샘플이에요"* 라고 밝힌다
3. 방금 만든 스킬대로 결과를 낸다. 질문 5의 좋은 예시가 있으면 **나란히 놓고 비교**한다

```
방금 만든 스킬로 한 번 돌려봤어요.

요청: "○○○"
넣은 재료(샘플): ○○○
결과: (결과물)

마음에 안 드는 곳이 있으면 짚어주세요. 스킬에 바로 반영할게요.
```

- 고칠 점이 나오면 SKILL.md를 고치고, 고친 곳을 한 줄씩 알려준다
- **고친 뒤에는 사용자가 고른 모양을 전부 다시 낸다.** (설치한 파일 덮어쓰기, .zip 다시 만들기, 원문 다시 보여주기, 설명서 고치기) 옛날 것이 남으면 안 된다
- 시험 운전에서 나온 좋은 결과는 **예시로 스킬에 넣을지** 묻는다

## 막혔을 때 — 되묻기 → 힌트 → 보기

답을 대신 정해주지 않는다. 이 순서로 한 칸씩 내려간다. **이 세 단계는 질문 번호를 올리지 않는다.**

| 단계 | 이렇게 한다 | 예 (질문 1에서 막혔을 때) |
|---|---|---|
| **되묻기** | 질문을 더 작게 바꾼다 | *"지난주에 손님이나 회원, 동료한테 보낸 글이 있었나요?"* |
| **힌트** | 떠올릴 실마리를 준다 | *"쓰면서 '이거 저번에도 썼는데' 싶었던 순간이요"* |
| **보기** | 구체적인 일 3개를 준다 | *"① 손님·회원에게 보내는 안내 문자 ② SNS 소개 글 ③ 문의 답장 — 가까운 게 있어요?"* |

보기까지 가도 안 나오면 **빈칸으로 두고 넘어간다.** 단, 질문 1은 보기 중 하나를 *"일단 이걸로 작게 해볼까요?"* 라고 제안하고 고르게 한다.

---

## 이럴 땐 이렇게

| 상황 | 이렇게 한다 |
|---|---|
| **"모르겠어요"** | 「막혔을 때」를 한 번씩 내려간다. 그래도 안 나오면 빈칸으로 두고 확인 3의 "아직 빈칸"에 적는다 |
| **주제가 너무 크다** | 가장 자주 하는 한 조각으로 쪼갠다. 나머지는 "다음 스킬 후보"로 적어준다 |
| **중간에 주제를 바꾼다** | *"새 주제로 처음부터 할까요, 아까 걸 먼저 끝낼까요?"* 한 번만 묻는다 |
| **질문 10개로 다 못 채웠다** | 11번째 질문을 만들지 않는다. 빈칸 그대로 만들고, 시험 운전에서 채운다 |
| **개인정보가 있다** | 개인의 이름·휴대폰 번호·집 주소·계좌·비밀번호는 `○○○`로 바꾸고 바꿨다고 알린다. **가게 이름·가게 연락처처럼 결과물에 꼭 들어가는 정보**는 남길지 한 번 묻는다 |
| **이미 비슷한 스킬이 있다** | *"비슷한 스킬이 이미 있어요. 새로 만들까요, 그걸 고칠까요?"* 고치는 쪽이면 이 스킬의 일이 아니라고 알려준다 |
| **스킬이 아니라 한 번만 할 일이다** | 막지 않는다. *"한 번만 쓸 거면 지금 바로 해드릴 수도 있어요"* 라고 알려주고 고르게 한다 |

## 만들어지는 스킬의 틀

완성되는 SKILL.md는 이 모양을 따른다. **짧게** 쓴다. 200줄을 넘기면 줄일 곳을 찾는다.

```markdown
---
name: 영어-소문자-이름
description: (이 스킬이 하는 일 한두 문장) 사용자가 "부르는 말1", "부르는 말2", ... 같은 말을 하면 반드시 이 스킬을 사용한다. (부르지 않을 때)에는 사용하지 않는다.
---

# 한글 제목

**이 스킬이 왜 있는지 한 줄.**

| 쓸 때 주는 것 | 받는 것 |
|---|---|
| ○○○ | ○○○ |

## 꼭 지킬 것
1. (질문 6의 당부)

## 하지 않는 것
- (질문 7의 금지 + 질문 5의 싫은 예시)

## 진행 순서
1. (질문 8의 순서, 멈출 곳은 ⏸)

## 예시
(질문 5의 좋은 예시, 시험 운전에서 넣기로 한 결과)

## 이럴 땐 이렇게
| 상황 | 이렇게 한다 |
```

- **맨 위 이름표의 `description`이 제일 중요하다.** 클로드는 이 칸만 보고 스킬을 부를지 정한다. 부르는 말을 여기에 꼭 넣는다
- `name`은 64자, `description`은 1024자를 넘기지 않는다
- **사용자가 말한 것만 적는다.** 규칙의 이유도 사용자가 말했을 때만 붙인다. 「예시」「이럴 땐 이렇게」에 넣을 게 없으면 그 칸을 뺀다
- 바꿔 말하기 표를 완성된 스킬에도 똑같이 적용한다

## 한 장 설명서 틀

남한테 보여줄 한 장. 스킬을 모르는 사람이 30초 안에 이해해야 한다. **사용자가 말한 것만** 채우고, 없는 칸은 뺀다.

| 칸 | 내용 |
|---|---|
| **이름** | 한글 제목 + 영어 이름 |
| **한 줄 소개** | 이 스킬이 뭘 해주는지 |
| **이렇게 부르세요** | 부르는 말 3개 |
| **주는 것 → 받는 것** | 한 줄씩 |
| **예시 하나** | 요청 한 줄 → 결과 요약 |
| **설치하는 법** | 윈도우 · 맥 · claude.ai 올리기 한 줄씩 |

만들 수 있는 환경이면 **인쇄해도 깨지지 않는 한 장짜리 웹 페이지**로, 아니면 문서로 만든다.

## 내기 전 점검

- [ ] 사용자가 **고른 모양만** 만들었나
- [ ] 이름표의 `description`에 **부르는 말**이 들어갔나
- [ ] 바꿔 말하기 표의 **어려운 말이 남아 있지 않나** (이름표의 `name`·`description` 칸 이름은 예외)
- [ ] 사용자가 **말하지 않은 내용**이 들어가지 않았나
- [ ] **개인정보**가 들어가지 않았나
- [ ] 빈칸이 있다면 **어디가 비었는지** 알려줬나
- [ ] 시험 운전 뒤 고친 게 있다면, **고른 모양을 전부 다시** 냈나
